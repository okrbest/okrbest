## 1. 와이어프레임 분석 — 화면정의서가 그리는 대시보드

Figma MCP 접근은 여전히 막혀 있으나(편집 권한 필요), 캡처 5장으로 화면 구조를 확정했다.

### 전체 구조 — 3단 대시보드 + 제품 영역 승격

대시보드는 단일 화면이 아니라 **제품 영역**이다. 좌측 보조 사이드바가
"대시보드 · 채팅 · 보드" 3개 탭으로 재편되고, 대시보드 탭 아래에 유형 3종이 있다.

| 유형 | 부제 | 성격 |
|---|---|---|
| 내 대시보드 | My Daily Focus | 개인의 오늘 — 할 일, 멘션, 생산성 |
| 팀 대시보드 | Team Performance | 팀의 분기 — OKR, 보드, 플레이북, 팀원 현황 |
| 조직 대시보드 | Company-wide Insight | 전사 — 합성 지표, 팀별 비교, 격려 문화 |

공통 요소: 상단 브레드크럼(대시보드 > 유형), 우상단 Todo·Agents·프로필 버튼,
상세 필터, 하단 "AI 인사이트" 요약 줄(업무 현황·성과 지표·업무 알림 3련 + 전체보기).

### 내 대시보드 위젯 (캡처 1)

| ③ | 나의 업무 생산성 | 오늘 목표 달성률 게이지, 평균 응답 속도(상위 % 표기), 최근 업데이트 시각 |

## 3. 위젯별 실현성 판정

세 군으로 나눈다. **A = 현재 상태에서 바로 표출 가능**, **B = 집계·규약을 보강하면 가능**,
**C = 새 데이터 모델이나 시스템이 필요**.

### 내 대시보드

| 위젯 | 판정 | 근거와 경로 |
|---|---|---|
| ② 새로운 멘션 수 | **A** | `mention_count` 합산 — 기존 셀렉터 재사용 |
| ⑥ 멘션 및 요청 목록 (채널 출처) | **A** | 멘션 검색 API. 출처 배지 "채널" + 채널명 표기 |
| ④ Todo 3타일 (전체/오늘 마감/지연) | **B** | Todo 원천 결정 필요 (4절 결정 1). 보드 카드 경로면 date 속성으로 즉시, Todo 플러그인 경로면 마감 필드 확장 |
| ⑤ 지금 바로 조치하세요 | **B** | ④와 동일 원천 + 우선순위 속성 |
| ② 해결한 업무·지연된 업무 | **B** | ④와 동일 원천의 완료·지연 집계 |
| ③ 오늘 목표 달성률 | **B** | OKR 속성 규약 (4절 결정 2) |
| ③ 평균 응답 속도 | **B** | 멘션 수신→내 답장 시간차 집계 쿼리 신설 |
| ⑥ 멘션 및 요청 (보드 출처) | **B** | 보드 멘션 알림의 출처 식별 — 보드 알림 DM 파싱 또는 보드 API 교차 |
| ② 배지 획득 | **C** | 배지 시스템 자체가 없다 (4절 결정 3) |
| ⑦ AI 인사이트 요약 문장 | **B/C** | 규칙형 템플릿이면 B (집계값을 문장 틀에 대입), LLM 생성이면 C |

## 4. 핵심 결정 사항 — brainstorming에서 확정할 것

구현 순서를 가르는 결정이 다섯 개 있다. 전부 1단계 brainstorming의 안건이다.

1. **Todo의 데이터 원천.** 와이어프레임의 Todo는 마감일·우선순위·담당자·지연을 가진다.
   - (a) **보드 카드를 Todo로 쓴다** — date·select·person 속성으로 전부 표현 가능. 규약만 세우면 집계가 바로 된다. 보드와 할 일이 한 곳에 모이는 장점.
   - (b) **Todo 플러그인을 확장한다** — 현재 플러그인에는 마감·우선순위가 없어 포크 확장이 필요하다. 상단 Todo 버튼과의 일관성은 좋다.
   - 권고: (a). 플러그인 바이너리 포크는 유지 비용이 크고, OKR 규약(결정 2)과 한 체계로 묶인다.
2. **OKR 보드 속성 규약.** 목표(Objective) 카드와 KR의 관계(하위 카드 vs 체크박스 속성), 진척 number(0~100), 분기 라벨, 상태 5단(백로그·연구/분석·진행중·검토/QA·완료) 명칭을 표준 템플릿으로 정한다. 증감 표시용 **주간 스냅샷 테이블** 신설 여부도 함께.
3. **배지·칭찬 시스템의 범위.** 와이어프레임에 배지 획득(개인), 팀원별 배지, 칭찬 피드, 우수 팀이 반복 등장한다 — 단순 위젯이 아니라 **게이미피케이션 기능 신설**이다. 별도 기능 spec으로 분리할지, 대시보드 1차에서 뺄지 결정한다.
4. **합성 지표의 산식.** "조직 활동 상태 75.5%", "규정 준수율", "종합 업무 퍼포먼스", "평균 응답 속도 상위 5%"는 산식이 정의돼야 구현할 수 있다. 정의 없이 구현하면 숫자가 신뢰를 잃는다.
5. **AI 인사이트의 1차 범위.** 하단 요약 줄은 규칙형 템플릿(집계값 + 문장 틀)으로 LLM 없이 시작할 수 있다. 조직 대시보드의 질의 챗은 별도 기획(데이터 거버넌스 포함)으로 분리를 권고한다.

## 5. 아키텍처

### 표출 위치 — 레일 제품 영역

와이어프레임의 "대시보드·채팅·보드" 3탭 구조에 맞춰, 대시보드를 **레일의 제품
아이콘**(017 레일 문법, 028 액센트 준수)으로 추가하고 `/{team}/dashboard/{type}`
라우트를 신설한다. 보조 사이드바에 유형 3종(내·팀·조직) 선택 목록을 둔다 —
015·021 정적 뷰 패턴의 확장이다.

### 데이터 경로 — 2단계

1. **1단계 (A군)**: 웹앱이 기존 API를 직접 조합한다. Boards v2·Playbooks·Todo
   플러그인 API는 웹앱에서 플러그인 경로로 직접 호출한다 (쿠키 인증 공유).
2. **2단계 (B군)**: `GET /api/v4/okrbest/dashboard/...` 집계 엔드포인트를 서버에
   신설한다 — 활동 시계열, 응답 속도, 팀별 조인 표, OKR 스냅샷. 포크 전용
   네임스페이스에 두고 `docs/upstream-adapted-divergences.md`에 기록한다.
   플러그인 바이너리(focalboard·playbooks·todo)는 수정하지 않는다.

### 디자인 — 로드맵과의 관계

019 간격 토큰, 014 타이포 6단, slate 크롬을 그대로 쓴다. 와이어프레임의 위젯 카드
(흰 카드·12px 안팎 모서리·헤어라인)는 014 모달 마감 문법과 동족이다. 필요한 신규
요소는 **숫자 타일, 진행 바, 분포 바(다색 구간), 도넛, 스파크라인** — 웹앱 번들에
차트 라이브러리가 없으므로 경량 SVG 자작 vs 라이브러리 도입을 brainstorming에서
결정한다. 다크 테마(로드맵 2순위) 적용 대상에 대시보드를 포함한다.

### 권한

- 내·팀 대시보드는 자신이 멤버인 채널·보드·실행의 데이터만 집계한다.
- 조직 대시보드는 노출 대상 결정이 필요하다 — 전 구성원 공개인지, 리더 역할
  한정인지. 팀원별 Todo 건수·응답 속도 같은 **개인별 수치의 타인 노출**은
  002(프로필 공개 범위) 정책과 함께 specify 단계에서 확정한다.
- "상세 필터", 우수 팀 선정 같은 비교·서열화 요소는 조직 문화 민감도가 있어
  기획 확인을 거친다.

## 6. 단계별 실행 계획

CLAUDE.md 규칙대로, 각 단계는 brainstorming 또는 `/speckit-specify`로 진입한다.

| 단계 | 내용 | 대상 위젯 | 분량 | 진입 방식 |
|---|---|---|---|---|
| 1 | **결정 세션** — 4절의 다섯 결정 + 차트 방식 | — | S | **brainstorming** |
| 2 | 대시보드 셸 — 레일 진입점·라우트·유형 사이드바·카드 그리드·AI 인사이트 줄(규칙형) | 공통 골격 | M | specify |
| 3 | 내 대시보드 1차 | 멘션·요청(A), Todo 3타일·조치 목록(결정 1 반영), 활동 요약 | M | specify |
| 4 | 팀 대시보드 1차 | 팀 전환(A), 보드 현황(A), 플레이북 실행 현황(A~B) | M | specify |
| 5 | OKR 규약 + 목표 위젯 | OKR 카드, 내 목표 달성률, 스냅샷(증감) | M~L | specify (규약은 1단계에서 확정) |
| 6 | 서버 집계 | 활동 시계열, 응답 속도, 팀원별 Todo, 진행 막힘+리마인드 | M~L | specify (API 계약 포함) |
| 7 | 조직 대시보드 | 주간 지표, 팀별 현황 표, 합성 지표(산식 확정분만) | L | specify |
| 8 | 배지·칭찬 시스템 | 개인 배지, 팀 배지 카드, 칭찬 피드, 우수 팀 | L | **별도 기능 spec** (brainstorming) |
| 9 | AI 인텔리전스 챗 | 조직 질의 챗 | L | **별도 기획** (데이터 거버넌스 포함) |

단계 2~4가 끝나면 와이어프레임의 내·팀 대시보드 골격이 실데이터로 돈다.
단계 8·9는 대시보드가 아니라 독립 기능이므로 이 계획서의 범위에서 분리해 둔다.

## 7. 검증 기준 후보 (SC 초안)

- **SC-D1**: 각 대시보드 첫 로드가 채널 20개·보드 5개(카드 총 1,000장)·실행 20건 환경에서 2초 이내에 완료된다.
- **SC-D2**: 위젯 수치가 원천 화면과 일치한다 — 멘션 수 = 사이드바 뱃지 합, 보드 분포 = 보드 그룹 뷰 집계, 플레이북 진행 = 플레이북 화면의 체크리스트 값.
- **SC-D3**: 멤버가 아닌 채널·보드·실행의 데이터가 어떤 위젯에도 나타나지 않는다.
- **SC-D4**: slate·다크 양쪽에서 모든 위젯이 WCAG AA를 지킨다 (디자인 로드맵 상시 게이트에 편입).
- **SC-D5**: Boards·Playbooks·Todo 플러그인 중 어느 것을 비활성화해도 나머지 위젯은 정상이고, 해당 위젯만 빈 상태 안내로 대체된다.
- **SC-D6**: OKR 규약을 따르지 않는 보드는 OKR 위젯에서 제외되고, 제외 사유가 설정 화면에 표시된다.

## 8. 비범위

- Boards·Playbooks·Todo 플러그인 바이너리 수정 — API 소비만 한다
- HR 데이터(입/퇴사자·인건비) 질의 — 저장되지 않는 데이터. AI 인텔리전스 기획(단계 9)에서 범위 재협의
- 외부 BI 연동·내보내기
- 모바일 앱 대시보드 — 웹 우선
- 와이어프레임의 데모 수치·문구 재현 — 수치는 전부 실데이터로 대체한다
