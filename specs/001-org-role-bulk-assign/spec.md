## User Scenarios & Testing *(mandatory)*

### User Story 1 - 여러 사용자에게 부서/직위 일괄 지정 (Priority: P1)

관리자가 "조직/직위 관리" 화면에서 여러 사용자를 체크박스로 선택한 뒤, 상단의 일괄 지정 툴바에서 부서 또는 직위(또는 둘 다)를 선택하고 "선택 적용"을 누르면, 선택된 사용자 전원의 해당 필드가 한 번에 변경된다. 이후 "저장" 버튼을 한 번만 눌러 변경된 사용자 전원의 배정을 서버에 반영한다.

**Why this priority**: 현재는 사용자마다 부서/직위를 선택하고 행마다 있는 "저장" 버튼을 눌러야 해서, 사용자가 많은 팀에서는 반복 작업 부담이 크다. 다중 선택과 일괄 지정·저장은 이 기능의 핵심 가치이며, 이것만 구현해도 실질적인 업무 개선(MVP)이 된다.

**Independent Test**: 사용자 3명을 체크박스로 선택하고, 일괄 부서만 선택해 "선택 적용"을 누른 뒤 "저장"을 클릭하면, 선택된 3명의 부서만 변경되고 각자의 기존 직위 값은 유지된 채로 서버에 저장됨을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자 리스트에 여러 사용자가 표시되어 있는 상태, **When** 관리자가 2명 이상의 사용자 체크박스를 선택하고 일괄 부서 선택 후 "선택 적용"을 누르면, **Then** 선택된 사용자들의 부서 값만 변경되고 직위 값은 각자 기존 값으로 유지된다.
2. **Given** 일괄 지정으로 여러 사용자의 값이 변경(미저장)된 상태, **When** 관리자가 "저장" 버튼을 한 번 클릭하면, **Then** 변경된(Dirty) 사용자 전원의 배정이 서버에 저장되고, 변경되지 않은 사용자는 저장 대상에서 제외된다.
3. **Given** 변경(Dirty)된 사용자가 하나도 없는 상태, **When** 관리자가 화면을 확인하면, **Then** "저장" 버튼은 비활성화되어 있다.

### User Story 2 - 필터/검색 화면에서 표시된 사용자 전체 선택 (Priority: P2)

관리자가 부서/직위 필터나 검색어로 사용자 목록을 좁힌 상태에서, 헤더의 "전체 선택" 체크박스를 클릭하면 현재 화면에 표시된(필터링된) 사용자만 전체 선택/해제된다. 필터를 바꿔 다른 사용자 그룹을 추가로 선택해도 이전 선택은 유지된다.

**Why this priority**: 대규모 팀에서는 필터/검색으로 대상을 좁혀 작업하는 경우가 많다. 전체 선택 범위가 명확하지 않으면(예: 필터 밖 사용자까지 실수로 선택) 의도치 않은 대량 변경 사고로 이어질 수 있어, 다중 선택 기능(User Story 1)에 안전하게 기반이 되는 다음 우선순위 기능이다.

**Independent Test**: 검색어로 사용자 목록을 2명으로 좁힌 뒤 "전체 선택"을 클릭하면 그 2명만 선택되고, 검색어를 지웠을 때 나머지 사용자들은 선택되어 있지 않음을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 부서/직위 필터 또는 검색어로 사용자 목록이 일부만 표시된 상태, **When** 관리자가 헤더의 "전체 선택" 체크박스를 클릭하면, **Then** 현재 화면에 표시된 사용자만 선택되고 필터에 해당하지 않아 화면에 없는 사용자의 선택 상태는 변경되지 않는다.
2. **Given** 특정 사용자가 체크박스로 선택된 상태, **When** 관리자가 필터/검색 조건을 변경해 그 사용자가 화면에서 보이지 않게 되어도, **Then** 해당 사용자의 선택 상태는 그대로 유지되며 이후 "저장" 시에도 변경 사항이 있다면 포함된다.

### User Story 3 - 일괄 저장 결과(성공/실패) 확인 (Priority: P3)

관리자가 다수 사용자를 일괄 저장했을 때, 일부는 성공하고 일부는 실패할 수 있다. 저장이 끝나면 성공/실패 건수를 요약한 메시지가 표시되어, 관리자가 실패한 대상을 파악하고 재시도할 수 있다.

**Why this priority**: 다중 저장에서는 네트워크 오류 등으로 일부만 실패하는 상황이 발생할 수 있다. 이 시나리오는 핵심 저장 기능(User Story 1)이 동작한 이후에 완성도를 높이는 보조 기능이다.

**Independent Test**: 특정 사용자 저장 요청이 실패하도록 설정한 상태에서 다수 사용자를 일괄 저장하면, 성공 건수와 실패 건수가 함께 표시되는 요약 메시지를 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 변경된 사용자 여러 명 중 일부의 저장 요청이 실패하는 상황, **When** 관리자가 "저장"을 클릭하면, **Then** 성공한 사용자 수와 실패한 사용자 수가 모두 표시되고, 실패 건이 있는 경우 요약 메시지는 자동으로 사라지지 않는다.
2. **Given** 모든 변경 사용자의 저장이 성공한 상황, **When** 저장이 완료되면, **Then** 성공 메시지가 일정 시간 후 자동으로 사라진다(기존 단일 저장 성공 메시지와 동일한 동작 유지).

---

### Edge Cases

- 일괄 지정 시 부서/직위 중 한 필드만 선택하고 "선택 적용"을 누르면, 선택하지 않은 필드는 선택된 사용자 각자의 기존 값이 그대로 유지되어야 한다(다른 값으로 덮어쓰거나 비워지면 안 됨).
- 일괄 지정 툴바는 부서/직위를 "미지정(빈 값)"으로 일괄 초기화하는 기능은 제공하지 않는다 — 값을 설정하는 용도로만 동작한다.
- 선택된 사용자 중 아무도 변경(Dirty)되지 않았다면(단순히 체크박스만 선택하고 값은 그대로인 경우) "저장" 클릭 시 해당 사용자에 대한 저장 요청은 발생하지 않는다.
- 팀을 전환하거나 사용자 목록을 다시 불러오면 체크박스 선택 상태, 일괄 지정 툴바 값은 초기화된다.
- 일괄 저장 도중 관리자가 다른 팀으로 전환하는 경우, 이미 진행 중인 저장 요청이 이전 팀의 데이터를 잘못된 화면 상태에 반영하지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자 리스트의 각 행에 선택용 체크박스를 제공해야 한다.
- **FR-002**: 시스템은 사용자 리스트 헤더에 "전체 선택" 체크박스를 제공해야 하며, 클릭 시 현재 부서/직위 필터 및 검색어 조건에 따라 화면에 표시된 사용자에 한해 선택 상태를 일괄 전환해야 한다.
- **FR-003**: 시스템은 필터/검색 조건 변경으로 특정 사용자가 화면에서 보이지 않게 되어도 해당 사용자의 선택 상태를 유지해야 한다.
- **FR-004**: 시스템은 일괄 지정 툴바(일괄 부서 선택, 일괄 직위 선택, "선택 적용" 버튼)를 제공해야 하며, 선택된 사용자가 1명 이상이고 부서 또는 직위 중 하나 이상이 선택된 경우에만 "선택 적용"을 활성화해야 한다.
- **FR-005**: "선택 적용" 실행 시, 시스템은 선택된 사용자 전원에 대해 실제로 값이 지정된 필드(부서 또는 직위)만 덮어써야 하며, 값을 지정하지 않은 필드는 각 사용자의 기존 값을 그대로 유지해야 한다.
- **FR-006**: "선택 적용"은 화면상의 변경 사항만 반영하며, 서버 저장은 별도의 "저장" 조작을 통해서만 이루어져야 한다.
- **FR-007**: 시스템은 마지막으로 서버에 저장된 값과 현재 화면상의 값을 비교하여 변경된(Dirty) 사용자를 판별해야 한다.
- **FR-008**: 시스템은 화면 전체에 대해 단일 "저장" 버튼을 제공해야 하며, 클릭 시 변경된(Dirty) 사용자 전원의 배정을 저장하고, 변경되지 않은 사용자는 저장 대상에서 제외해야 한다. 기존에 존재하던 사용자별 개별 "저장" 버튼은 제거한다.
- **FR-009**: 변경된(Dirty) 사용자가 한 명도 없는 경우, 시스템은 "저장" 버튼을 비활성화해야 한다.
- **FR-010**: 시스템은 저장 처리 중 사용자가 "저장"을 중복 클릭하지 못하도록 버튼을 비활성화해야 한다.
- **FR-011**: 일괄 저장 중 일부 사용자의 저장이 실패해도, 시스템은 나머지 사용자에 대한 저장 처리를 계속 진행해야 한다(부분 실패 허용).
- **FR-012**: 저장 완료 후, 시스템은 성공한 사용자 수와 실패한 사용자 수를 요약한 메시지를 표시해야 한다. 실패가 없는 경우 메시지는 일정 시간 후 자동으로 사라지고, 실패가 있는 경우에는 자동으로 사라지지 않아야 한다.
- **FR-013**: 시스템은 팀 전환 또는 사용자 목록 재조회 시 체크박스 선택 상태와 일괄 지정 툴바의 입력 값을 초기화해야 한다.
- **FR-014**: 시스템은 기존에 제공되던 부서/직위별 필터, 사용자 검색 기능의 동작을 이번 변경 이후에도 그대로 유지해야 한다.
- **FR-015**: 일괄 지정 툴바는 부서 또는 직위를 "미지정(빈 값)"으로 일괄 초기화하는 기능을 제공하지 않는다(값 설정 전용).

### Key Entities *(include if feature involves data)*

- **사용자 배정 (조직/직위 프로필)**: 한 사용자가 하나의 팀 내에서 갖는 부서·직위 지정 정보. 저장 시점의 값(서버 기준)과 화면에서 편집 중인 값(아직 저장되지 않은 값)이 구분되며, 이 둘의 차이가 "변경(Dirty)" 여부를 결정한다.
- **부서 (조직 단위)**: 팀 내에서 사용자를 소속시킬 수 있는 조직 분류 항목.
- **직위**: 팀 내에서 사용자에게 부여할 수 있는 직위 분류 항목.
- **선택 상태**: 사용자 리스트에서 일괄 작업 대상으로 지정된 사용자 집합. 필터/검색 결과와 독립적으로 유지된다.
- **일괄 지정 입력값**: 일괄 지정 툴바에서 관리자가 선택한 부서/직위 값. 각 필드는 비어 있으면 "변경하지 않음"을 의미하며, 값이 지정된 필드만 선택된 사용자 전원에게 적용된다.
- **저장 결과 요약**: 일괄 저장 조작 1회에 대한 성공/실패 처리 결과(성공한 사용자 수, 실패한 사용자 수)를 담는 화면 표시용 정보.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 선택한 사용자 수와 관계없이 단 1회의 저장 조작으로 변경된 모든 사용자의 부서/직위 배정을 반영할 수 있다.
- **SC-002**: 관리자는 부서 또는 직위 중 하나만 지정해 일괄 적용했을 때, 지정하지 않은 필드가 의도치 않게 변경되는 사례 없이 100% 기존 값을 유지한다.
- **SC-003**: 저장 조작 후 5초 이내에 성공/실패 처리 결과(건수)를 화면에서 확인할 수 있다.
- **SC-004**: 필터/검색 조건을 변경해도 이미 선택한 사용자의 선택 상태는 100% 유지되어 손실되지 않는다.
- **SC-005**: 기존에 제공되던 단일 사용자 저장, 부서/직위 필터, 사용자 검색 기능은 이번 변경 이후에도 회귀 없이 동일하게 동작한다.

## Assumptions

- 이번 기능은 프론트엔드 화면(조직/직위 관리) 개선에 한정된 1차 작업이며, 기존에 사용 중인 사용자 단건 저장 방식의 서버 처리 방식을 그대로 재사용한다. 다수 사용자를 한 번의 서버 요청으로 저장하는 별도의 서버 기능 신설은 이번 범위에 포함되지 않으며, 향후 트래픽/성능상 필요가 확인되면 별도 과제로 다룬다.
- 처리 대상 사용자 규모는 현재 화면이 다루는 팀 단위 사용자 목록(약 수백 명 수준) 범위로 가정하며, 그 이상의 대규모 처리 성능 목표는 이번 범위에 포함되지 않는다.
- 저장은 변경된 사용자에 대해 순차적으로 처리되어, 다수 사용자를 동시에 저장할 때 발생할 수 있는 서버 부하를 최소화한다.
- 부서/직위를 "미지정" 상태로 일괄 초기화(일괄 해제)하는 기능은 이번 범위에서 제외한다.
- 두 명 이상의 관리자가 동시에 같은 팀의 배정을 편집하는 동시 편집 충돌 처리는 이번 범위에 포함되지 않으며, 기존 단건 저장 방식과 동일한 수준으로 취급한다.
