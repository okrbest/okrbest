# Feature Specification: 팀 멤버 프로필 부서/직위 표시 및 계정 설정 직책 관리체계 전환

**Feature Branch**: `002-org-role-profile-visibility`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "멤버 프로필 팝오버에 부서/직위가 표시되지 않아 팀 관리자가 지정한 부서/직위를 확인할 수 있도록 하고, 개인이 직접 입력하던 계정 설정의 직책 필드는 관리자 관리 모델(조직/직위 관리)에 맞춰 읽기 전용으로 전환한다."

## Clarifications

### Session 2026-07-27

- Q: 부서 또는 직위 중 하나만 지정된 경우, 그리고 화면(프로필 카드/계정 설정)별로 부서·직위를 어떤 형식으로 표시할까? → A: 프로필 카드는 "부서명 · 직위명" 한 줄 결합 표시를 유지하되 한쪽이 없으면 그 자리에 "부서 미지정"/"직위 미지정"을 넣어 결합한다(예: "개발팀 · 직위 미지정"). 계정 설정은 기존 라벨-값 행 구조에 맞춰 "부서" 행과 "직위" 행을 각각 별도로 두고, 값이 없는 행에는 "미지정"을 표시한다.
- Q: 사용자에게 활성(현재) 팀이 없는 경우 계정 설정의 부서/직위 행을 어떻게 처리할까? → A: 행 자체를 숨긴다. 팀 맥락이 없는 상태를 "미지정"으로 표시하면 "배정되지 않음"과 "확인 불가"가 다시 혼동되므로, 프로필 카드에서 타팀 사용자를 숨기는 것(User Story 3)과 동일한 원칙을 적용한다.
- Q: 사용자 조직 프로필에는 "주 부서/주 직위" 외에 겸직용 "추가 직위" 필드도 있는데, 프로필 카드·계정 설정에 겸직까지 표시할까? → A: 주 부서/주 직위만 표시한다. 현재 조직/직위 관리 화면에는 겸직을 배정하는 UI 자체가 없어(저장 시 항상 빈 값으로 전송됨) 실제로 표시할 겸직 데이터가 없으며, 이번 기능의 범위는 이미 배정 가능한 주 부서/주 직위 확인으로 한정한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프로필 카드에서 동료의 부서/직위 확인 (Priority: P1)

같은 팀에 속한 멤버가 다른 동료의 프로필 카드(팝오버)를 열었을 때, 팀 관리자가 지정한 부서와 직위를 바로 확인할 수 있다.

**Why this priority**: 현재 프로필 카드에는 부서/직위 정보가 전혀 노출되지 않아, 동료가 어느 부서·직위인지 알기 위해 별도로 물어보거나 관리 화면에 접근해야 한다. 이 문제를 해결하는 것이 이번 기능의 핵심 가치다.

**Independent Test**: 팀 관리자가 조직/직위 관리 화면에서 특정 멤버에게 부서와 직위를 지정한 뒤, 같은 팀의 다른 멤버 계정으로 로그인해 해당 멤버의 프로필 카드를 열어 부서·직위가 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 팀 관리자가 멤버 A에게 부서 "개발팀"과 직위 "팀장"을 지정한 상태, **When** 같은 팀의 멤버 B가 멤버 A의 프로필 카드를 연다, **Then** 프로필 카드에 "개발팀 · 팀장"이 표시된다.
2. **Given** 멤버 A에게 부서만 지정되고 직위는 지정되지 않은 상태, **When** 멤버 B가 멤버 A의 프로필 카드를 연다, **Then** "개발팀 · 직위 미지정"처럼 지정된 부서명과 함께 직위 자리에 "직위 미지정"이 결합되어 표시된다.
3. **Given** 멤버 A에게 부서/직위가 전혀 지정되지 않은 상태, **When** 멤버 B가 멤버 A의 프로필 카드를 연다, **Then** "부서 미지정 · 직위 미지정"으로 표시되어, 아직 배정되지 않았을 뿐 조회 권한이 없어 숨겨진 것이 아님을 알 수 있다.

### User Story 2 - 계정 설정에서 자신의 부서/직위를 읽기 전용으로 확인 (Priority: P2)

사용자가 계정 설정 화면에서 자신에게 배정된 부서/직위를 확인할 수 있지만, 더 이상 직접 값을 입력하거나 수정할 수 없다.

**Why this priority**: 부서/직위가 팀 관리자 관리 체계로 일원화된 이상, 개인이 자유 텍스트로 값을 직접 써 넣을 수 있는 기존 경로는 실제 배정값과 어긋나는 혼란을 만든다. 이 경로를 막고 조회만 가능하게 정리해야 단일 소스 원칙이 지켜진다.

**Independent Test**: 팀 관리자가 지정한 부서/직위가 있는 사용자로 로그인해 계정 설정의 해당 항목을 열어, 입력창/저장 버튼 없이 값과 안내 문구만 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 팀 관리자가 사용자 본인에게 부서/직위를 지정한 상태, **When** 사용자가 계정 설정에서 해당 항목을 연다, **Then** 기존 "사용자 이름"/"사용자 ID" 행과 같은 형식으로 "부서" 행과 "직위" 행이 각각 읽기 전용 값으로 표시되고, 입력창이나 저장 동작은 제공되지 않는다.
2. **Given** 사용자에게 부서 또는 직위 중 하나만 지정된 상태, **When** 사용자가 계정 설정에서 해당 항목을 연다, **Then** 지정된 행은 값이, 지정되지 않은 행은 "미지정"이 표시되며, 값이 없는 행에는 이 값이 팀 관리자에 의해 관리된다는 안내 문구가 함께 표시된다.
3. **Given** 사용자가 이전에 자유 텍스트로 입력해 두었던 값이 있는 상태, **When** 이번 변경이 적용된 이후 계정 설정을 연다, **Then** 더 이상 그 자유 텍스트 값이 아니라 "부서"/"직위" 행에 팀 관리자 지정값(또는 미지정)이 표시된다.
4. **Given** 사용자에게 활성화된(현재) 팀이 전혀 없는 상태, **When** 사용자가 계정 설정을 연다, **Then** "부서"/"직위" 행 자체가 표시되지 않는다.

---

### User Story 3 - 소속되지 않은 팀 맥락에서의 안전한 표시 (Priority: P3)

열람자가 프로필 카드를 연 시점에 대상 사용자가 열람자의 현재 팀 소속이 아닌 경우(예: 다른 팀 소속 사용자와의 다이렉트 메시지), 부서/직위 영역이 오표시 없이 처리된다.

**Why this priority**: 팀별로 배정되는 부서/직위를 팀 맥락 없이 보여주면 실제로는 확인 불가능한 상황과 "배정되지 않음"을 혼동하게 만들 수 있다. 핵심 시나리오는 아니지만 잘못된 정보 노출을 막기 위해 필요하다.

**Independent Test**: 서로 다른 팀에 속한 두 사용자가 다이렉트 메시지로 대화하는 상황에서 상대방의 프로필 카드를 열어, 부서/직위 영역이 "미지정"과 구분되게 처리되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 멤버 B가 멤버 A와 같은 팀에 속해 있지 않은 상태, **When** 멤버 B가 멤버 A의 프로필 카드를 연다, **Then** 부서/직위 영역이 표시되지 않는다(값이 없는 "미지정"과는 시각적으로 구분됨).

---

### Edge Cases

- 부서와 직위가 모두 지정되지 않은 경우: 프로필 카드는 "부서 미지정 · 직위 미지정", 계정 설정은 "부서"/"직위" 두 행 모두 "미지정"으로 표시한다.
- 부서 또는 직위 중 하나만 지정된 경우: 프로필 카드는 지정된 값과 미지정 라벨을 결합해 표시하고(예: "개발팀 · 직위 미지정"), 계정 설정은 지정된 행에만 값을, 나머지 행에는 "미지정"을 표시한다.
- 조회 대상이 열람자의 현재 팀 소속이 아닌 경우: 부서/직위 표시 영역 자체를 노출하지 않는다(User Story 3).
- 조직/직위 관리 기능이 비활성화된 환경(팀/시스템 설정)에서는 프로필 카드와 계정 설정 모두에서 부서/직위 영역을 노출하지 않는다.
- 봇 계정 등 부서/직위 배정 대상이 아닌 계정의 프로필 카드에서는 해당 영역을 노출하지 않는다.
- 사용자가 여러 팀에 속한 경우, 프로필 카드/계정 설정에 표시되는 부서/직위는 열람 시점에 활성화된 팀 기준으로 결정된다.
- 사용자에게 활성화된(현재) 팀이 전혀 없는 경우, 계정 설정에서도 "부서"/"직위" 행 자체를 표시하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 같은 팀에 소속된 멤버가 다른 팀원의 프로필 카드에서 팀 관리자가 지정한 부서명과 직위명을 조회할 수 있게 해야 한다.
- **FR-002**: 시스템은 부서·직위 중 하나 또는 둘 다 지정되지 않은 경우 해당 항목(들)을 "미지정"으로 표시해야 한다(화면별 정확한 형식은 FR-002a/FR-002b를 따른다).
- **FR-002a**: 프로필 카드는 부서명과 직위명을 "부서명 · 직위명" 한 줄로 결합해 표시해야 하며, 한쪽이 없으면 그 자리에 "부서 미지정" 또는 "직위 미지정"을 넣어 결합 표시해야 한다(예: "개발팀 · 직위 미지정").
- **FR-002b**: 계정 설정 화면은 부서와 직위를 각각 별도의 라벨-값 행으로 표시해야 하며, 값이 없는 행에는 "미지정"을 표시해야 한다.
- **FR-003**: 시스템은 조회 대상이 열람자의 현재 팀 소속이 아닌 경우, 부서/직위 표시 영역을 노출하지 않아야 한다.
- **FR-004**: 시스템은 프로필 카드에서 개인이 직접 입력하던 기존 자유 텍스트 직책 표시를 제거하고, 팀 관리자가 지정한 부서/직위 결합 표시(FR-002a)로 대체해야 한다.
- **FR-005**: 시스템은 계정 설정 화면에서 사용자가 자신에게 배정된 부서/직위를 부서·직위 별도 행(FR-002b)의 읽기 전용 값으로 확인할 수 있게 해야 한다.
- **FR-005a**: 시스템은 사용자에게 활성화된(현재) 팀이 없는 경우, 계정 설정에서 "부서"/"직위" 행 자체를 표시하지 않아야 한다.
- **FR-006**: 시스템은 계정 설정 화면에서 사용자가 부서/직위(직책) 값을 직접 입력하거나 수정할 수 있는 경로를 제공하지 않아야 한다.
- **FR-007**: 시스템은 계정 설정 화면에서 부서/직위 값이 팀 관리자에 의해 관리됨을 알리는 안내 문구를 제공해야 한다.
- **FR-008**: 시스템은 부서/직위 조회를 위한 권한을, 부서/직위 수정 권한(팀 관리자/시스템 관리자 전용)과 분리하여 같은 팀 소속 멤버가 조회할 수 있도록 허용해야 한다(단, 기존 사용자 간 가시성 제한 정책이 적용 중이라면 그 정책을 그대로 따른다). 수정 권한 정책은 이번 기능으로 변경하지 않는다.
- **FR-009**: 시스템은 조직/직위 관리 기능이 비활성화된 경우, 프로필 카드와 계정 설정 양쪽에서 부서/직위 표시 영역을 노출하지 않아야 한다.

### Key Entities

- **부서(조직 단위)**: 팀 내부의 조직 구조를 나타내는 단위로, 이름을 가지며 팀 관리자가 관리한다.
- **직위**: 팀 내에서 사용되는 직위/직책 정의로, 이름을 가지며 팀 관리자가 관리한다.
- **사용자 조직 프로필**: 특정 팀 내에서 한 사용자에게 배정된 주 부서와 주 직위를 나타내며, 팀 관리자가 배정하고 프로필 카드·계정 설정 조회에 사용된다. (겸직 개념은 배정 UI가 없어 이번 기능의 표시 범위에서 제외한다.)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 팀 멤버는 별도 문의나 관리 화면 접근 없이, 프로필 카드만으로 동료의 부서와 직위를 확인할 수 있다.
- **SC-002**: 계정 설정 화면에서 사용자가 부서/직위 값을 직접 입력·수정하는 경로가 100% 제거된다.
- **SC-003**: 부서/직위가 배정되지 않은 멤버의 프로필에서도 "미지정" 표시를 통해 혼란 없이 상태를 확인할 수 있다.
- **SC-004**: 팀 관리자가 지정한 부서/직위 값과 프로필 카드·계정 설정에 표시되는 값이 항상 일치한다(단일 소스 원칙 위반 사례 0건).

## Assumptions

- 부서/직위의 단일 소스는 팀 관리자의 조직/직위 관리 기능이며, 개인이 입력하던 기존 직책 값은 더 이상 신뢰 가능한 표시 소스로 사용하지 않는다.
- 표시 대상은 열람자와 같은 팀에 소속된 멤버 전체이며, 부서/직위 자체를 배정·관리하는 팀 관리자 권한 정책은 이번 기능의 변경 범위에 포함하지 않는다.
- 사용자가 여러 팀에 속해 있을 경우, 프로필 카드와 계정 설정에 표시되는 부서/직위는 조회 시점에 활성화된(현재 보고 있는) 팀 기준으로 결정된다.
- 조직/직위 관리 기능이 비활성화된 환경에서는 이번 기능의 표시 영역 자체가 노출되지 않는 것을 정상 동작으로 간주한다.
- 부서/직위 조회는 같은 팀 소속을 기본 조건으로 하되, 기존에 적용 중인 사용자 간 가시성 제한 정책(있는 경우)을 그대로 따른다 — 이번 기능이 새로운 가시성 예외를 만들지 않는다.
