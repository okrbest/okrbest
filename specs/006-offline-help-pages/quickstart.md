# Quickstart: 오프라인 도움말 페이지 검증

이 기능이 end-to-end로 동작하는지 확인하기 위한 실행 가능한 검증 시나리오다.
구현 세부사항(컴포넌트 내부 로직)은 [data-model.md](./data-model.md)와
`tasks.md`(구현 단계에서 생성)를 참고한다.

## 사전 준비

```bash
cd webapp
npm install   # 최초 1회
cd channels
npm run dev   # 또는 프로젝트의 표준 로컬 실행 스크립트
```

## 시나리오 1: 서식 도움말 진입 (User Story 1, P1)

1. 브라우저에서 로그인 후 채널 진입, 메시지 작성창에 포커스.
2. 작성창 하단 도움말 버튼 클릭.
3. **기대 결과**: 서식 안내 페이지(또는 도움말 목록에서 "서식" 선택 시 서식 안내)가 새 창 또는 인앱 화면으로 열린다.
4. 작성창에 임의 텍스트 입력 후 다시 도움말 버튼 클릭 → 확인 후 창을 닫거나 채널로 돌아옴.
5. **기대 결과**: 앞서 입력한 텍스트가 작성창에 그대로 남아 있다(SC-002).

## 시나리오 2: 명령어 도움말 (User Story 2, P2)

1. 도움말 목록에서 "명령어" 항목 선택.
2. **기대 결과**: 이 포크(서버)에 실제로 존재하는 슬래시 명령어만 이름·설명·예시와 함께 나열된다 — 존재하지 않는 명령어 언급이 없어야 한다(SC-004).

## 시나리오 3: 멘션·파일첨부·전송 도움말 (User Story 3, P3)

1. 도움말 목록에서 "멘션", "파일 첨부", "전송" 항목을 각각 선택.
2. **기대 결과**: 각 주제의 안내 페이지가 표시되고, 실제 동작(예: `@`/`~` 멘션 표기, 드래그 앤 드롭 첨부)과 내용이 일치한다.

## 시나리오 4: 팝업 차단 폴백 (Edge Case)

1. 브라우저 팝업 차단 설정을 켠 상태로 도움말 버튼 클릭.
2. **기대 결과**: 새 창이 열리지 않는 대신 인앱 화면으로 도움말이 표시된다(SC-003) — 기능이 완전히 막히지 않는다.

## 시나리오 5: 리브랜드·번역 확인

1. 도움말의 5개 페이지를 모두 열어 본문에 "Mattermost" 문자열이 남아 있지 않은지 확인(FR-005).
2. 브라우저 언어를 한국어로 설정한 상태에서 5개 페이지 모두 한국어로 표시되는지 확인(FR-006) — 영어 원문이 노출되는 항목이 없어야 한다.

## 자동화 테스트 실행

```bash
cd webapp/channels
npm run test -- src/components/help src/components/help_popout src/components/advanced_text_editor/help_button src/components/advanced_text_editor/footer.test.tsx
npm run check
npm run check-types
```

모든 테스트·린트·타입체크가 통과해야 constitution 원칙 I을 충족한 것으로 간주한다.
