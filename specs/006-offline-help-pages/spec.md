# Feature Specification: 오프라인 도움말 페이지

**Feature Branch**: `006-offline-help-pages`

**Created**: 2026-07-31

**Status**: Draft

**Input**: User description: "오프라인 도움말 페이지 기능 추가 (specs/006-offline-help-pages). Upstream 커밋 MM-61383 \"add back offline user help for messagging\" (https://github.com/mattermost/mattermost/commit/37ec26b81a0d13c264ffd6afd6370bc83115307d, 2026-01-23)를 참고 소스로 사용. 메시지 작성창(composer) 하단에 도움말 버튼을 추가하고, 클릭 시 서식(formatting)/명령어(commands)/전송(sending)/멘션(mentioning)/파일첨부(attaching) 안내 페이지를 새 창(popout) 또는 인앱으로 띄우는 기능."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 메시지 작성 중 서식 문법 확인 (Priority: P1)

메시지를 작성하던 사용자가 굵게/기울임/코드블록 등 서식 문법이 기억나지 않아 작성창 하단의 도움말 버튼을 클릭하면, 별도 창(팝업)에서 서식 가이드 페이지가 열려 예시와 함께 문법을 확인할 수 있다. 확인 후 원래 작성 중이던 메시지로 바로 돌아와 이어서 작성한다.

**Why this priority**: 서식 문법은 신규/비정기 사용자가 가장 자주 막히는 지점이며, 작성 흐름을 끊지 않고 확인할 수 있어야 실제 도움이 된다. 이 기능 하나만으로도 "도움말 버튼 → 서식 안내"라는 핵심 가치가 완결된다.

**Independent Test**: 메시지 작성창 하단의 도움말 버튼을 클릭 → 서식 안내 페이지가 새 창 또는 인앱 화면으로 열리는지, 안내 내용이 실제 지원되는 서식과 일치하는지 확인만으로 독립적으로 검증 가능.

**Acceptance Scenarios**:

1. **Given** 사용자가 메시지 작성창에 포커스가 있는 상태, **When** 작성창 하단의 도움말 버튼을 클릭, **Then** 기본 화면으로 "메시징 기초" 개요 페이지가 표시되며, 여기서 서식/명령어/전송/멘션/파일첨부 도움말로 이동할 수 있는 링크가 함께 제공된다.
2. **Given** 도움말 창이 열려 있는 상태, **When** 사용자가 작성 중이던 채널/메시지로 돌아감, **Then** 작성 중이던 텍스트가 그대로 유지되어 있다.

---

### User Story 2 - 슬래시 명령어 목록 확인 (Priority: P2)

`/`로 시작하는 슬래시 명령어의 종류와 사용법이 궁금한 사용자가 도움말에서 "명령어" 섹션을 선택하면, 지원되는 명령어 목록과 각 명령어의 사용 예시를 확인할 수 있다.

**Why this priority**: 서식 다음으로 자주 찾는 정보이지만, 명령어 자체를 몰라도 메시지 전송의 핵심 흐름에는 지장이 없어 P1보다 우선순위가 낮다.

**Independent Test**: 도움말 내 "명령어" 페이지로 이동해 현재 서버/포크에 실제 존재하는 명령어만 나열되는지 확인.

**Acceptance Scenarios**:

1. **Given** 도움말 목록 화면, **When** "명령어" 항목을 선택, **Then** 명령어별 이름·설명·예시가 표 또는 목록 형태로 표시된다.

---

### User Story 3 - 멘션·파일첨부·전송 방법 확인 (Priority: P3)

`@`/`~` 멘션 표기법, 파일 첨부 방법(드래그 앤 드롭 등), 메시지 전송/줄바꿈 단축키가 궁금한 사용자가 각각의 도움말 페이지에서 안내를 확인한다.

**Why this priority**: 서식·명령어에 비해 상대적으로 직관적으로 유추 가능한 영역이라 우선순위가 가장 낮지만, upstream 원본 기능의 완전성을 위해 포함한다.

**Independent Test**: 각 하위 도움말 페이지(멘션/파일첨부/전송)로 개별 이동해 내용이 실제 동작과 일치하는지 확인.

**Acceptance Scenarios**:

1. **Given** 도움말 목록 화면, **When** "멘션" 또는 "파일 첨부" 또는 "전송" 항목을 선택, **Then** 해당 주제의 안내 페이지가 표시된다.

---

### Edge Cases

- 브라우저의 팝업 차단 설정으로 별도 창이 열리지 않을 경우, 인앱 화면으로 대체 표시되어야 한다.
- 도움말 버튼이 작성창 하단에서 다른 버튼(전송, 첨부 등)과 겹치거나 좁은 화면에서 잘리지 않아야 한다.
- 도움말 페이지 내 링크·안내 문구가 이 포크에 존재하지 않는 기능(예: 우리가 제거했거나 아직 없는 기능)을 언급하지 않아야 한다.
- 다국어(한국어) 환경에서 번역이 없는 항목은 영어 원문이 그대로 노출될 수 있으며, 이 경우도 레이아웃이 깨지지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 메시지 작성창(composer) 하단에 도움말 버튼을 표시해야 한다.
- **FR-002**: 도움말 버튼 클릭 시 시스템은 기본 화면으로 "메시징 기초" 개요를 표시하고, 여기서 서식/명령어/전송/멘션/파일첨부 각 상세 주제로 이동 가능한 도움말 화면을 제공해야 한다(총 6개 화면: 개요 1 + 상세 주제 5).
- **FR-003**: 시스템은 가능한 경우 도움말을 별도 창(팝업)으로 열어야 하며, 팝업이 불가능한 환경에서는 인앱 화면으로 대체 표시해야 한다.
- **FR-004**: 도움말 화면 전환은 사용자가 작성 중이던 메시지 내용을 보존해야 한다(작성창 내용 손실 없음).
- **FR-005**: 도움말 각 페이지에 포함된 제품명 언급("Mattermost" 등)은 전면 OKR.BEST로 치환하여 표기해야 한다.
- **FR-006**: 도움말 각 페이지의 사용자 대면 문자열(신규 i18n 문자열 134개 전체)은 이번 구현 범위 안에서 한국어 번역을 제공해야 한다.
- **FR-007**: 도움말 페이지 목록은 실제로 이 포크에 존재하는 기능만 안내해야 하며, 우리 fork가 아직 반영하지 않았거나 의도적으로 제외한 기능에 대한 안내는 포함하지 않아야 한다.
- **FR-008**: 도움말 화면은 각 페이지의 브라우저 탭 제목을 해당 주제에 맞게 표시해야 한다.

### Key Entities

- **도움말 페이지(Help Page)**: "메시징 기초"(기본 랜딩 개요) 및 서식/명령어/전송/멘션/파일첨부(상세 주제 5개), 총 6개 화면. 각 화면은 제목, 본문(텍스트+예시), 관련 링크로 구성.
- **도움말 진입점(Help Entry Point)**: 메시지 작성창 하단의 버튼. 클릭 시 도움말 목록 또는 첫 페이지로 연결.
- **도움말 팝업 창(Help Popout)**: 도움말을 별도 브라우저 창으로 표시하는 표시 방식. 팝업 차단 시 인앱 화면으로 대체.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 메시지 작성 중 도움말 버튼 클릭 후 원하는 주제(메시징 기초 개요, 서식/명령어/전송/멘션/파일첨부)의 안내 화면에 3초 이내에 도달할 수 있다.
- **SC-002**: 도움말 화면을 열고 닫아도 작성 중이던 메시지 내용이 100% 보존된다.
- **SC-003**: 팝업이 차단된 환경에서도 도움말 내용을 인앱 화면으로 100% 확인할 수 있다(기능 완전 불가 상태 없음).
- **SC-004**: 도움말 페이지에 노출되는 안내 내용 중, 이 포크에 존재하지 않는 기능에 대한 언급이 0건이다.

## Assumptions

- 이 기능은 upstream 커밋 `37ec26b81a0d13c264ffd6afd6370bc83115307d`(MM-61383)을 **cherry-pick으로 그대로 반영**한 뒤, 그 위에 리브랜드·번역·콘텐츠 감사를 adapt 후속 작업으로 적용하는 방식으로 구현한다(컴포넌트를 처음부터 새로 작성하지 않음) — merge-tree 충돌 없음 확인됨.
- 도움말 본문 내 제품명 언급은 전부 OKR.BEST로 치환하며, 신규 i18n 문자열 134개는 이번 구현 범위에서 전체 한국어 번역을 완료한다(사용자 확정 사항).
- 도움말 콘텐츠는 "메시징 기초"(기본 랜딩 개요) + 서식/명령어/전송/멘션/파일첨부(상세 주제 5개), 총 6개 화면으로 구성된다 — upstream 원본의 실제 파일 구성(`messaging.tsx`가 기본 라우트)과 일치. 정보 구조와 예시는 upstream 원본을 기준으로 하되, 우리 fork에 없는 기능·설정 관련 안내는 제외하거나 수정한다.
- 팝업 창 지원 여부(브라우저 새 창 vs 인앱 전용)는 upstream과 동일하게 "가능하면 팝업, 불가능하면 인앱 대체" 방식을 기본으로 한다.
- 이 기능은 데스크톱/브라우저 사용자를 우선 대상으로 하며, 모바일 환경에서의 별도 최적화는 이번 스펙 범위 밖으로 가정한다.
- 도움말 버튼·페이지 이동은 별도 서버 API 없이 클라이언트(webapp) 정적 라우팅만으로 구현 가능하다고 가정한다(upstream 커밋이 서버 변경 없이 웹앱만 수정한 것과 동일).
