# Quickstart: 공개 채널 멤버십 없는 검색 허용

**Feature**: [spec.md](./spec.md) | **Data Model**: [data-model.md](./data-model.md)

이 문서는 구현 완료 후 3개 사용자 스토리와 핵심 안전장치(비공개 채널 비노출)를 수동으로 검증하는 절차다. 구현 코드·테스트 본문은 `tasks.md`와 실제 구현 단계에서 다룬다.

## 사전 준비

- Elasticsearch(또는 OpenSearch)가 필요하다 — 기본 데이터베이스 검색으로는 이 기능을 검증할 수 없다(FR-009).
- 로컬 개발 환경에서 Elasticsearch를 함께 띄우려면:

  ```sh
  cd server
  ENABLED_DOCKER_SERVICES="postgres elasticsearch" make start-docker
  make run-server
  ```

- 관리자 계정 1개, 일반 사용자 계정 2명(A: 검증 대상 사용자, B: 메시지 작성자)이 필요하다.
- 팀 1개(T1)와 그 팀 안에 공개 채널 1개(C-public, 사용자 A는 미가입), 비공개 채널 1개(C-private, 사용자 A는 미가입)를 준비한다.

## 시나리오 1 — 기본값(꺼짐)에서 기존 동작 유지 (User Story 2, 시나리오 1)

1. 관리자 콘솔 > 환경 > Elasticsearch에서 "멤버십 없이 공개 채널 메시지 검색 허용" 설정이 꺼짐(기본값)인지 확인한다.
2. 사용자 B로 C-public에 고유 키워드(예: `QUICKSTART-PUBLIC-1`)가 포함된 메시지를 게시한다.
3. 사용자 A로 로그인해 `QUICKSTART-PUBLIC-1`을 검색한다.
4. **기대 결과**: 검색 결과가 비어 있다 — 기존 동작(멤버십 기반 검색)이 그대로 유지된다(SC-002).

## 시나리오 2 — 설정을 켠 뒤 공개 채널 메시지 검색 (User Story 1)

1. 관리자 콘솔에서 설정을 켠다.
2. Elasticsearch가 이미 가동 중이었다면, 백필 작업이 트리거되는지 서버 로그에서 확인한다(`backfillPostsChannelType` 관련 로그).
3. 백필이 끝난 뒤(또는 신규 게시물로 테스트하려면 이 단계 생략 가능), 사용자 B로 C-public에 새 고유 키워드(예: `QUICKSTART-PUBLIC-2`)가 포함된 메시지를 게시한다.
4. 사용자 A로 `QUICKSTART-PUBLIC-2`를 검색한다.
5. **기대 결과**: 검색 결과에 해당 메시지가 채널명(C-public)과 함께 나타난다(SC-001). 별도 "미가입 채널" 배지 없이 일반 결과와 동일한 형태로 표시된다(clarify Q3).

## 시나리오 3 — 비공개 채널은 절대 노출되지 않음 (Edge Case, 가장 중요한 안전장치)

1. 설정이 켜진 상태를 유지한다.
2. 사용자 B로 C-private(사용자 A 미가입)에 고유 키워드(예: `QUICKSTART-PRIVATE-1`)가 포함된 메시지를 게시한다.
3. 사용자 A로 `QUICKSTART-PRIVATE-1`을 검색한다.
4. **기대 결과**: 검색 결과가 비어 있다 — 설정이 켜져 있어도 비공개 채널 메시지는 절대 노출되지 않는다(SC-003, FR-003). 이 시나리오가 실패하면 즉시 배포를 중단해야 하는 심각도다.

## 시나리오 4 — 컴플라이언스 모드가 우선한다 (User Story 3)

1. 관리자 콘솔에서 컴플라이언스 모드(Compliance Settings > Enable)를 켠다. 검색 확장 설정은 켜진 채로 둔다.
2. 사용자 A로 시나리오 2에서 심어둔 `QUICKSTART-PUBLIC-2`를 다시 검색한다.
3. **기대 결과**: 검색 결과가 비어 있다 — 컴플라이언스 모드가 켜져 있으면 검색 확장 설정과 무관하게 멤버십 기반 검색으로 강제 전환된다(SC-004, FR-005).
4. 컴플라이언스 모드를 다시 끈다.
5. 같은 검색을 반복한다.
6. **기대 결과**: 다시 결과에 나타난다 — 컴플라이언스 모드를 끄면 검색 확장 설정이 즉시 재적용된다.

## 시나리오 5 — 채널 유형 전환 시 재색인 (Edge Case)

1. C-public(공개)을 비공개로 전환한다.
2. 이전에 C-public에 심어둔 메시지(`QUICKSTART-PUBLIC-1` 또는 `-2`)를, 그 채널의 멤버가 아닌 사용자 A로 검색한다.
3. **기대 결과**: 검색 결과가 비어 있다 — 채널 유형이 바뀌면 기존에 색인된 게시물의 `channel_type`도 갱신되어 더 이상 "공개 채널 확장 검색" 대상이 되지 않는다(FR-008).

## 검증 완료 기준

위 5개 시나리오가 모두 기대 결과대로 동작하면 이 기능은 spec.md의 모든 User Story와 핵심 Edge Case를 충족한 것이다. 시나리오 3(비공개 채널 비노출)은 다른 시나리오가 전부 통과하더라도 이것 하나가 실패하면 기능 전체를 릴리스해서는 안 되는 최우선 검증 항목이다.
