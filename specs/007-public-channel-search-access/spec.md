## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가입하지 않은 공개 채널의 메시지 검색 (Priority: P1)

사용자가 자신이 속한 팀 안에서 특정 키워드를 검색했을 때, 아직 가입하지 않은 공개 채널에 있는 메시지도 검색 결과에 나타나야 한다. 지금까지는 채널에 먼저 가입해야만 그 채널의 메시지가 검색됐기 때문에, 어느 채널에 있었는지 기억나지 않는 메시지를 찾으려면 관련 있어 보이는 공개 채널을 하나씩 열어보며 찾아야 했다.

**Why this priority**: 이 기능의 핵심 가치. 이게 없으면 나머지 두 스토리(관리자 설정, 컴플라이언스 예외)는 의미가 없다.

**Independent Test**: 관리자 설정을 켠 상태에서, 사용자가 가입하지 않은 공개 채널에 특정 키워드가 포함된 메시지를 미리 심어두고, 그 키워드로 검색했을 때 결과에 해당 메시지가 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 설정이 켜져 있고 사용자가 A팀의 멤버이며 A팀의 공개 채널 #general에는 가입하지 않은 상태, **When** #general에만 있는 메시지의 키워드로 검색, **Then** 검색 결과에 해당 메시지가 채널 정보(채널명 등)와 함께 표시된다.
2. **Given** 설정이 켜져 있고 사용자가 가입한 채널과 가입하지 않은 공개 채널 모두에 동일 키워드 메시지가 있는 상태, **When** 검색 실행, **Then** 두 채널의 메시지가 모두 결과에 포함된다.

---

### User Story 2 - 관리자의 기능 켜기/끄기 (Priority: P2)

시스템 관리자는 이 검색 확장 동작을 조직 정책에 따라 켜거나 끌 수 있어야 하며, 별도로 설정하지 않는 한 지금까지의 동작(채널 멤버십 기반 검색)이 그대로 유지되어야 한다.

**Why this priority**: 검색 접근 범위를 넓히는 기능이므로 조직마다 원하는 정책이 다를 수 있고, 기존 고객에게 예고 없이 동작이 바뀌면 안 된다.

**Independent Test**: 관리자 콘솔에서 설정을 끈 채로 배포한 뒤, 사용자가 가입하지 않은 공개 채널의 메시지를 검색했을 때 결과에 나타나지 않는지 확인한다. 이후 설정을 켜고 나서 같은 검색을 반복해 결과에 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 설정이 기본값(꺼짐)인 새 환경, **When** 사용자가 가입하지 않은 공개 채널의 메시지를 검색, **Then** 결과에 나타나지 않는다(기존 동작 유지).
2. **Given** 관리자가 설정을 켬, **When** 검색 엔진이 이미 가동 중이던 상태에서 설정을 켰을 때, **Then** 기존에 색인된 메시지들도 백그라운드 작업을 통해 점차 새 검색 범위에 포함되도록 갱신된다(즉시 전체 반영을 보장하지 않음).

---

### User Story 3 - 컴플라이언스 모드에서 자동으로 기존 동작 유지 (Priority: P3)

컴플라이언스(법적 보존/감사) 모드가 활성화된 조직에서는, 검색 확장 설정이 켜져 있더라도 시스템이 자동으로 기존의 엄격한 멤버십 기반 검색으로 되돌아가야 한다. 관리자가 별도로 신경 쓰지 않아도 컴플라이언스 요구사항이 항상 우선한다.

**Why this priority**: 법적/감사 요구사항과 충돌 가능성을 차단하는 안전장치. 핵심 가치(P1)에 곧바로 필요하지는 않지만, 컴플라이언스 조직에 배포하기 전에 반드시 보장되어야 한다.

**Independent Test**: 컴플라이언스 모드와 검색 확장 설정을 모두 켠 상태에서, 가입하지 않은 공개 채널의 메시지를 검색했을 때 결과에 나타나지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 컴플라이언스 모드가 켜져 있고 검색 확장 설정도 켜져 있음, **When** 사용자가 가입하지 않은 공개 채널의 메시지를 검색, **Then** 결과에 나타나지 않는다(멤버십 기반 검색으로 강제 전환).
2. **Given** 컴플라이언스 모드가 꺼진 상태로 되돌아감, **When** 검색 확장 설정이 여전히 켜져 있는 상태에서 같은 검색을 반복, **Then** 다시 결과에 나타난다.

---

### Edge Cases

- 비공개(private) 채널의 메시지는 설정 상태와 무관하게, 해당 채널 멤버가 아닌 사용자의 검색 결과에 **절대** 노출되어서는 안 된다.
- 사용자가 속하지 않은 팀의 채널 메시지는 설정 상태와 무관하게 노출되어서는 안 된다.
- 채널의 공개/비공개 유형이 변경되는 경우(예: 공개 → 비공개 전환), 그 채널의 기존 메시지들도 새 유형 기준으로 검색 범위가 갱신되어야 한다 — 전환 전 색인 상태가 남아 비공개 채널 메시지가 계속 노출되는 일이 없어야 한다.
- 설정을 처음 켰을 때 기존에 색인된 방대한 메시지 데이터를 일괄 갱신(백필)해야 하므로, 이 작업이 검색 엔진 성능에 과도한 부하를 주지 않도록 처리 속도가 제한되어야 하며, 백필이 끝나기 전까지는 일부 오래된 메시지가 새 검색 범위에서 누락될 수 있다.
- 검색 백엔드(Elasticsearch/OpenSearch)가 구성되지 않은 환경(기본 데이터베이스 검색)에서는 이 기능이 적용되지 않는다 — 관리자 설정 자체는 노출되지 않거나, 켜더라도 동작에 영향이 없어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 관리자가 "멤버십 없이 공개 채널 메시지 검색 허용" 설정을 관리자 콘솔에서 켜고 끌 수 있게 해야 한다. 기본값은 꺼짐(off)이며, 기존 고객 환경에는 배포 후에도 동작 변화가 없어야 한다.
- **FR-002**: 설정이 켜진 상태에서 사용자가 검색을 수행하면, 검색 결과에는 ① 사용자가 멤버인 채널의 메시지와 ② 사용자가 속한 팀 내 공개 채널(멤버가 아니더라도)의 메시지가 함께 포함되어야 한다.
- **FR-003**: 비공개 채널의 메시지는 설정 상태와 무관하게, 해당 채널 멤버가 아닌 사용자에게 검색 결과로 노출되어서는 안 된다.
- **FR-004**: 사용자가 속하지 않은 팀의 채널 메시지는 설정 상태와 무관하게 검색 결과로 노출되어서는 안 된다.
- **FR-005**: 컴플라이언스 모드가 활성화된 경우, 검색 확장 설정이 켜져 있더라도 시스템은 자동으로 기존 멤버십 기반 검색 동작으로 전환해야 하며, 관리자가 별도로 조치하지 않아도 된다.
- **FR-006**: 검색 결과에 멤버가 아닌 공개 채널의 메시지가 포함될 경우, 사용자가 그 메시지가 어느 채널의 것인지 식별할 수 있도록 채널 정보(예: 채널명)가 함께 표시되어야 한다. 단, 멤버 채널의 결과와 구분하는 별도 배지·표시는 추가하지 않고 upstream과 동일하게 일반 검색 결과와 같은 형태로 보여준다.
- **FR-007**: 관리자가 설정을 처음 켰을 때, 기존에 색인된 메시지들도 새 검색 범위 판단에 필요한 채널 유형 정보를 갖도록 백그라운드에서 일괄 갱신되어야 한다. 이 작업은 검색 엔진의 다른 요청 처리 성능에 과도한 영향을 주지 않도록 초당 10,000요청으로 처리 속도가 고정 제한되어야 하며(Elasticsearch·OpenSearch 공통, 관리자가 별도로 조정할 수 있는 옵션은 아님), upstream 참조 구현값을 그대로 따른다.
- **FR-008**: 채널의 공개/비공개 유형이 변경되면, 시스템은 해당 채널에 속한 기존 메시지들의 색인된 채널 유형 정보를 새 유형에 맞게 갱신해야 한다.
- **FR-009**: 이 기능은 검색 백엔드(Elasticsearch/OpenSearch)가 활성화된 환경에서만 적용되며, 검색 백엔드가 구성되지 않아 기본 데이터베이스 검색을 사용하는 환경의 동작에는 영향을 주지 않아야 한다. 관리자 설정 노출 여부는 새로 게이팅 로직을 만들지 않고, 기존 Elasticsearch 설정 섹션 전체가 이미 공유하는 노출 조건을 그대로 상속한다(upstream 참조 구현도 이 필드를 다른 Elasticsearch 설정과 동일한 방식으로만 다루고 별도 게이팅을 추가하지 않았음).

### Key Entities *(include if feature involves data)*

- **검색 설정(Search Configuration)**: 이 기능의 켜짐/꺼짐 여부를 나타내는 **시스템 전역 단일** 관리자 설정(팀별·역할별 세분화 없음). 컴플라이언스 설정 여부에 따라 실제 적용 여부가 재판단된다.
- **채널(Channel)**: 공개/비공개 유형을 가지며, 검색 범위 판단의 기준이 되는 유형(공개/비공개)과 소속 팀 정보를 갖는다.
- **게시물 색인(Post Index)**: 검색에 사용되는 게시물의 검색 엔진 색인 항목. 소속 채널의 유형 정보를 함께 보유해야 새 검색 범위 판단에 사용할 수 있다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 설정을 켠 팀에서, 가입하지 않은 공개 채널에 있던 메시지도 키워드 검색으로 찾을 수 있다 — 별도 안내 없이도 사용자가 공개 채널을 하나씩 열어보지 않고 검색만으로 원하는 메시지를 찾을 수 있다.
- **SC-002**: 설정이 꺼진 상태(기본값)에서는 기존 검색 결과 범위가 100% 그대로 유지된다 — 회귀가 전혀 없다.
- **SC-003**: 비공개 채널 메시지 노출 사고가 0건이어야 한다 — 이 기능으로 인해 비공개 채널이나 소속되지 않은 팀의 메시지가 검색 결과에 노출되는 사례가 검증(테스트) 단계에서 하나도 발견되지 않아야 한다.
- **SC-004**: 컴플라이언스 모드가 켜진 조직에서는 이 기능이 항상 자동으로 무력화되어, 관리자가 이 기능과 컴플라이언스 설정의 상호작용을 별도로 검토하지 않아도 안전하다.
- **SC-005**: 설정을 처음 켰을 때의 백그라운드 데이터 갱신(백필) 작업은 FR-007의 고정 처리율(초당 10,000요청, upstream 참조 구현값)로 제한되어 검색 엔진 부하를 안전한 수준으로 유지한다 — upstream도 별도 성능 벤치마크 도구 없이 이 고정값 하나로 안전을 보장했으므로, 이 문서에서도 별도 성능 측정 인프라를 새로 요구하지 않는다.

## Assumptions

- 검색 결과에서 메시지를 클릭했을 때의 후속 동작(채널 열람, 가입 유도 등)은 기존 검색 결과 클릭 동작을 그대로 따르며, 이번 기능 범위에서 새로 설계하지 않는다.
- Elasticsearch와 OpenSearch 두 백엔드 모두에서 동일한 사용자 경험을 제공한다.
