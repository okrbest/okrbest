# Quickstart: 검색 결과 RHS 팝아웃

**Feature**: [spec.md](./spec.md) | **Data Model**: [data-model.md](./data-model.md)

이 문서는 구현 완료 후 3개 사용자 스토리를 수동으로 검증하는 절차다. 구현 코드·테스트 본문은 `tasks.md`와 실제 구현 단계에서 다룬다.

## 사전 준비

```sh
cd webapp
npm run run  # 또는 기존 개발 서버 기동 절차
```

- 최소 2개 팀에 소속된 사용자 계정 1개(크로스팀 검색 시나리오용).
- 검색 가능한 메시지·파일이 있는 채널 1개, 고정된 메시지가 있는 채널 1개.
- 팝아웃은 새 브라우저 창을 여는 동작이므로, 브라우저의 팝업 차단이 꺼져 있어야 한다.

## 시나리오 1 — 검색 결과 팝아웃 (User Story 1)

1. 아무 채널에서 메시지를 검색해 RHS에 검색 결과를 띄운다(검색어 예: `QUICKSTART-SEARCH-1`).
2. RHS 헤더의 팝아웃 버튼을 클릭한다.
3. **기대 결과**: 새 창이 열리고 3초 이내(SC-001)에 동일한 검색어·동일한 결과 목록이 표시된다. 창 제목에 검색어와 서버명이 포함된다(FR-004).
4. 팝아웃 창에서 "메시지" ↔ "파일" 필터를 전환한다.
5. **기대 결과**: 필터 전환이 원래 RHS와 동일하게 동작한다(FR-005).

## 시나리오 2 — 다른 RHS 모드 팝아웃 (User Story 2)

1. "최근 멘션" RHS를 연 뒤 팝아웃한다. **기대 결과**: 새 창 제목이 "최근 멘션 - {서버명}" 형식(SC-002).
2. "저장된 메시지" RHS를 연 뒤 팝아웃한다. **기대 결과**: 새 창 제목이 "저장된 메시지 - {서버명}" 형식.
3. 특정 채널의 "고정된 메시지" RHS를 연 뒤 팝아웃한다. **기대 결과**: 새 창 제목에 채널명이 포함되고, 그 채널의 고정 메시지만 표시된다.
4. 특정 채널의 "채널 파일" RHS를 연 뒤 팝아웃한다. **기대 결과**: 새 창 제목에 채널명이 포함되고, 그 채널의 파일만 표시된다.

## 시나리오 3 — 팝아웃 창 내 상호작용 (User Story 3)

1. 시나리오 1에서 연 검색 팝아웃 창에서 검색어를 바꿔 재검색한다. **기대 결과**: 새 검색어로 결과가 갱신된다(FR-005).
2. 결과 목록을 끝까지 스크롤한다. **기대 결과**: 추가 페이지가 로드된다(FR-006).
3. 검색 결과 항목의 채널명을 클릭한다. **기대 결과**: 원래 창(부모 창)이 해당 채널로 이동한다. 팝아웃 창 자체는 검색 결과 화면을 유지한다(FR-007).
4. 검색 결과 게시물의 댓글(스레드) 아이콘을 클릭한다. **기대 결과**: 별도의 스레드 팝아웃 창이 새로 열린다 — 검색 팝아웃 창이 스레드 화면으로 바뀌지 않는다(FR-008, Edge Cases).
5. 팝아웃 창을 새로고침(F5)한다. **기대 결과**: 새로고침 직전의 검색어·필터·팀 상태가 그대로 복원된다(SC-004).

## 시나리오 4 — 크로스팀 검색 팝아웃 (Acceptance Scenario 3)

1. 크로스팀 검색이 활성화된 상태에서, 현재 팀이 아닌 다른 팀을 대상으로 검색한다.
2. 팝아웃한다.
3. **기대 결과**: 팝아웃 창도 동일한 대상 팀 컨텍스트로 검색 결과를 표시한다.

## 검증 완료 기준

위 4개 시나리오가 모두 기대 결과대로 동작하면 spec.md의 모든 User Story와 핵심 Edge Case를 충족한 것이다. 팝아웃 창에서의 댓글 열기(시나리오 3-4)는 팝아웃 창 자체의 화면을 바꾸지 않아야 한다는 점이 가장 흔히 놓치기 쉬운 검증 포인트다.
