# Feature Specification: 검색 결과 RHS 팝아웃

**Feature Branch**: `008-search-rhs-popout`

**Created**: 2026-08-10

**Status**: Draft

**Input**: upstream 커밋 [`2bd143ce`](https://github.com/mattermost/mattermost/commit/2bd143ced747794d40e17bae5654ebc837d085fa) ([MM-65630] Implement Search RHS popout, clean up and rework parts of search RHS #35499) — `/speckit-sync`가 규모(27 files, +1538/-310)와 신규 대형 기능이라는 이유로 spec 전환 대상으로 분류. 검색 결과 우측 패널(RHS)을 별도 브라우저 창으로 팝아웃할 수 있게 한다. 기존 thread popout 인프라(`rhs_popout`, `popout_windows`)를 확장하는 작업.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 검색 결과를 별도 창으로 팝아웃 (Priority: P1)

사용자가 채널/팀에서 메시지를 검색한 뒤, 검색 결과 RHS 헤더의 "새 창에서 열기" 버튼을 눌러 검색 결과를 별도 브라우저(또는 데스크톱 앱) 창으로 분리해서 볼 수 있다. 원래 창의 RHS는 그대로 유지되거나 닫히고, 팝아웃 창에는 동일한 검색어·검색 타입(메시지/파일)·팀 컨텍스트로 검색 결과가 표시된다.

**Why this priority**: 팝아웃의 핵심 가치 — 검색 결과를 메인 화면과 분리해 나란히 두고 참고하며 작업할 수 있게 하는 것. 이 시나리오 없이는 기능 자체가 성립하지 않는다.

**Independent Test**: 검색을 실행해 결과 RHS를 연 뒤 "새 창에서 열기"를 클릭한다. 별도 창이 열리고 동일한 검색 결과(같은 검색어·정렬·페이지 상태)가 나타나는지 확인해 완전히 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 특정 검색어로 메시지 검색 결과를 RHS에서 보고 있다, **When** RHS 헤더의 팝아웃 버튼을 클릭한다, **Then** 동일한 검색어·검색 타입(메시지)의 결과를 표시하는 새 창이 열린다.
2. **Given** 사용자가 파일 검색 결과를 보고 있다, **When** 팝아웃 버튼을 클릭한다, **Then** 새 창에 동일한 파일 검색 결과가 표시된다.
3. **Given** 사용자가 크로스팀 검색이 활성화된 상태로 특정 팀을 대상으로 검색했다, **When** 팝아웃한다, **Then** 팝아웃 창도 동일한 대상 팀 컨텍스트로 검색 결과를 표시한다.

---

### User Story 2 - 멘션 · 저장된 메시지 · 고정된 메시지 · 채널 파일을 팝아웃 (Priority: P2)

사용자가 "최근 멘션", "저장된 메시지", 채널의 "고정된 메시지", "채널 파일" 패널을 RHS에서 열람 중일 때도 동일하게 팝아웃할 수 있다. 각 모드는 팝아웃 창 제목에도 반영된다(예: "최근 멘션 - {서버명}", "고정된 메시지 - {채널명} - {서버명}").

**Why this priority**: 검색 결과 팝아웃과 동일한 인프라를 공유하는 RHS의 다른 진입점들이며, 사용성 일관성을 위해 필요하지만 순수 검색 시나리오(P1)보다 사용 빈도가 낮다.

**Independent Test**: 각 패널(멘션/저장됨/고정됨/채널 파일)을 열고 팝아웃 버튼을 눌러 새 창에 해당 패널이 올바른 제목과 함께 열리는지 개별적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 "최근 멘션" RHS를 보고 있다, **When** 팝아웃한다, **Then** 새 창 제목이 "최근 멘션 - {서버명}" 형식이고 동일한 멘션 목록이 표시된다.
2. **Given** 사용자가 특정 채널의 "고정된 메시지" RHS를 보고 있다, **When** 팝아웃한다, **Then** 새 창 제목에 채널명이 포함되고, 팝아웃 창에서도 해당 채널의 고정 메시지만 표시된다.

---

### User Story 3 - 팝아웃 창에서 검색 결과 상호작용 (Priority: P3)

팝아웃 창 안에서도 검색어 수정, 대상 팀 변경, 메시지/파일 필터 전환, 스크롤에 따른 추가 결과 로드(페이지네이션), 결과 게시물의 댓글(스레드) 열기 등 기존 RHS에서 가능하던 조작을 그대로 수행할 수 있다.

**Why this priority**: 팝아웃 창이 정적 스냅샷이 아니라 기존 RHS와 동등한 기능을 제공해야 실질적 가치가 있으나, 팝아웃을 "여는" 행위(P1) 자체보다는 부차적이다.

**Independent Test**: 팝아웃 창에서 검색어를 바꿔 재검색하고, 스크롤로 다음 페이지를 로드해 독립적으로 검증할 수 있다.

---

### Edge Cases

- 팝아웃 창을 연 뒤 원래 창(부모 창)이 닫히거나 새로고침되면 팝아웃 창은 어떻게 동작하는가? (기존 팝아웃 인프라의 부모-자식 연결 해제 처리를 따른다.)
- 검색 결과가 없는 상태(빈 결과)에서 팝아웃하면 팝아웃 창에도 동일한 "결과 없음" 상태가 표시되어야 한다.
- 팝아웃 창에서 검색 결과의 게시물을 클릭해 댓글(스레드)을 열면, 현재 창이 이동하는 대신 스레드 팝아웃(`/_popout/thread/...`)이 별도로 열려야 한다 — 팝아웃 창 자체를 검색 결과가 아닌 다른 화면으로 바꾸지 않는다.
- 사용자가 속하지 않은 팀·채널 컨텍스트로 팝아웃 URL을 직접 조작해 접근을 시도하면 어떻게 되는가? (기존 서버 권한 체계에 따라 결과가 제한되어야 한다.)
- 데스크톱 앱과 브라우저 탭 각각에서 팝아웃 동작(창 관리 방식)이 다를 수 있다 — 기존 `popout_windows` 유틸의 데스크톱/브라우저 분기를 따른다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 검색 결과 RHS 헤더에는 현재 검색 결과(메시지/파일)를 별도 창으로 여는 조작 지점이 있어야 한다.
- **FR-002**: 팝아웃 창은 원래 RHS와 동일한 검색어, 검색 타입(메시지/파일), 대상 팀(크로스팀 검색 시)으로 검색 결과를 재현해야 한다.
- **FR-003**: 시스템은 "최근 멘션", "저장된 메시지", "고정된 메시지"(채널별), "채널 파일" 각 RHS 모드에 대해서도 동일한 팝아웃 조작을 지원해야 한다.
- **FR-004**: 팝아웃 창 제목은 모드에 따라 서버명·채널명·검색어 중 관련 정보를 포함해 사용자가 여러 팝아웃 창을 구분할 수 있어야 한다.
- **FR-005**: 팝아웃 창 안에서 검색어 변경, 대상 팀 변경, 메시지/파일 필터 전환이 가능해야 하며 그 결과가 팝아웃 창의 URL 상태에 반영되어야 한다(새로고침 후에도 동일 검색 상태 복원).
- **FR-006**: 팝아웃 창에서 스크롤 시 추가 검색 결과(메시지/파일)를 로드할 수 있어야 한다(기존 RHS의 페이지네이션 동작과 동일).
- ~~**FR-007**: 팝아웃 창에서 검색 결과의 채널명을 클릭하면 원래 창이 해당 채널로 이동해야 한다.~~ — **철회(2026-08-10)**: upstream이 구현 다음날 이 기능 자체를 되돌렸다(`a744a758`, "Fix an E2E test broken in #35499"). 이후 upstream-master 최신 상태까지도 재도입되지 않아 upstream의 최종 설계로 판단, 우리 fork도 동일하게 되돌렸다(채널명은 클릭 불가능한 일반 텍스트). 자세한 내용은 `/speckit-sync` 세션(2026-08-10, sync/upstream-20260810)의 `a744a758` 처리 기록 참고.
- **FR-008**: 팝아웃 창에서 검색 결과 게시물의 댓글을 열면 별도의 스레드 팝아웃 창이 열려야 하며, 팝아웃 창 자체의 화면 전환으로 처리되어서는 안 된다.
- **FR-009**: 팝아웃 기능은 기존 팝아웃 인프라(팝아웃 창 생성·부모-자식 통신·데스크톱 앱 연동)를 재사용해야 하며, 새로운 별도의 창 관리 체계를 도입하지 않는다.

### Key Entities

- **검색 팝아웃 쿼리 상태**: 팝아웃 창의 URL에 인코딩되는 검색 컨텍스트 — 검색어, 검색 타입, RHS 모드(검색/멘션/저장됨/고정됨/채널파일), 채널 식별자, 대상 팀 ID.
- **RHS 모드**: 팝아웃 가능한 RHS 화면 종류(검색 결과, 최근 멘션, 저장된 메시지, 고정된 메시지, 채널 파일) — 각각 팝아웃 시 별도 제목 포맷을 가짐.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 검색 결과 RHS를 보고 있는 사용자가 팝아웃 버튼 클릭 한 번으로 3초 이내에 동일한 검색 결과가 표시된 새 창을 얻을 수 있다.
- **SC-002**: 지원되는 5가지 RHS 모드(검색/멘션/저장됨/고정됨/채널파일) 각각에서 팝아웃 후 원래 화면과 100% 동일한 결과 목록이 재현된다.
- **SC-003**: 팝아웃 창에서의 검색어 변경·필터 전환·추가 로드·댓글 열기 조작이 기존 RHS와 동일하게 동작해, 사용자가 팝아웃 여부와 무관하게 동일한 작업을 완료할 수 있다.
- **SC-004**: 팝아웃 창을 새로고침해도 직전 검색 상태(검색어·타입·팀)가 100% 복원된다.

## Assumptions

- 팝아웃 창 인프라(창 생성, 부모-자식 메시지 통신, 데스크톱 앱 API 연동)는 기존에 반영된 thread popout·RHS 플러그인 팝아웃 기능(`rhs_popout`, `thread_popout`, `popout_windows`, `use_browser_popout`)을 그대로 재사용하며, 이 spec의 범위는 검색 RHS에 팝아웃 진입점과 검색 전용 팝아웃 화면(`rhs_search_popout`)을 추가하는 것으로 한정한다.
- 서버 측 검색 권한·접근 제어는 기존 로직을 그대로 따르며 이 기능으로 인해 변경되지 않는다(팝아웃은 클라이언트 측 창 분리 기능일 뿐 검색 API 동작을 바꾸지 않음).
- 최근 반영한 자체 기능인 "공개 채널 멤버십 없이 검색 허용"(specs/007-public-channel-search-access)과는 별개 관심사이며, 이 기능은 그 검색 접근 범위 확장 결과를 팝아웃 창에서도 동일하게 노출하기만 하면 된다 — 검색 접근 로직 자체를 재구현하지 않는다.
- i18n: 이 기능은 `/speckit-sync`의 cherry-pick/adapt가 아니라 spec 파이프라인으로 별도 개발되는 신규 기능이므로, 신규 문자열(`rhs_search_popout.title.*` 등)은 constitution 원칙 V(en/ko 동시 갱신)를 그대로 따른다 — 영문은 upstream 원문을 채택하고, 한국어는 이 기능 구현 시 함께 번역해 커밋한다.
