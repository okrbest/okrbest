## 검증 기록

**1차 (2026-09-03)** — 아래 3건을 고쳐 통과.

1. **성공 기준에 기술 용어가 샜다**: 초안의 "CSS transform 적용 시 프레임 드랍 없음"을 SC-006 "화면 갱신이 끊겨 보이지 않는다"로 바꿨다. 구현 방식을 성공 기준이 앞질러 정하고 있었다.
2. **드래그와 클릭 구분이 경계 상황에만 있었다**: 요구사항으로 올려 FR-005로 명시했다. 이 구분이 빠지면 기존 배경 클릭 닫기(FR-021)와 정면으로 부딪히므로 검증 대상이어야 한다.
3. **PDF 처리가 비어 있었다**: 확대 컨트롤을 PDF와 공유하므로 "PDF에서 `+`를 누르면?"에 답이 있어야 한다. Assumptions와 범위 밖에 이미지·SVG 한정을 못 박고, 경계 상황에도 적었다.

**남은 판단 대기 항목** — 명세를 막지는 않으나 plan에서 정한다.

- 배율 상한·하한 값: 현재 값을 이어받는 것으로 가정했다. 바꾸려면 화면으로 확인하고 정한다.
- 구현 모델(현재의 실제 크기 변경 + 스크롤 유지 vs upstream의 표시 변형 + 넘침 잘라내기): plan의 선행 결정 사항이다. 이 명세는 어느 쪽을 택하든 성립한다.

**2차 (2026-09-03, `/speckit-analyze` 후)** — 지적 10건 중 명세에 걸린 3건을 고쳤다.

1. **FR-006이 고른 모델에서 공허했다**: "전환 효과를 적용하지 않아야 한다"는 upstream의 transform 모델 전제로 쓴 문장인데, 우리는 스크롤 방식을 택했고 두 SCSS 어디에도 `transition`이 없다(실물 확인). 억제할 대상이 없어 검증 불가능한 요구였다. "이동 중 이미지가 커서를 지연 없이 따라와야 한다"로 다시 썼다 — 의도는 같고 어느 모델에서든 잰다.
2. **SC-006에 수치가 없었다**: "눈에 띄는 멈춤 없음"은 사람마다 다르게 읽는다. "프레임 시간 50ms 초과 0회"로 바꿔 성능 기록으로 판정하게 했다.
3. **SC-007은 만들 수 있는 기준이 아니었다**: 처음 보는 사용자 90% 성공률은 사용자 조사가 있어야 재는 값이다. 구현 완료 판정에 넣으면 `미측정`으로 빠져나가는 칸이 된다. `OBS-001`로 이름을 바꿔 "출시 후 관찰" 절로 옮겼다.
4. **경계 상황 하나가 양자택일로 남아 있었다**: 다운로드 불가 상태를 "노출되지 않거나, 노출된다면"으로 열어 뒀는데 계약은 이미 확정돼 있었다. "조작 수단이 노출되지 않는다"로 못박았다.

**해소한 판단 대기 항목** — 구현 모델을 plan에서 결정했다: 현재의 스크롤 방식 유지 ([plan.md](../plan.md), [research.md](../research.md) 결정 1). 배율 상한·하한은 현행 유지로 확정했다 ([research.md](../research.md) 사실 7).
