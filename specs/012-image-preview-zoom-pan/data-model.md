# Phase 1 데이터 모델: 이미지 프리뷰 확대·이동 조작 확장

**대상 명세**: [spec.md](./spec.md) | **조사**: [research.md](./research.md)

여기서 말하는 "데이터"는 저장소에 남는 것이 아니라 모달이 열려 있는 동안 들고 있는 화면 상태다. 명세의 Key Entities를 구현 가능한 형태로 옮긴다.

## 상태가 어디에 사는가

| 상태 | 위치 | 수명 |
|---|---|---|
| 배율, 맞춤 배율, 이동 위치, 파일 식별자 | `FilePreviewModal`의 컴포넌트 상태 | 모달이 열려 있는 동안 |
| 끌기 진행 상황 | `ImagePreview`의 ref (상태 아님) | 버튼을 누른 동안 |
| 실제 스크롤 위치 | 감싸는 `<div>`의 DOM 속성 | 렌더마다 상태에서 복원 |

끌기 진행 상황을 상태로 두지 않는 이유는 마우스가 움직일 때마다 재렌더가 일어나기 때문이다(research.md 결정 1).

## 기존 상태 — 유지

### 배율 `scale: Record<number, number>`

파일 자리(index)마다 표시 배율을 들고 있다.

- 기준값 `ZoomSettings.DEFAULT_SCALE = 1.75`
- 범위 `[MIN_SCALE 0.25, MAX_SCALE 3.0]`
- 실제 확대 비율은 `scale / DEFAULT_SCALE`
- 이미지와 PDF가 같은 기록을 공유한다 (research.md 사실 4)

### 맞춤 배율 `fitScale: Record<number, number>`

이미지가 화면에 전부 들어오는 배율. 리셋의 목적지다.

- 이미지 로드 시 `DEFAULT_SCALE × min(컨테이너너비/원본너비, 컨테이너높이/원본높이, 1)`로 계산
- `min(..., 1)` 때문에 원본이 컨테이너보다 작으면 맞춤 배율은 기준값과 같다 — 작은 이미지를 억지로 늘리지 않는다

## 새로 더하는 상태

### 이동 위치 `panOffset: Record<number, {x: number; y: number}>`

파일 자리마다 스크롤 오프셋을 들고 있다. FR-017이 요구한다.

- 초기값 `{x: 0, y: 0}`
- 단위는 픽셀, 감싸는 요소의 `scrollLeft`/`scrollTop`에 대응
- 유효 범위는 배율에 따라 달라진다: `x ∈ [0, max(0, 원본너비 × 배율비 − 컨테이너너비)]`, `y`도 같은 꼴
- 배율이 바뀌면 범위가 바뀌므로 매번 잘라 준다

**왜 상태로 올리나**: 스크롤 위치는 DOM 노드에 있는데 파일을 넘겨도 같은 노드다. 지금은 파일 전환 때 0으로 초기화돼 파일별 위치가 남지 않는다 (research.md 사실 5).

### 파일 식별자 `fileIdentities: string[]`

각 자리에 어떤 파일이 있었는지 기억한다. FR-018이 요구한다.

- 만드는 규칙: 파일 id가 있으면 `id:<파일 id>`, 없으면(외부 링크) `link:<링크>`
- 접두사를 붙이는 이유는 id와 링크가 우연히 같은 문자열이어도 섞이지 않게 하려는 것이다
- `getDerivedStateFromProps`에서 자리마다 비교해, 달라진 자리만 배율·맞춤 배율·이동 위치를 초기화한다

**왜 필요한가**: 지금은 파일 개수 변화만 본다. 메시지 수정으로 같은 자리의 첨부가 바뀌면 개수가 그대로라 이전 파일의 배율이 새 파일에 남는다 (research.md 사실 6).

### 끌기 진행 상황 (ref, 상태 아님)

```
{
  active: boolean          // 버튼을 누르고 있나
  startX, startY: number   // 누른 지점의 화면 좌표
  startScrollLeft/Top      // 누른 순간의 스크롤 위치
  moved: boolean           // 임계값 5px을 넘었나
}
```

- `moved`가 참이면 뒤따르는 `click`을 무시한다 (research.md 결정 3)
- `mouseup` 뒤에도 `click` 처리가 끝날 때까지 `moved`를 유지해야 한다

## 상태 전이

### 이미지 로드

```
이미지 로드 완료
  → 원본 크기 기록
  → 맞춤 배율 계산
  → 현재 배율이 기준값 그대로면 맞춤 배율로 교체
  → 이동 위치 {0, 0}
```

현재 배율이 기준값에서 이미 벗어나 있으면(사용자가 조작했으면) 덮어쓰지 않는다.

### 확대·축소 (버튼·키보드)

```
배율 변경 요청
  → 새 배율 = 잘라내기(현재 배율 ± 0.25, [0.25, 3.0])
  → 이동 위치를 새 배율의 유효 범위로 잘라내기
```

### 확대·축소 (휠)

```
휠 입력 (deltaY ≠ 0)
  → 변화 폭 = 0.25 × 세기 비례 계수
  → 새 배율 = 잘라내기(현재 배율 ∓ 변화 폭, [0.25, 3.0])
  → 새 이동 위치 = 커서 기준 식 (research.md 결정 2)
  → 잘라내기
```

### 끌기

```
mousedown (왼쪽 버튼, 배율 > 맞춤 배율)
  → 시작 좌표·스크롤 기록, active = true

mousemove (active)
  → 이동 거리 > 5px 이면 moved = true
  → 새 스크롤 = 시작 스크롤 − (현재 좌표 − 시작 좌표)
  → DOM에 직접 적용 (재렌더 없음)

mouseup
  → active = false
  → 최종 스크롤을 panOffset 상태에 반영

click (moved 이면)
  → 무시, moved 되돌리기
```

배율이 맞춤 배율 이하면 `mousedown`에서 아무것도 시작하지 않는다 (FR-002).

### 리셋

```
리셋 요청
  → 배율 = 맞춤 배율
  → 이동 위치 = {0, 0}
```

### 파일 전환·교체

```
props.fileInfos 변경
  → 자리마다 파일 식별자 비교
  → 달라진 자리: 배율·맞춤 배율·이동 위치 초기화
  → 같은 자리: 그대로 둔다
```

## 불변 조건

명세의 요구를 상태 수준의 규칙으로 옮긴 것이다. 테스트가 이 조건을 직접 확인한다.

1. 배율은 항상 `[MIN_SCALE, MAX_SCALE]` 안에 있다. (FR-015)
2. 이동 위치는 항상 현재 배율의 유효 범위 안에 있다. 배율을 줄여 이미지가 화면에 다 들어오면 `{0, 0}`이 된다. (FR-016)
3. 배율이 맞춤 배율 이하면 이동 위치는 `{0, 0}`이다. (FR-002, FR-016)
4. 어떤 자리의 파일 식별자가 그대로면 그 자리의 배율·이동 위치는 다른 자리의 변경에 영향받지 않는다. (FR-017, FR-018)
5. `moved`가 참인 동안 배경 클릭 닫기가 일어나지 않는다. (FR-005)
