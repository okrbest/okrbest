# Phase 1 검증 가이드: 이미지 프리뷰 확대·이동 조작 확장

**대상 명세**: [spec.md](./spec.md) | **계약**: [contracts/component-contracts.md](./contracts/component-contracts.md)

구현이 끝났는지 판정하는 절차다. 자동 검증(게이트·테스트)과 실주행 확인으로 나뉜다.

## 사전 준비

```bash
node --version    # v24.11.x 여야 한다 (.nvmrc = 24.11)
```

Node 버전이 다르면 webapp 테스트가 로드 단계에서 실패한다. `nvm use`로 맞춘다.

## 자동 검증

### 1. 접촉 패키지 테스트

```bash
cd webapp/channels
npm run test -- src/components/file_preview_modal
```

**기대**: 전부 통과. 스냅샷은 감싸는 요소를 `<div class="image_preview">`로 유지하는 한 갱신이 필요 없다(계약 문서의 마크업 계약). 스냅샷이 깨지면 마크업 계약을 어긴 것이니 갱신하기 전에 왜 바뀌었는지부터 확인한다.

### 2. 품질 게이트 (constitution 원칙 I)

```bash
cd webapp
npm run check          # eslint + stylelint
npm run check-types    # tsc -b
```

**기대**: 둘 다 통과. `check-types`는 전체 빌드라 시간이 걸린다.

### 3. 새 동작의 단위 테스트

구현과 함께 들어와야 하는 테스트다. 각 항목은 **구현 전에 실패하는 것을 먼저 확인**한다 (constitution 원칙 III — 실패를 못 본 테스트는 인정하지 않는다).

| 대상 | 확인할 것 | 관련 |
|---|---|---|
| 끌기 게이트 | 맞춤 배율에서 `mousedown` → 이동 시작 안 함 / 확대 상태에서 → 시작함 | FR-002 |
| 버튼 구분 | 오른쪽·가운데 버튼 `mousedown` → 이동 시작 안 함 | FR-003 |
| 끌기·클릭 구분 | 5px 넘게 움직인 뒤 `click` → 닫기 호출 안 됨 / 2px만 움직이면 → 닫기 호출됨 | FR-005, FR-021 |
| 휠 경계 | 상한에서 더 확대 → 상한 유지 / 하한에서 더 축소 → 하한 유지 | FR-015 |
| 휠 무시 | `deltaY = 0` → 아무 일 없음 | FR-011 |
| 휠 세기 | 큰 `deltaY`가 작은 `deltaY`보다 배율을 더 바꿈 | FR-009 |
| 커서 기준점 | 주어진 커서 위치·배율 변화에 대해 계산된 스크롤 목표값이 식과 일치 | FR-008 |
| 키보드 | `+`/`=`/`-`/`0` 각각 대응 동작 | FR-012 |
| 키보드 차단 | `INPUT` 포커스 중 → 배율 안 바뀜 / 조합키와 함께 → 안 바뀜 | FR-013, FR-014 |
| 키보드 파일 형식 | PDF를 보는 중 `+` → 배율 안 바뀜 | 범위 밖 명시 |
| 파일 식별자 | 개수 같고 내용만 바뀐 교체 → 그 자리만 초기화, 다른 자리 유지 | FR-018 |
| 이동 위치 유지 | 파일 A를 이동해 두고 B로 갔다 돌아오면 A의 위치 복원 | FR-017 |
| 리셋 | 확대·이동 후 리셋 → 맞춤 배율 + `{0,0}` | FR-016, FR-020 |

## 실주행 확인

`npm run run` 또는 개발 서버로 앱을 띄우고 채널에 이미지를 올려 확인한다. 자동 테스트로 못 잡는 것만 적는다.

### 시나리오 1 — 끌어서 본다 (US1)

1. 큰 이미지(가로 3000px 이상)를 채널에 올리고 클릭해 프리뷰를 연다.
2. **확인**: 이미지가 화면에 맞게 줄어 열린다. (FR-019)
3. `+`를 두어 번 눌러 확대한다.
4. 이미지를 잡아끈다. **확인**: 커서를 따라 움직이고, 커서에서 밀리지 않는다. (FR-001, FR-006)
5. 끄는 중 커서를 이미지 밖 배경으로 빼고 버튼을 뗀다. **확인**: 모달이 닫히지 않는다. (FR-005) ← 가장 중요한 확인
6. 배경을 그냥 한 번 클릭한다. **확인**: 모달이 닫힌다. (FR-021)

### 시나리오 2 — 커서 기준 확대 (US2)

1. 도표나 글자가 있는 이미지를 연다.
2. 이미지의 오른쪽 아래 구석에 커서를 두고 휠을 위로 굴린다.
3. **확인**: 그 구석이 화면상 거의 같은 자리에 남는다. 중앙 기준으로 커져 화면 밖으로 밀리면 실패다. (FR-008, SC-002)
4. 휠을 계속 굴려 상한까지 간다. **확인**: 상한에서 멈추고 화면이 흔들리지 않는다.
5. 휠을 굴리는 동안 뒤쪽 채널 목록을 본다. **확인**: 함께 스크롤되지 않는다. (FR-010)
6. 트랙패드가 있으면 핀치로 확대해 본다. **확인**: 크게 벌릴수록 많이 확대된다. (FR-009)

### 시나리오 3 — 키보드 (US3)

1. 프리뷰를 열고 `+`, `-`, `0`을 차례로 누른다. **확인**: 버튼과 같게 동작한다.
2. `0`을 누른다. **확인**: 맞춤 배율로 돌아가고 이동 위치도 처음으로 간다. (FR-016)
3. `Ctrl`(맥은 `Cmd`)을 누른 채 `+`를 누른다. **확인**: 이미지 배율은 그대로다. (FR-014)
4. PDF를 열고 `+`를 누른다. **확인**: 배율이 바뀌지 않는다. (범위 밖)

### 시나리오 4 — 파일별 상태 (US1 연장)

1. 이미지 3개가 붙은 메시지를 올린다.
2. 첫 번째를 확대하고 왼쪽 위로 이동해 둔다.
3. 두 번째로 넘어가 다른 배율로 확대한다.
4. 첫 번째로 돌아온다. **확인**: 배율과 이동 위치가 그대로다. (FR-017, SC-005)

### 시나리오 5 — 첨부 교체 (FR-018)

우리 코드의 잠복 버그를 고쳤는지 보는 확인이다 (research.md 사실 6).

1. 이미지 1개가 붙은 메시지를 올리고 프리뷰에서 크게 확대한다.
2. 프리뷰를 닫고 그 메시지를 수정해 첨부를 **다른 이미지 1개로 교체**한다(개수는 그대로).
3. 다시 프리뷰를 연다. **확인**: 새 이미지가 맞춤 배율로 열린다. 이전 이미지의 확대 배율이 남아 있으면 실패다.

### 시나리오 6 — 경계

- 아주 작은 이미지(100×100)를 연다. **확인**: 억지로 늘어나지 않는다.
- SVG를 연다. **확인**: 다른 이미지와 같게 확대·이동된다.
- 외부 링크 이미지를 연다. **확인**: 같게 동작한다.

### 시나리오 7 — 부드러움 (SC-006)

1. 큰 이미지를 열고 휠을 3초 동안 연속으로 굴린다. **확인**: 눈에 띄는 멈춤이 없다.
2. 확대 상태에서 3초 동안 계속 끈다. **확인**: 커서를 따라오며 끊기지 않는다.

멈춤이 보이면 research.md 결정 2의 "되읽기 회피"가 지켜지지 않았을 가능성이 높다. 브라우저 개발자 도구의 성능 탭에서 강제 동기 레이아웃(forced reflow) 경고를 확인한다.
