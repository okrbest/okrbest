# Feature Specification: 이미지 프리뷰 확대·이동 조작 확장

**Feature Branch**: `012-image-preview-zoom-pan`

**Created**: 2026-09-03

**Status**: Draft

**Input**: upstream mattermost `aa03fae7`(MM-69026, "Add zoom and pan to the image file preview", #36775) 선별 반영 과정에서 spec으로 전환. ledger 항목은 `docs/upstream-master-unmerged-commits.md`의 `aa03fae7` 행.

## 배경

okrbest는 이미지 프리뷰 확대를 자체 구현해 두었다. 커밋 `136b14d77b`("채널 이미지 확대 축소", 2026-01-08)가 확대·축소를, `86e424498e`("채널 이미지 외부 클릭시 프리뷰 창 닫힘")가 배경 클릭 닫기를 넣었다.

지금 사용자가 할 수 있는 일:

- 파일 프리뷰 모달에서 이미지·SVG를 열면 확대 컨트롤(+, −, 리셋)이 나온다.
- 큰 이미지는 열릴 때 화면에 맞게 줄어든다. 리셋 버튼은 원본 크기가 아니라 이 "맞춤 배율"로 되돌린다.
- 확대하면 이미지가 실제로 커지고, 넘치는 부분은 스크롤바로 본다.
- 이미지 바깥 배경을 클릭하면 모달이 닫힌다.

upstream은 같은 기능을 다른 방식으로 만들면서 조작 수단 셋을 더 넣었다. 우리에게 없는 셋이 이번 작업의 대상이다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 확대한 이미지를 끌어서 본다 (Priority: P1)

사용자가 채널에 올라온 스크린샷을 열고 왼쪽 아래 글자를 읽으려 확대한다. 지금은 스크롤바를 찾아 가로·세로를 따로 움직여야 한다. 이미지를 직접 잡아끌어 원하는 곳으로 옮길 수 있어야 한다.

**Why this priority**: 확대의 목적은 특정 부분을 보는 것이다. 확대해 놓고 그 부분으로 못 가면 확대 자체가 반쪽이다. 셋 중 사용 빈도와 답답함이 가장 크다.

**Independent Test**: 이미지를 확대한 뒤 커서로 끌어 화면 밖에 있던 영역을 화면 안으로 가져온다. 다른 둘(휠·키보드) 없이도 완결된 개선이다.

**Acceptance Scenarios**:

1. **Given** 이미지를 맞춤 배율보다 크게 확대한 상태, **When** 이미지 위에서 마우스 왼쪽 버튼을 누른 채 끌면, **Then** 이미지가 커서를 따라 움직이고 가려져 있던 영역이 드러난다.
2. **Given** 이미지가 맞춤 배율이라 화면에 다 들어오는 상태, **When** 이미지를 끌면, **Then** 이미지는 움직이지 않는다.
3. **Given** 이미지를 확대해 끄는 중, **When** 배경 위에서 버튼을 떼면, **Then** 모달이 닫히지 않고 이동 결과가 유지된다.
4. **Given** 이미지를 확대해 이동해 둔 상태, **When** 리셋을 실행하면, **Then** 배율이 맞춤 배율로 돌아가고 이미지 위치도 처음으로 돌아온다.
5. **Given** 이미지를 확대해 이동해 둔 상태, **When** 다음 파일로 넘어갔다 돌아오면, **Then** 이전 파일의 이동 위치가 새 파일에 적용되지 않는다.

---

### User Story 2 - 커서가 가리키는 곳을 기준으로 확대한다 (Priority: P2)

사용자가 도표 이미지의 오른쪽 구석 수치를 보려 한다. 그 지점에 커서를 두고 휠을 굴리면 그 지점이 제자리에 머문 채 주변이 커져야 한다. 화면 중앙 기준으로 커지면 보려던 곳이 화면 밖으로 밀려나 다시 끌어와야 한다.

**Why this priority**: 확대와 이동을 한 동작으로 합쳐 준다. P1이 있어야 의미가 살아나므로 그다음이다.

**Independent Test**: 이미지의 특정 지점에 커서를 두고 휠을 굴려, 그 지점이 화면상 같은 자리에 남는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이미지 프리뷰가 열린 상태, **When** 이미지 위에서 휠을 위로 굴리면, **Then** 확대되고 커서가 가리키던 지점이 화면상 같은 위치에 남는다.
2. **Given** 이미지 프리뷰가 열린 상태, **When** 휠을 아래로 굴리면, **Then** 축소되고 같은 기준점 규칙이 적용된다.
3. **Given** 이미지 프리뷰가 열린 상태, **When** 이미지 위에서 휠을 굴리면, **Then** 뒤쪽 채널 목록이나 페이지가 함께 스크롤되지 않는다.
4. **Given** 트랙패드로 핀치하는 상태, **When** 크게 벌리면, **Then** 작게 벌릴 때보다 배율이 더 많이 변한다.
5. **Given** 이미지가 확대 상한에 도달한 상태, **When** 계속 확대하면, **Then** 상한에서 멈추고 화면이 흔들리지 않는다.

---

### User Story 3 - 키보드로 확대·축소한다 (Priority: P3)

마우스에서 손을 떼지 않고도, 혹은 휠이 없는 환경에서도 배율을 바꾸고 싶다. `+`/`=`로 확대, `-`로 축소, `0`으로 리셋한다.

**Why this priority**: 편의 개선이다. 버튼이라는 기존 수단이 이미 있어 없다고 막히지는 않는다.

**Independent Test**: 프리뷰를 열고 `+`, `-`, `0`을 눌러 배율이 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이미지 프리뷰가 열린 상태, **When** `+` 또는 `=`를 누르면, **Then** 확대 버튼을 누른 것과 같게 확대된다.
2. **Given** 이미지 프리뷰가 열린 상태, **When** `-`를 누르면, **Then** 축소된다.
3. **Given** 이미지를 확대·이동해 둔 상태, **When** `0`을 누르면, **Then** 맞춤 배율과 처음 위치로 돌아간다.
4. **Given** 프리뷰 안의 입력 칸(댓글 입력 등)에 커서가 있는 상태, **When** `-`를 입력하면, **Then** 배율은 그대로고 글자가 입력된다.
5. **Given** 이미지 프리뷰가 열린 상태, **When** `Ctrl`/`Cmd`와 함께 `+`를 누르면, **Then** 이미지 배율은 바뀌지 않는다(브라우저 확대에 맡긴다).

---

### Edge Cases

- 이미지를 끌다가 커서가 프리뷰 영역 밖으로 나간 뒤 버튼을 뗀다 → 이동이 그 지점에서 끝나고, 다음에 눌렀을 때 이미지가 튀지 않는다.
- 끌지 않고 배경을 한 번 클릭한다 → 기존대로 모달이 닫힌다. 이동과 클릭을 구분해야 한다.
- 축소 하한까지 줄인 뒤 더 축소를 시도한다 → 하한에서 멈춘다.
- 이미지가 아직 로드되지 않아 크기를 모른다 → 확대·이동 조작이 오류 없이 무시된다.
- 다운로드 권한이 없어 축소판만 보이는 경우 → 조작 수단이 노출되지 않거나, 노출된다면 동일하게 동작한다.
- 같은 자리의 파일이 교체된다(메시지 수정으로 첨부가 바뀌는 경우) → 이전 파일의 배율·위치가 새 파일에 남지 않는다.
- SVG처럼 고유 크기 규칙이 다른 이미지 → 맞춤 배율과 확대·이동이 다른 이미지와 같게 동작한다.
- 외부 링크로 들어온 이미지 → 서버에 저장된 이미지와 같게 동작한다.
- PDF를 보는 중 `+`를 누른다 → 이번 범위 밖이다. 아래 Assumptions 참조.

## Requirements *(mandatory)*

### Functional Requirements

**드래그 이동**

- **FR-001**: 이미지가 맞춤 배율보다 크게 확대된 상태에서, 사용자는 마우스 왼쪽 버튼으로 이미지를 끌어 표시 위치를 옮길 수 있어야 한다.
- **FR-002**: 이미지가 맞춤 배율이어서 화면에 전부 들어오는 상태에서는 끌어도 위치가 바뀌지 않아야 한다.
- **FR-003**: 마우스 왼쪽 버튼이 아닌 입력으로는 이동이 시작되지 않아야 한다.
- **FR-004**: 이동 중에는 커서가 이미지를 잡고 있음을 나타내는 모양으로 바뀌어야 한다.
- **FR-005**: 이동 동작과 배경 클릭을 구분해, 이동을 끝내며 버튼을 뗀 것이 모달 닫기로 이어지지 않아야 한다.
- **FR-006**: 이동 중에는 배율 변화에 걸리는 부드러운 전환 효과를 적용하지 않아, 이미지가 커서에서 밀리지 않아야 한다.

**휠 확대·축소**

- **FR-007**: 사용자는 이미지 위에서 휠을 굴려 확대·축소할 수 있어야 한다.
- **FR-008**: 휠 확대·축소는 커서가 가리키는 지점을 기준으로 삼아, 그 지점이 화면상 같은 위치에 남아야 한다.
- **FR-009**: 배율 변화 폭은 휠 입력의 세기에 비례해야 한다(트랙패드 핀치 대응).
- **FR-010**: 이미지 위에서 휠을 굴릴 때 프리뷰 뒤쪽 화면이 스크롤되지 않아야 한다.
- **FR-011**: 휠 입력의 변화량이 0이면 아무 일도 일어나지 않아야 한다.

**키보드**

- **FR-012**: 프리뷰가 열려 있을 때 `+` 또는 `=`는 확대, `-`는 축소, `0`은 리셋으로 동작해야 한다.
- **FR-013**: 입력 칸(한 줄 입력, 여러 줄 입력, 편집 가능 영역)에 포커스가 있으면 위 키가 배율을 바꾸지 않아야 한다.
- **FR-014**: `Ctrl`·`Cmd`·`Alt` 같은 조합키와 함께 눌린 입력은 배율을 바꾸지 않아야 한다.

**배율 경계와 상태**

- **FR-015**: 배율에는 상한과 하한이 있어야 하며, 경계에 닿으면 그 값에서 멈춰야 한다.
- **FR-016**: 이미지가 맞춤 배율로 돌아가면 이동 위치도 처음으로 돌아와야 한다.
- **FR-017**: 배율과 이동 위치는 파일별로 따로 유지되어야 하며, 파일을 넘겨도 서로 섞이지 않아야 한다.
- **FR-018**: 같은 자리의 파일이 다른 파일로 바뀌면 그 자리의 배율과 이동 위치를 초기화해야 하고, 바뀌지 않은 자리의 상태는 유지해야 한다.

**기존 동작 보존**

- **FR-019**: 큰 이미지가 열릴 때 화면에 맞게 줄어드는 동작을 유지해야 한다.
- **FR-020**: 리셋은 원본 크기가 아니라 맞춤 배율로 되돌려야 한다.
- **FR-021**: 이미지 바깥 배경을 클릭하면 모달이 닫히는 동작을 유지해야 한다.
- **FR-022**: 확대 컨트롤(+, −, 리셋 버튼)은 지금처럼 이미지·SVG에서 계속 보여야 하며, 버튼만으로도 기존과 같이 조작할 수 있어야 한다.

### Key Entities

- **프리뷰 배율(scale)**: 파일별로 유지되는 표시 배율. 맞춤 배율을 기준점으로 삼고 상한·하한을 가진다.
- **맞춤 배율(fit scale)**: 이미지가 화면에 전부 들어오는 배율. 로드 시 계산하며 리셋의 목적지다.
- **이동 위치(translate)**: 파일별로 유지되는 이미지의 표시 위치 오프셋. 맞춤 배율에서는 항상 처음 위치다.
- **파일 식별자**: 같은 자리의 파일이 바뀐 것을 알아보는 근거. 배율·위치 초기화 판단에 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 확대한 이미지에서 화면 밖에 있던 임의 지점을 화면 중앙으로 가져오는 데 걸리는 조작이 끌기 1회로 끝난다(현재는 가로·세로 스크롤 2회 이상).
- **SC-002**: 휠로 확대·축소한 뒤, 커서가 가리키던 지점이 화면상 원래 위치에서 이미지 짧은 변의 2% 이내에 남는다.
- **SC-003**: 이미지를 끌어 이동한 뒤 버튼을 떼는 조작에서 모달이 닫히는 경우가 0%다(끝나는 지점이 이미지 위든 배경 위든).
- **SC-004**: 기존 동작 3종(열 때 맞춤 축소, 리셋의 맞춤 배율 복귀, 배경 클릭 닫기)에 회귀가 0건이다.
- **SC-005**: 파일 5개가 붙은 메시지에서 각 파일을 서로 다른 배율·위치로 둔 뒤 앞뒤로 넘겨도, 각 파일이 자기 배율·위치로 복원되는 비율이 100%다.
- **SC-006**: 끌기와 휠 조작 중 화면 갱신이 끊겨 보이지 않는다(연속 조작 3초 동안 눈에 띄는 멈춤 없음).
- **SC-007**: 확대 컨트롤을 처음 보는 사용자가 안내 없이 확대한 이미지의 특정 부분을 찾아가는 데 성공하는 비율이 90% 이상이다.

## Assumptions

- **적용 대상은 이미지·SVG로 한정한다.** PDF 프리뷰는 지금처럼 버튼으로만 확대·축소한다. PDF는 이미 세로 스크롤로 페이지를 넘기므로 휠 확대를 얹으면 스크롤과 충돌하고, upstream도 이미지 경로에만 넣었다. PDF에도 키보드·휠을 넣으려면 범위를 다시 잡아야 한다.
- **입력 수단은 마우스와 키보드로 한정한다.** 터치 기기의 손가락 끌기·핀치는 이번 범위 밖이다. upstream 원본도 마우스 이벤트만 다룬다. 터치 지원은 별도 작업으로 뗀다.
- **배율 상한·하한은 현재 값을 이어받는다.** 확대 상한을 새로 정하는 문제는 이번 작업의 목적(조작 수단 추가)과 별개이며, 바꾸려면 사용자 눈으로 확인하고 정하는 편이 낫다. plan 단계에서 재검토한다.
- **확대 컨트롤이 보이는 조건은 그대로 둔다.** 지금 이미지·SVG·PDF에서 보이며, 이 범위를 넓히거나 좁히지 않는다.
- 접근성 관련 추가 요구(스크린 리더 안내, 포커스 순서 재설계)는 이번 범위 밖이다. 다만 기존 키보드 접근성을 떨어뜨리지 않는다.
- 배율·이동 위치를 세션 너머로 저장하지 않는다. 모달을 닫으면 사라진다.

## 범위 밖

- PDF 프리뷰의 휠·키보드·끌기 조작
- 터치 기기 제스처(손가락 끌기, 핀치 줌)
- 확대 상한·하한 값 자체의 재설정
- 동영상·오디오·코드 프리뷰
- 프리뷰 모달의 전체 구조 개편
