# 기능 명세: Slack 디자인 벤치마킹

**Feature Branch**: `feat/new-design`

**Created**: 2026-10-06

**Status**: Draft

**Input**: OKR.Best 채널 화면의 UI/UX를 Slack 계측 스펙에 맞춰 개선한다. 근거는 `/home/sdh/okrbest/okrbest-design`의 두 실측 문서 — `slack-design/design.md`(Slack 기준값)와 `okrbest-design/design.md`(현재값·격차 분석). 브레인스토밍에서 확정한 결정: ① 무채색 명도 3단 크롬을 기본 테마로 ② 레이아웃 골격 유지 ③ 타이포그래피는 Slack 수치 이식.

## 배경

Slack 웹 클라이언트와 OKR.Best 채널 화면을 같은 방법(픽셀·computedStyle 실측)으로
계측해 대조한 문서가 있다. 격차는 수치로 정리되어 있다.

| 격차 | Slack | OKR.Best 현재 |
|---|---|---|
| 크롬 색 | 무채색 명도 3단 (`#EAEAEA` → `#FDFDFD` → `#FFFFFF`) | 고채도 파랑 2단 (`#123B91` / `#1543A3`) |
| 활성 채널 표시 | 완전 반전 (`#333133` 배경 / `#F8F8F8` 글자) | 배경 명도만 미세 변경, 대비 4.05로 AA 미달 |
| 사이드바 글자 | 대비 8.82 | 알파 0.64 때문에 4.61 — 활성 항목이 가장 안 읽힌다 |
| 본문 타이포 | 15px/22px, 제목 18px/900, 크기 6단 | 14px/20px, 제목 16px/600·행간 1.00, 크기 3단, 한글 폰트 미지정 |
| 사이드바 폭 | 뷰포트 약 23% 가변 | 264px 고정 — 1024px에서 본문이 649px로 눌린다 |
| 모달 마감 | 스크림 + 그림자 + 1px 헤어라인 + 모서리 8px | 스크림만, 그림자 없음 |
| 의미색 위치 | 오류·링크·상태색은 테마와 무관하게 고정 | 테마 층에 있어 **프리셋 5종 전부 AA 미달 발생** |

접근성 실패가 구조적이다. 어떤 프리셋을 골라도 어딘가 WCAG AA에 미달하고,
실패 지점이 테마마다 옮겨 다닌다. 지금 보고 있는 활성 채널이 가장 안 읽히는
역전도 있다.

이 기능은 Slack 계측에서 추출한 설계 원칙 — 명도로 층을 나눈다, 선택은 반전으로
표시한다, 위계는 굵기로 세운다, 표면색은 알파로 쌓는다 — 을 OKR.Best의 기존 테마
체계 안에서 구현한다. 레이아웃 골격(팀 레일·사이드바·본문·앱바·북마크 바 5단
구조, 본문 카드 모양)은 바꾸지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 기본 화면이 Slack의 층과 강조로 보인다 (Priority: P1)

사용자가 채널 화면을 연다. 크롬(상단 헤더·팀 레일·사이드바)이 무채색이고,
바깥이 가장 어둡고 본문으로 갈수록 밝아지는 명도 3단으로 영역이 나뉜다. 지금
보고 있는 채널은 사이드바에서 배경과 글자가 반전되어 한눈에 띈다. 사이드바
글자는 흐릿하지 않고 선명하다.

**이 우선순위인 이유**: "Slack처럼 보인다"는 체감의 대부분이 여기서 나온다.
동시에 AA 미달 3건 중 2건(사이드바 글자, 활성 채널)이 이 스토리에서 해소된다.
이것 하나만 배포해도 외관과 접근성이 함께 좋아진다.

**독립 검증**: 새 기본 테마로 채널 화면을 열고 계측 하네스로 실측한다 —
크롬 3단 명도 순서, 활성 채널 반전, 사이드바 글자 대비.

**Acceptance Scenarios**:

1. **Given** 테마를 바꾼 적 없는 사용자다, **When** 채널 화면을 연다, **Then** 무채색 명도 3단 크롬이 보이고 팀 레일·상단 헤더가 가장 어둡고 본문이 가장 밝다.
2. **Given** 채널 여러 개가 사이드바에 있다, **When** 한 채널을 연다, **Then** 그 항목만 배경·글자가 반전되고 글자 대비가 7:1 이상이다.
3. **Given** 사이드바에 포인터를 올린다, **When** 항목 위를 hover 한다, **Then** 약한 배경 변화만 생기고 활성 항목과 혼동되지 않는다.
4. **Given** 기존 사용자가 파랑 프리셋이나 커스텀 테마를 저장해 뒀다, **When** 이 기능이 배포된다, **Then** 저장한 테마가 그대로 유지된다.

---

### User Story 2 — 글자 위계가 Slack 수준으로 선다 (Priority: P2)

사용자가 메시지를 읽는다. 본문은 15px에 행간 22px로 여유 있고, 채널 제목과
작성자 이름은 크기 차이가 작아도 굵기(900)로 확실히 구분된다. 한글이 OS마다
다른 글꼴로 그려지지 않고 지정된 한글 폰트로 일관되게 보인다.

**이 우선순위인 이유**: 타이포그래피는 모든 화면에 깔리는 기반이다. 색 다음으로
체감이 크고, 한글 자형 고정은 이 포크의 1급 로케일(한국어) 품질 문제다.

**독립 검증**: 채널 화면에서 본문·제목·작성자 이름의 크기·굵기·행간을 실측하고,
한글 텍스트가 지정 폰트로 렌더링되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 채널에 메시지가 있다, **When** 본문을 실측한다, **Then** 15px/22px이다.
2. **Given** 채널 제목이 보인다, **When** 실측한다, **Then** 18px, 굵기 900, 행간 비율 1.25 이상이다.
3. **Given** 한글 메시지가 있다, **When** 렌더링된 폰트를 확인한다, **Then** 명시된 한글 폰트가 적용되고 시스템 폴백에 의존하지 않는다.
4. **Given** 제목·본문·보조 텍스트가 한 화면에 있다, **When** 크기를 실측한다, **Then** 12·13·15·18·22·28 단계 안의 값이다.

---

### User Story 3 — 어떤 프리셋을 골라도 읽을 수 있다 (Priority: P3)

사용자가 테마 설정에서 파랑 프리셋 5종(Denim·Sapphire·Quartz·Indigo·Onyx) 중
무엇을 골라도 오류 문구, 새 메시지 구분선, 온라인·자리비움·방해금지 상태 점,
링크, 버튼이 전부 기준 대비를 넘는다. 테마를 바꿨더니 다른 곳이 안 보이게 되는
일이 없다.

**이 우선순위인 이유**: 현재는 "쓸 만한 테마가 0개"다. 프리셋을 남겨두는 결정
(기존 선택지 유지)이 의미를 가지려면 전부 교정되어야 한다.

**독립 검증**: 프리셋 5종을 차례로 적용하고 계측 하네스로 항목별 대비를 전수
측정한다.

**Acceptance Scenarios**:

1. **Given** 프리셋 5종 중 하나를 적용했다, **When** 오류 문구·링크·버튼 글자 대비를 잰다, **Then** 전부 4.5:1 이상이다.
2. **Given** 프리셋 5종 중 하나를 적용했다, **When** 새 메시지 구분선·상태 점 대비를 잰다, **Then** 전부 3:1 이상이다.
3. **Given** 커스텀 테마를 저장한 사용자다, **When** 이 기능이 배포된다, **Then** 커스텀 테마 값은 바뀌지 않는다.

---

### User Story 4 — 좁은 화면에서 본문이 먼저다 (Priority: P4)

사용자가 1024~1280px 폭 창에서 작업한다. 사이드바가 뷰포트에 비례해 줄어들어
본문이 충분히 남는다. 드래그로 폭을 조절하면 그 값이 유지된다.

**이 우선순위인 이유**: 좁은 창에서 본문 649px는 Slack(722px)보다 좁다. 드래그
리사이즈 기반이 이미 있어 비용이 작다.

**독립 검증**: 1024·1280·1440·1920px 뷰포트에서 본문 폭을 실측한다.

**Acceptance Scenarios**:

1. **Given** 사이드바 폭을 조절한 적 없는 사용자다, **When** 1024px 폭 창에서 채널 화면을 연다, **Then** 본문 폭이 720px 이상이다.
2. **Given** 드래그로 사이드바 폭을 바꿨다, **When** 창 크기를 바꾸거나 다시 접속한다, **Then** 조절한 폭이 유지된다.
3. **Given** 768px 이하 폭이다, **When** 채널 화면을 연다, **Then** 기존 드로어 동작이 그대로다.

---

### User Story 5 — 모달과 전환이 마감된 느낌을 준다 (Priority: P5)

사용자가 모달을 연다. 스크림 위에 그림자와 가는 테두리를 두른 카드가 떠 있다.
hover·활성 같은 배경 전환은 즉각적이고, 레이아웃이 움직이는 전환은 부드럽게
감속한다.

**이 우선순위인 이유**: 마감 디테일이다. 체감 기여는 있지만 앞 스토리들 없이는
의미가 작다.

**독립 검증**: 모달 하나를 열어 그림자·테두리·모서리를 실측하고, 전환 지속
시간을 실측한다.

**Acceptance Scenarios**:

1. **Given** 모달이 열려 있다, **When** 실측한다, **Then** 모서리 8px, 바깥 그림자, 1px 헤어라인 테두리가 있다.
2. **Given** 인터랙티브 요소가 있다, **When** 배경색 전환을 실측한다, **Then** 약 80ms 안에 끝난다.
3. **Given** 레이아웃이 움직이는 전환이 있다, **When** 실측한다, **Then** 약 160ms에 감속 곡선을 쓰고 어떤 전환도 500ms를 넘지 않는다.

---

### Edge Cases

- 다크 계열 프리셋(Indigo·Onyx)에서 활성 채널 반전은 방향이 반대다(밝은 배경 + 어두운 글자). 프리셋별 값으로 대응하고, 양쪽 모두 대비 7:1 이상을 지킨다.
- 커스텀 테마 사용자: 저장된 값은 건드리지 않는다. 의미색 교정은 프리셋과 기본값에만 적용한다.
- 한글 폰트 로드가 실패하면 시스템 산세리프로 폴백하고 레이아웃이 깨지지 않아야 한다.
- 본문 15px/22px 전환으로 한글 위아래가 잘리는 곳(현재 제목 행간 1.00)이 없어야 한다.
- 사이드바 폭을 이미 드래그로 저장한 사용자는 저장값이 새 기본 정책보다 우선한다.
- upstream 머지: 이 기능의 변경은 upstream 파일과 갈라진다. 발산을 기록하지 않으면 다음 sync 때 조용히 되돌아갈 수 있다.

## Requirements *(mandatory)*

### Functional Requirements

**색·테마**

- **FR-001**: 무채색 명도 3단 프리셋을 신설한다. 팀 레일·상단 헤더가 가장 어둡고(`#EAEAEA` 수준), 사이드바가 그다음(`#FDFDFD` 수준), 본문이 가장 밝다(`#FFFFFF`). 영역 경계는 선이 아니라 밝기 차이로 읽힌다.
- **FR-002**: 신설 프리셋이 기본 테마다. 테마를 명시적으로 저장한 기존 사용자의 선택은 바꾸지 않는다.
- **FR-003**: 기존 파랑 프리셋 5종(Denim·Sapphire·Quartz·Indigo·Onyx)은 선택지로 유지한다.
- **FR-004**: 의미색 — 오류 문구, 새 메시지 구분선, 온라인·자리비움·방해금지 상태 점 — 은 어떤 프리셋에서도 기준 대비(글자 4.5:1, 비텍스트 3:1)를 넘는다. 프리셋을 새로 추가할 때 의미색을 다시 조율하지 않아도 되도록 기본값을 한 곳에서 정한다.

**사이드바 상태**

- **FR-005**: 사이드바 글자는 불투명하게 렌더링한다. 반투명(알파 0.64) 덧씌움을 걷어낸다. 무채색 기본 테마에서 대비 8.8:1 이상, 모든 프리셋에서 4.5:1 이상.
- **FR-006**: 활성 채널은 배경·글자를 반전해 표시한다. 활성 항목의 글자 대비는 7:1 이상이고, 사이드바에서 대비가 가장 높은 항목이어야 한다(현재의 역전을 금지한다).
- **FR-007**: 사이드바 항목 상태는 3단으로 구분한다 — 기본(투명), hover(약한 오버레이), 활성(반전). hover와 활성이 혼동되지 않게 강도 차이를 크게 둔다.

**타이포그래피**

- **FR-008**: 메시지 본문은 15px, 행간 22px이다.
- **FR-009**: 채널 제목은 18px, 굵기 900, 행간 비율 1.25 이상이다. 메시지 작성자 이름은 본문과 같은 크기에 굵기 900으로 구분한다.
- **FR-010**: 크기 단계는 12·13·15·18·22·28의 6단이다. 채널 화면의 텍스트는 이 단계 안의 값을 쓴다.
- **FR-011**: 한글 폰트를 명시한다(Noto Sans KR 또는 동급 한글 글리프 포함 폰트). 한글 자형이 OS 폴백에 좌우되지 않는다. 폰트는 외부 네트워크 없이 로드된다.

**레이아웃**

- **FR-012**: 사이드바는 넓은 화면에서 뷰포트 폭에 비례해 줄어든다(약 23%). 1024px 뷰포트에서 본문 폭 720px 이상. 사용자가 드래그로 조절한 폭은 정책보다 우선한다.
- **FR-013**: 레이아웃 골격은 유지한다 — 5단 구조(팀 레일·사이드바·본문·앱바·북마크 바)와 본문 카드 모양을 바꾸지 않는다. 768px 이하 드로어 동작도 그대로다.

**모달·모션**

- **FR-014**: 모달은 세 겹으로 마감한다 — 스크림, 바깥 그림자, 1px 헤어라인 테두리. 모서리는 8px이다.
- **FR-015**: 배경색 전환은 약 80ms로 즉각적이고, 레이아웃이 움직이는 전환은 약 160ms에 감속 곡선을 쓴다. 어떤 전환도 500ms를 넘지 않는다.

**프로세스 제약** (constitution)

- **FR-016**: webapp 게이트를 통과하고 출력을 완료 근거로 남긴다 — `npm run check`, `npm run check-types`, `npm run test` (원칙 I). 구현 전 기준선 실패 목록을 저장하고 마감 때 diff로 회귀를 판정한다.
- **FR-017**: `Copyright (c) 2015-present Mattermost, Inc.` 헤더를 유지한다 (원칙 IV).
- **FR-018**: 사용자에게 보이는 문자열(새 테마 이름 등)을 추가하면 `en.json`·`ko.json`을 같은 변경에서 갱신한다 (원칙 V).
- **FR-019**: upstream 파일과 갈라지는 변경은 `docs/upstream-adapted-divergences.md`에 기록한다. 구조적 스타일 변경은 upstream 파일 인라인 수정 대신 이 포크 전용 레이어로 격리해 머지 충돌을 줄인다.

### Key Entities

- **테마 프리셋**: 사용자가 고르는 표면색 묶음. 신설 무채색 1종 + 기존 파랑 5종. 사이드바·헤더·본문 바탕과 그 파생 상태(hover·활성)를 정의한다.

## Assumptions

### 1. 기준선은 구현 전에 재계측한다

기존 계측일은 2026-08-10이고, 그 후 코드가 바뀌었을 수 있다(예: 모달 모서리가
계측에서는 0px였지만 지금 코드는 둥근 값을 정의한다). SC의 "기준선" 수치는 재계측
값으로 갱신하고, 문서의 수치와 다르면 재계측 값을 기준으로 삼는다.

### 2. 기본 테마 변경은 미설정 사용자에게만 적용한다

테마를 명시적으로 저장한 사용자(프리셋 선택 포함)는 그대로 둔다. 서버 기본값과
신규 계정만 신설 프리셋을 받는다.

### 3. 의미색 교정은 프리셋 값과 기본값으로 한다

커스텀 테마 편집기의 필드 구조(테마 호환성)는 바꾸지 않는다. 프리셋 5종의 의미색
값을 기준 대비를 넘는 값으로 교정하고, 테마에 값이 없을 때의 기본값을 한 곳에서
정한다. 사용자가 저장한 커스텀 테마 값은 건드리지 않는다.

### 4. 한글 폰트는 저장소에 번들한다

기존 폰트와 같은 방식(자체 호스팅)으로 조달한다. 외부 CDN 의존을 추가하지 않는다.
폰트 파일의 라이선스(OFL 등)를 확인하고 고지를 유지한다.

### 5. 계측 하네스 저장소가 형제 디렉터리에 있다

`/home/sdh/okrbest/okrbest-design`이 존재하고 실행 가능하다고 전제한다. 계측
대상 환경(로컬 또는 team.okrbest.com)에 접속할 인증은 사용자가 제공한다.
