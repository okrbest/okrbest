# Quickstart: 읽지 않은 항목 모아보기 — 실행·검증 가이드

## 사전 준비

```bash
# 저장소 루트에서
nvm use                      # Node 20.11 (.nvmrc)
cd webapp && npm install     # 최초 1회

# 로컬 서버 + 웹앱 (기존 개발 절차 그대로)
cd ../server && make run-server
cd ../webapp && npm run run        # webpack dev server
```

테스트 데이터: 계정 2개(A: 검증 대상, B: 메시지 발신)와 채널 3곳 이상.
B로 각 채널에 메시지를 보내 A에게 읽지 않은 메시지를 만든다. 한 채널에서는
A를 @멘션한다.

## 품질 게이트 (원칙 I — 구현 전 기준선 저장 필수)

```bash
cd webapp
npm run check        # eslint + stylelint
npm run check-types  # tsc -b
npm run test         # Jest (TZ=UTC)
```

구현 시작 전에 위 3개를 돌려 실패 목록을 기준선으로 저장하고, 마감 때 같은
명령의 실패 목록과 diff로 회귀를 판정한다.

## 종단 검증 시나리오 (SC 대응)

### SC-001 — 클릭 1번으로 전 채널 확인

1. A로 로그인. 읽지 않은 채널 5곳 준비.
2. 사이드바 "읽지 않은 항목" 클릭 1번.
3. **기대**: 5개 채널 그룹과 각 본문이 한 화면에 나온다. 멘션 채널이 맨 위.

### SC-002 — 1초 내 첫 목록

1. 읽지 않은 채널 20곳 이하 상태에서 화면 진입.
2. **기대**: 진입 후 1초 안에 첫 그룹 목록 표시 (DevTools Performance로 실측).

### SC-003 — 보기만으로 읽음 처리 0건

1. 진입 전 사이드바 배지 수를 기록.
2. 화면을 열어 모든 그룹을 끝까지 스크롤.
3. 화면을 떠났다가 새로고침.
4. **기대**: 배지 수 변화 없음. 각 채널 진입 시 "새 메시지" 구분선 유지.

### SC-004 — 읽음 처리 1초 내 동기화

1. 그룹 하나에서 "읽음으로 표시" 클릭.
2. **기대**: 1초 안에 그룹 제거 + 사이드바·탭 제목 배지 갱신.
3. 같은 계정의 두 번째 브라우저 탭에서도 반영 확인 (US2-4).

### SC-005 — 신규 계정 UNREADS 그룹 비표시

1. 사이드바 설정을 만진 적 없는 새 계정 10개로 각각 로그인.
2. **기대**: 전부 사이드바에 UNREADS 채널 그룹 없음.
3. 설정 모달 → 사이드바 → "읽지 않은 채널 모아보기" 켜면 나타남 (US4-3).

### SC-006 — 키보드 전용 완주

1. 마우스 없이: Alt+↑/↓로 사이드바의 "읽지 않은 항목" 진입.
2. ↑/↓(또는 Tab)로 그룹 포커스 이동, Esc로 포커스 그룹 읽음 처리.
3. 메시지 액션 메뉴(이모지 선택기 등)를 연 상태에서 Esc — 메뉴만 닫히고
   그룹은 읽음 처리되지 않아야 한다. 한 번 더 누르면 그룹 읽음.
4. **기대**: 마우스 0회로 열기 → 이동 → 읽음 처리 완료, Esc 충돌 없음.

### FR-013 — 새 항목 배너

1. A가 화면을 보는 동안 B가 새 채널에 메시지 발신.
2. **기대**: 목록은 그대로, "새 항목" 배너 표시. 배너 클릭 시 갱신.
