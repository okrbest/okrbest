# Feature Specification: 읽지 않은 항목 모아보기

**Feature Branch**: `015-unreads-view`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "Slack의 읽지 않은 항목(Unreads) 화면을 벤치마킹한다. 읽지 않은 메시지를 한 곳에서 모아 보는 메뉴를 신설하고, 기존 '읽지 않은 채널 모아보기'(사이드바 그룹)는 기본 꺼짐으로 둔다. 기존 구현을 최대한 재사용해 추가 개발을 최소화한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 읽지 않은 메시지를 한 화면에서 확인한다 (Priority: P1)

여러 채널에 읽지 않은 메시지가 쌓인 사용자가 사이드바의 "읽지 않은 항목" 메뉴를 누른다. 전용 화면이 열리고, 읽지 않은 메시지가 채널별로 묶여 메시지 본문까지 보인다. 채널을 하나씩 돌지 않아도 밀린 대화를 한 번에 따라잡는다.

**Why this priority**: 이 기능의 존재 이유다. 지금은 읽지 않은 채널을 하나씩 들어가야 내용이 보인다. 이 이야기 하나만 구현해도 "한 곳에서 모아 본다"는 가치가 성립한다.

**Independent Test**: 채널 3곳에 읽지 않은 메시지를 만들고, 메뉴 클릭 한 번으로 세 채널의 메시지 본문이 한 화면에 채널별로 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 채널 3곳에 읽지 않은 메시지가 있다, **When** 사이드바의 "읽지 않은 항목"을 누른다, **Then** 세 채널이 각각 그룹으로 표시되고 각 그룹에 마지막으로 읽은 시점 이후의 메시지가 본문과 함께 나온다.
2. **Given** 멘션이 있는 채널과 없는 채널이 섞여 있다, **When** 화면을 연다, **Then** 멘션이 있는 채널 그룹이 먼저, 나머지는 최근 활동순으로 나온다.
3. **Given** 화면을 열어 메시지를 끝까지 훑었다, **When** 아무 읽음 처리도 하지 않고 떠난다, **Then** 해당 채널들은 여전히 읽지 않음 상태다(보기만으로 읽음 처리되지 않는다).
4. **Given** 읽지 않은 메시지가 하나도 없다, **When** 화면을 연다, **Then** "모두 읽었습니다" 성격의 빈 상태 안내가 나온다.
5. **Given** 그룹의 메시지 위에 마우스를 올린다, **When** 메시지 액션을 쓴다, **Then** 채널에서와 같이 반응 추가·스레드 열기·저장을 할 수 있다.

---

### User Story 2 - 화면 안에서 읽음 처리한다 (Priority: P2)

사용자가 모아보기 화면에서 다 읽은 채널 그룹을 "읽음으로 표시"한다. 그룹이 목록에서 사라지고 사이드바 배지도 줄어든다. 전부 따라잡았으면 "모든 메시지 읽음으로 표시" 한 번으로 끝낸다.

**Why this priority**: 모아 보기만 하고 읽음 처리를 못 하면 사이드바 배지가 계속 남아 화면의 효용이 반감된다. 다만 P1 없이 성립하지 않으므로 P2다.

**Independent Test**: 화면에서 그룹 하나를 읽음 처리하고, 그룹이 사라지는지·사이드바의 해당 채널 읽지 않음 표시가 지워지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 모아보기 화면에 그룹 3개가 있다, **When** 한 그룹의 "읽음으로 표시"를 누른다, **Then** 그 그룹이 목록에서 사라지고 사이드바에서 해당 채널의 읽지 않음 표시가 지워진다.
2. **Given** 그룹이 여러 개 있다, **When** "모든 메시지 읽음으로 표시"를 누른다, **Then** 모든 그룹이 사라지고 빈 상태 안내가 나온다.
3. **Given** 키보드 포커스가 한 그룹에 있다, **When** Esc를 누른다, **Then** 그 그룹이 읽음 처리된다.
4. **Given** 이 화면에서 채널을 읽음 처리했다, **When** 같은 계정으로 연 다른 기기·탭을 본다, **Then** 거기서도 읽음 상태가 반영된다.

---

### User Story 3 - 그룹을 접고, 새 메시지 유입에 흔들리지 않는다 (Priority: P3)

사용자가 긴 그룹을 접어 다른 채널부터 처리한다. 화면을 보는 동안 새 메시지가 와도 목록이 갑자기 재배열되지 않고, "새 항목" 알림을 눌렀을 때만 갱신된다.

**Why this priority**: 소비 경험을 다듬는 요소다. 없어도 P1·P2만으로 기능이 성립한다.

**Independent Test**: 그룹 접기/펼치기를 토글하고, 화면을 열어 둔 채 다른 계정으로 새 메시지를 보내 목록이 멋대로 바뀌지 않는지·알림으로 갱신되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 그룹이 펼쳐져 있다, **When** 그룹 머리글의 접기 컨트롤을 누른다, **Then** 메시지 본문이 숨고 머리글만 남는다. 다시 누르면 펼쳐진다.
2. **Given** 화면을 보고 있다, **When** 다른 채널에 새 읽지 않은 메시지가 생긴다, **Then** 목록은 그대로 두고 새 항목이 있다는 알림이 나타나며, 알림을 누르면 목록이 갱신된다.
3. **Given** 화면을 보고 있다, **When** 다른 기기에서 어떤 채널을 읽음 처리한다, **Then** 해당 그룹은 다음 갱신 때 목록에서 빠진다.

---

### User Story 4 - 사이드바는 기본 상태를 유지한다 (Priority: P3)

새로 가입한 사용자의 사이드바에는 "읽지 않음(UNREADS)" 채널 그룹이 나타나지 않는다. 전에 이 그룹을 직접 켠 사용자에게는 그대로 유지된다.

**Why this priority**: 신설 화면이 읽지 않음 소비의 기본 경로가 되도록 기존 기능을 기본 꺼짐으로 고정하는 요구다. 현재 서버 기본값이 이미 꺼짐이므로 확인·고정 성격이다.

**Independent Test**: 설정을 만진 적 없는 새 계정으로 로그인해 사이드바에 UNREADS 그룹이 없는지, 설정에서 켜면 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사이드바 설정을 바꾼 적 없는 계정이다, **When** 로그인한다, **Then** 사이드바에 UNREADS 채널 그룹이 없다.
2. **Given** 설정에서 "읽지 않은 채널 모아보기"를 켠 계정이다, **When** 이 기능이 배포된다, **Then** UNREADS 그룹이 그대로 유지된다.
3. **Given** 임의의 계정이다, **When** 설정 모달의 사이드바 탭을 연다, **Then** "읽지 않은 채널 모아보기" 토글이 여전히 있고 동작한다.

---

### Edge Cases

- 읽지 않은 메시지가 매우 많은 채널(수백 건)은 어떻게 하나 → 그룹에는 읽지 않은 구간의 최근 일부만 보여주고, 그룹 머리글의 채널 이동으로 이어 본다. 표시 한도는 기존 "읽지 않은 메시지부터 보기"가 쓰는 조회 한도를 따른다.
- 뮤트한 채널은 나오나 → 기존 읽지 않음 판정과 같다. 멘션이 없으면 제외, 멘션이 있으면 포함.
- 수동으로 "읽지 않음"으로 표시한 채널 → 읽지 않음 판정에 포함되므로 그룹으로 나온다.
- 화면을 보는 동안 그룹의 채널에서 내가 내보내지거나 채널이 보관되면 → 다음 갱신 때 그룹이 빠진다. 그룹 내 액션은 실패 안내를 보여준다.
- 읽음 처리 요청이 네트워크 오류로 실패하면 → 그룹을 지우지 않고 실패를 알린다.
- 멘션 수만 있고 본문을 불러오지 못한 채널(권한·삭제 등) → 그룹 머리글과 채널 이동만 제공하고 본문 영역에 불러오지 못했음을 표시한다.
- DM·그룹 메시지도 채널과 동일하게 그룹으로 나온다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사이드바 상단 고정 영역에 "읽지 않은 항목" 메뉴를 항상 표시한다. 메뉴에는 현재 팀의 읽지 않음 상태(멘션 수 또는 읽지 않음 표시)가 배지로 나타난다.
- **FR-002**: 메뉴를 누르면 전용 화면이 열린다. 화면 주소가 고유해 새로고침·뒤로가기에도 유지된다.
- **FR-003**: 화면은 읽지 않은 메시지를 채널별 그룹으로 보여준다. 그룹 순서는 멘션 있는 채널 우선, 그다음 최근 활동순이다.
- **FR-004**: 각 그룹 머리글은 채널 이름과 유형(공개/비공개/DM/그룹 메시지)을 구별해 보여주고, 채널로 이동하는 동작을 제공한다.
- **FR-005**: 각 그룹 본문은 그 채널에서 마지막으로 읽은 시점 이후의 메시지를 작성자·시각·본문·첨부와 함께 보여준다.
- **FR-006**: 그룹 안의 메시지에서 채널에서와 동일한 메시지 상호작용(반응 추가, 스레드 열기, 저장 등)을 쓸 수 있다.
- **FR-007**: 화면을 보는 것만으로는 어떤 채널도 읽음 처리되지 않는다. 읽음 처리는 사용자의 명시적 동작으로만 일어난다.
- **FR-008**: 그룹마다 "읽음으로 표시" 동작을 제공한다. 처리된 그룹은 목록에서 사라지고, 읽지 않음 배지(사이드바·팀·탭 제목)가 즉시 갱신된다.
- **FR-009**: 화면 머리글에 "모든 메시지 읽음으로 표시" 동작을 제공한다. 현재 목록의 모든 채널이 읽음 처리된다.
- **FR-010**: 키보드 포커스가 있는 그룹에서 Esc를 누르면 그 그룹이 읽음 처리된다.
- **FR-011**: 단축키 Ctrl+Shift+A(macOS는 Cmd+Shift+A)로 어디서든 이 화면을 연다.
- **FR-012**: 그룹을 접고 펼칠 수 있다. 접힌 그룹은 머리글만 남는다.
- **FR-013**: 화면을 보는 동안 새 읽지 않은 메시지가 생겨도 목록을 즉시 재배열하지 않는다. 새 항목이 있음을 알리고, 사용자가 선택했을 때 갱신한다. 단, 이미 표시 중인 그룹의 읽음 상태 변화(다른 기기에서 읽음 등)는 갱신 때 반영한다.
- **FR-014**: 읽지 않은 항목이 없으면 빈 상태 안내를 보여준다.
- **FR-015**: 읽지 않음 판정 기준은 기존 사이드바 배지와 동일하다. 화면의 그룹 유무와 사이드바의 읽지 않음 표시가 서로 어긋나지 않는다.
- **FR-016**: 기존 "읽지 않은 채널 모아보기"(사이드바 UNREADS 그룹)는 기본 꺼짐을 유지한다. 서버 기본값이 꺼짐임을 확인해 기록하고, 사용자가 직접 켠 설정과 설정 토글은 그대로 보존한다.
- **FR-017**: 화면의 모든 문구를 영어·한국어로 동시에 제공한다.

### Key Entities

- **읽지 않은 메시지 그룹**: 채널 하나와 그 채널에서 마지막으로 읽은 시점 이후의 메시지 묶음. 속성: 채널 식별·유형·이름, 멘션 수, 마지막 활동 시각, 접힘 상태.
- **읽음 상태**: 사용자·채널 쌍의 마지막 읽은 시점. 이 화면은 새 저장소를 만들지 않고 기존 읽음 상태를 그대로 읽고 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 읽지 않은 채널이 5개일 때, 메뉴 클릭 1번으로 5개 채널의 읽지 않은 메시지 본문을 모두 확인할 수 있다(기존에는 채널 진입 5번).
- **SC-002**: 읽지 않은 채널 20개 이하 환경에서, 화면 진입 후 1초 안에 첫 그룹 목록이 보인다.
- **SC-003**: 화면을 열어 끝까지 훑은 뒤에도 읽지 않음 배지 수가 변하지 않는다(명시적 읽음 처리 전까지 0건 자동 읽음).
- **SC-004**: 그룹 읽음 처리 후 1초 안에 사이드바·탭 제목의 읽지 않음 표시가 갱신된다.
- **SC-005**: 사이드바 설정을 바꾼 적 없는 신규 계정 10개 전부에서 사이드바에 UNREADS 채널 그룹이 나타나지 않는다.
- **SC-006**: 마우스 없이 단축키와 키보드만으로 화면 열기 → 그룹 이동 → 그룹 읽음 처리를 완료할 수 있다.

## Assumptions

- 대상은 데스크톱 웹이다. 모바일 앱의 "따라잡기" 탭과 별도 반응형 전용 화면은 범위 밖이다.
- Slack의 정렬 옵션 4종, 사이드바 섹션별 필터, 읽음 실행 취소, 메시지 단위 읽음 처리는 v1 범위 밖이다. 정렬은 멘션 우선 + 최근 활동순으로 고정한다.
- 읽지 않음 판정(뮤트 채널 제외 규칙 포함)과 읽음 처리 단위(채널 단위)는 기존 동작을 그대로 쓴다. 새 판정 규칙을 만들지 않는다.
- 채널당 본문 표시 한도는 기존 읽지 않은 구간 조회 한도를 따르며, 한도를 넘는 분량은 채널로 이동해 이어 본다.
- 기존 사이드바 UNREADS 그룹, 설정 토글, 관련 서버 설정은 제거하지 않는다. 기본 꺼짐은 현재 서버 기본값이 이미 보장하므로, 운영 서버의 설정값 확인을 배포 점검에 포함한다.
- upstream 포크 특성상 기존 화면·구성요소를 재사용하고 신규 구조 추가를 최소화한다. 세부 기술 선택은 plan에서 정한다.
