# Feature Specification: 시스템 관리자 테마 전체 적용

**Feature Branch**: `016-admin-theme-apply`

**Created**: 2026-10-08

**Status**: Draft

**Input**: User description: "시스템 관리자 테마 전체 적용: 화면 설정 > 테마 섹션에 시스템 관리자에게만 \"모든 팀원에게 새로운 테마를 적용합니다\" 체크박스를 추가한다. 관리자가 체크 후 저장하면 서버가 모든 활성 사용자(봇·비활성 제외)의 테마 preference를 관리자가 선택한 테마로 일회성 덮어쓰기한다(이후 각 사용자는 자기 테마 변경 가능). 접속 중 사용자에게 즉시 반영하고, 서버에서 시스템 관리자 권한을 강제한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관리자가 테마를 전 사용자에게 적용한다 (Priority: P1)

시스템 관리자가 화면 설정 > 테마에서 원하는 테마(기본 제공 또는 커스텀)를 고르고
"모든 팀원에게 새로운 테마를 적용합니다"를 체크한 뒤 저장한다. 저장이 끝나면
서버의 모든 활성 사용자(봇·비활성 계정 제외)의 테마가 관리자가 고른 테마로
바뀐다. 팀별로 다른 테마를 쓰던 사용자도 전역 테마 하나로 통일된다.

**Why this priority**: 이 기능의 핵심 가치다. 조직 전체의 화면을 한 번에 통일하는
것이 이 기능의 존재 이유이며, 이것만 동작해도 MVP가 된다.

**Independent Test**: 사용자 여러 명(일반 사용자, 팀별 테마 보유 사용자, 봇,
비활성 사용자)을 만든 뒤 관리자가 체크 후 저장하고, 각 사용자의 테마 설정을
조회해 활성 일반 사용자만 새 테마로 바뀌었는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 활성 사용자 A·B가 서로 다른 테마를 쓰고 있다, **When** 관리자가
   Denim 테마를 고르고 체크박스를 켠 채 저장한다, **Then** A·B의 테마가 모두
   Denim으로 바뀐다.
2. **Given** 사용자 C가 팀1·팀2에 팀별로 다른 테마를 설정해 뒀다, **When**
   관리자가 전체 적용을 실행한다, **Then** C의 팀별 테마는 사라지고 모든 팀에서
   관리자가 고른 테마 하나가 적용된다.
3. **Given** 봇 계정과 비활성(삭제된) 계정이 있다, **When** 관리자가 전체 적용을
   실행한다, **Then** 봇·비활성 계정의 설정은 바뀌지 않는다.
4. **Given** 전체 적용이 끝난 상태다, **When** 사용자 A가 자기 테마를 다른
   테마로 바꾼다, **Then** A의 선택이 그대로 유지된다(일회성 적용이므로 다시
   덮어쓰지 않는다).

---

### User Story 2 - 관리자가 아니면 이 기능을 쓸 수 없다 (Priority: P2)

일반 사용자의 화면 설정 > 테마에는 이 체크박스가 보이지 않는다. 화면을 우회해
전체 적용 요청을 직접 보내더라도 서버가 거부한다.

**Why this priority**: 전 사용자의 설정을 바꾸는 기능이므로 권한 통제가 뚫리면
기능 자체가 해악이 된다. P1 구현과 같은 변경 안에서 반드시 함께 보장해야 한다.

**Independent Test**: 일반 사용자 계정으로 설정 화면을 열어 체크박스가 없는지
확인하고, 같은 계정의 인증 정보로 전체 적용 요청을 직접 보내 거부(권한 오류)
응답을 확인한다.

**Acceptance Scenarios**:

1. **Given** 일반 사용자로 로그인했다, **When** 화면 설정 > 테마를 연다,
   **Then** "모든 팀원에게 새로운 테마를 적용합니다" 체크박스가 보이지 않는다.
2. **Given** 일반 사용자의 인증 정보가 있다, **When** 전체 적용 요청을 직접
   보낸다, **Then** 서버가 권한 부족으로 거부하고 어떤 사용자의 테마도 바뀌지
   않는다.

---

### User Story 3 - 접속 중인 사용자 화면에 즉시 반영된다 (Priority: P3)

관리자가 전체 적용을 실행하는 순간, 접속해 있는 사용자의 화면이 재로그인이나
새로고침 없이 새 테마로 바뀐다.

**Why this priority**: 없어도 기능은 성립한다(다음 접속 때 반영). 그러나 실시간
반영이 있어야 "적용했다"는 관리자의 체감과 사용자 경험이 완성된다.

**Independent Test**: 두 브라우저 세션(관리자, 일반 사용자)을 동시에 띄우고
관리자가 전체 적용을 실행한 뒤, 일반 사용자 화면이 수 초 안에 새 테마로
바뀌는지 관찰한다.

**Acceptance Scenarios**:

1. **Given** 일반 사용자가 접속해 채널을 보고 있다, **When** 관리자가 전체
   적용을 실행한다, **Then** 해당 사용자의 화면이 새로고침 없이 새 테마로
   전환된다.

---

### Edge Cases

- 관리자 자신도 적용 대상이다 — 저장 직후 관리자 화면도 같은 테마가 된다.
- 체크박스를 켜면 기존 "가입한 모든 팀에서 새로운 테마를 적용합니다" 체크박스는
  의미가 포함되므로(전역 적용) 비활성화된 켜짐 상태로 표시한다.
- 사용자 수가 많은 서버(수천 명)에서도 적용이 단일 작업으로 끝나야 하며, 적용
  도중 일부만 바뀐 상태로 멈추지 않아야 한다(전부 적용 또는 전부 미적용).
- 커스텀 테마를 골라 전체 적용해도 동일하게 동작한다.
- 테마 설정이 아예 없던 사용자(기본 테마 사용자)도 적용 후에는 관리자가 고른
  테마를 갖는다.
- 적용 요청의 테마 값이 올바르지 않으면(형식 오류) 서버가 거부하고 아무 변경도
  하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 화면 설정 > 테마 섹션은 시스템 관리자에게만 "모든 팀원에게 새로운
  테마를 적용합니다" 체크박스를 보여준다. 일반 사용자에게는 보이지 않는다.
- **FR-002**: 관리자가 체크박스를 켜고 저장하면, 시스템은 모든 활성 사용자의
  테마를 관리자가 선택한 테마로 덮어쓴다. 봇 계정과 비활성 계정은 제외한다.
- **FR-003**: 전체 적용 시 사용자별 팀 한정 테마는 제거되어, 모든 팀에서 동일한
  전역 테마 하나가 적용된다.
- **FR-004**: 전체 적용은 일회성이다. 적용 이후 각 사용자는 자기 테마를 자유롭게
  변경할 수 있고, 시스템이 이를 되돌리지 않는다.
- **FR-005**: 서버는 전체 적용 요청에 시스템 관리자 권한을 강제한다. 권한이 없는
  요청은 거부하며, 거부 시 어떤 사용자의 설정도 변경하지 않는다.
- **FR-006**: 전체 적용은 원자적으로 수행한다 — 도중 실패 시 일부 사용자만
  바뀐 상태를 남기지 않는다.
- **FR-007**: 접속 중인 사용자에게는 재로그인·새로고침 없이 새 테마가 즉시
  반영된다.
- **FR-008**: 관리자가 전체 적용 체크박스를 켜면 기존 "가입한 모든 팀에서
  새로운 테마를 적용합니다" 체크박스는 켜진 상태로 비활성화된다(전역 적용에
  포함되므로).
- **FR-009**: 체크박스 문구와 관련 안내는 한국어·영어로 제공한다.
- **FR-010**: 올바르지 않은 테마 값으로 들어온 전체 적용 요청은 거부하고 아무
  변경도 하지 않는다.

### Key Entities

- **테마 설정(사용자별)**: 각 사용자가 보유한 화면 테마. 전역 테마 하나와 팀
  한정 테마 여러 개를 가질 수 있다. 전체 적용은 전역 테마를 덮어쓰고 팀 한정
  테마를 제거한다.
- **시스템 관리자**: 서버 전체 관리 권한을 가진 사용자. 이 기능의 유일한 실행
  주체다.
- **적용 대상 사용자**: 봇이 아니고 비활성화되지 않은 모든 사용자. 관리자 자신을
  포함한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 저장 한 번으로 전 사용자 테마 적용을 끝낸다. 추가 조작이
  필요 없다.
- **SC-002**: 활성 사용자 1,000명 규모에서 전체 적용이 10초 안에 완료된다.
- **SC-003**: 접속 중인 사용자 화면은 적용 후 5초 안에 새 테마로 바뀐다.
  재로그인·새로고침이 필요 없다.
- **SC-004**: 일반 사용자 계정으로는 화면에서 이 기능을 발견할 수 없고, 직접
  요청해도 100% 거부된다.
- **SC-005**: 적용 후 사용자가 자기 테마를 바꾸면 그 선택이 유지된다 — 시스템이
  되돌리는 경우가 0건이다.

## Assumptions

- 적용 방식은 브레인스토밍에서 **일회성 덮어쓰기**로 확정했다. 강제 고정(사용자
  변경 금지)은 범위 밖이다.
- 적용 범위는 브레인스토밍에서 **서버 전체 활성 사용자**로 확정했다. 특정 팀
  한정 적용은 범위 밖이다.
- 게스트 계정도 활성 사용자이므로 적용 대상에 포함한다.
- 기존 사용자별 테마 저장 구조(전역/팀 한정)를 그대로 쓰며, 새로운 저장 구조를
  도입하지 않는다.
- 적용 전 확인 대화상자 등 추가 안전장치는 이번 범위에 넣지 않는다. 체크박스가
  명시적 의사 표시이고, 적용 후에도 각 사용자가 되돌릴 수 있기 때문이다.
- 시스템 콘솔(관리자 콘솔)이 아닌 일반 화면 설정에서 실행하는 것이 요구사항이다.
  시스템 콘솔 쪽 중복 기능은 만들지 않는다.
- 체크박스 한국어 문구는 요청 원문대로 "모든 팀원에게 새로운 테마를
  적용합니다"를 쓴다. 적용 범위는 문구와 무관하게 서버 전체 활성 사용자다
  (영어 문구는 "Apply new theme to all users").
