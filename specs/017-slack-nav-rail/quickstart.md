# Quickstart: 좌측 네비게이션 Slack식 재구성 — 종단 검증

**Date**: 2026-10-08 | **Plan**: [plan.md](./plan.md) | **Contract**: [contracts/nav-ui.md](./contracts/nav-ui.md)

완료 판정은 이 문서의 실주행 결과와 SC-001~SC-006 실측으로 한다.

## 준비

```bash
cd server && make run-server        # DB 비번이 다르면 MM_SQLSETTINGS_DATASOURCE 오버라이드
cd webapp && make run               # webpack watch
```

- Boards·Playbooks 플러그인이 활성화된 서버 (시스템 콘솔에서 확인)
- 계정: 시스템 관리자 1, 일반 사용자 1(팀 2곳 이상 가입), 게스트 또는 팀
  생성 권한 없는 계정 1

## 시나리오 1 — 제품 전환 (SC-001·SC-003, US1)

1. 일반 사용자로 채널 화면 접속.
2. **기대**: 레일에 [현재 팀 버튼, Channels, Boards, Playbooks]가 세로 나열,
   Channels 활성 강조. 상단 좌측에 Channels 드롭다운 버튼 없음.
3. Boards 클릭 → Boards 화면 + 강조 이동 (클릭 1번, SC-001).
4. Playbooks 클릭 → Playbooks 화면 + 강조 이동.
5. Channels 클릭 → 보던 팀 채널로 복귀.
6. 플러그인 2종을 비활성화하고 새로고침 → 레일에 Channels만, 빈 자리 없음.

## 시나리오 2 — 팀 전환 (SC-002, US2)

1. 팀 2곳 이상 가입 사용자로 채널 화면에서 팀명 드롭다운 오픈.
2. **기대**: 상단에 "내 팀" 목록 + 현재 팀 체크. 다른 팀 클릭 → 그 팀 채널로
   전환 (클릭 2번, SC-002).
3. Boards 화면으로 이동 후 레일 상단 팀 버튼 클릭 → 같은 팀 목록 → 다른 팀
   선택 → **Boards에 머문 채** 그 팀의 보드로 바뀐다.
4. Playbooks에서도 팀 전환 후 콘텐츠가 새 팀 기준으로 바뀌는지 확인.
5. 팀 1곳 사용자: 목록 1건 + 가입/생성 항목. 권한 없는 계정: 가입/생성 항목
   미노출.

## 시나리오 3 — 관리 메뉴 이전 (SC-004, US3)

1. 시스템 관리자로 팀명 드롭다운 오픈.
2. **기대**: 하단에 시스템 콘솔·통합·사용자 그룹·(설정에 따라 마켓플레이스·앱
   다운로드)·OKR.Best 정보 항목.
3. 각 항목 클릭 → 기존 product switcher에서 가던 곳과 동일한 화면.
4. 일반 사용자로 반복 → 권한 없는 항목 미노출(SC-004). 정보 항목 등 전체 공개
   항목은 보임.

## 시나리오 4 — 기존 동작 보존 (FR-009)

1. 채널 사이드바를 접고 레일에 호버 → peek으로 임시 공개, 벗어나면 닫힘.
2. 레일 최하단 프로필 버튼 → 사용자 계정 메뉴 열림 (상태 변경·설정·로그아웃).
3. 레일 플러그인 슬롯(있다면) 표시 유지.

## 시나리오 5 — 접근성 (SC-006)

- 레일의 모든 버튼·팀 목록 항목을 키보드로 순회하며 보조기술 이름이 읽히는지
  확인 (브라우저 접근성 트리 또는 Playwright snapshot으로 이름 없는 버튼 0건).

## 자동화 게이트 (머지 전)

```bash
cd webapp && npm run check && npm run check-types && npm run test
# 기준선 diff로 판정 — 구현 시작 전 저장한 목록과 비교
```
