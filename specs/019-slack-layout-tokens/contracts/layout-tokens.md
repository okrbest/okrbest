# 계약: 레이아웃 토큰

이 토큰을 정의하는 쪽(019)과 소비하는 쪽(후속 ②③④ 기능, 이후 모든 okrbest
스타일 작업)이 지키는 조건이다.

## 이름 규칙

- 네임스페이스는 `--okr-` 고정. 계열은 4+1개:
  `--okr-space-{1..7}` · `--okr-icon-{inline,aux,toolbar,main}` ·
  `--okr-target-{s,m,l}` · `--okr-row-{sidebar,menu,input}` · `--okr-radius-ms`
- 정의 위치는 `sass/okrbest/_tokens.scss` 한 곳. 다른 파일에서 `--okr-space-*`
  등을 재정의하지 않는다.
- upstream 변수(`--radius-*`, `--elevation-*` 등)와 이름·역할이 겹치는 토큰을
  만들지 않는다.

## 불변 조건

1. **색 불변**: 이 토큰 체계는 길이만 다룬다. 색·투명도 값을 담지 않는다.
2. **무변화 치환**: 019의 치환은 현재 렌더 값과 같은 토큰으로만 한다 —
   치환 전후 computed px 차이 0. 값을 바꾸는 작업은 영역 기능(②③④)의 몫이다.
3. **그리드 집행**: 대상 SCSS의 px 리터럴은 토큰 값이거나 예외 목록 값이어야
   한다. 검사 스크립트(`scripts/okrbest/check-layout-tokens.sh`)가 비0 종료로
   위반을 알린다.
4. **예외는 등록제**: 비그리드 값은 data-model.md 예외 표에 용도와 함께
   등록된 것만 허용한다.

## 소비자 계약 (후속 기능이 따를 것)

- 새 간격·크기·행 높이가 필요하면 먼저 기준표에서 고른다. 없으면 실측 근거와
  함께 기준표에 단계를 추가한 뒤 쓴다 — 코드에 리터럴을 먼저 쓰지 않는다.
- 아이콘↔폰트 짝은 균형표를 따른다: 글자 12→아이콘 14, 13→16, 15→18,
  18→20 (최종 표는 사용 가이드 문서가 정본).
- 검사 스크립트를 접촉 게이트에 포함한다 (위반 0 유지).

## 검증 방법

- 토큰 정의 완전성: SC-001 대조표 (후속 영역 필요 수치 ↔ 기준표).
- 무변화: 치환 지점 셀렉터별 전/후 실측 JSON diff 공란 (quickstart 절차).
- 그리드 집행: 검사 스크립트 통과 + 위반 샘플 RED 확인 (원칙 III).
