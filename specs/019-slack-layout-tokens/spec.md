# Feature Specification: Slack 레이아웃 리듬 공통 토큰 체계

**Feature Branch**: `019-slack-layout-tokens`

**Created**: 2026-10-11

**Status**: Draft

**Input**: User description: "Slack 레이아웃 리듬 공통 토큰 체계 — 전체 디자인 품질 개선 로드맵(①공통 체계 → ②헤더·툴바 → ③사이드바 → ④메시지 영역)의 1단계. 색·브랜드는 손대지 않고 레이아웃 숫자만 정본화한다."

## 배경과 로드맵 위치

사용자가 체감하는 "낮은 디자인 품질"의 주범은 색이 아니라 숫자다 — 화면마다
간격(6·7·10·12px)과 아이콘 크기(24/32px)가 제각각이라 리듬이 없다.
이 기능은 전체 개선 로드맵의 1단계로, Slack을 실측해 **간격·크기·비례의
기준표(토큰)**를 세우고 기존 임의 수치를 치환한다. 색은 014 체계(현행 톤)를
그대로 쓴다 — Slack 브랜드색(Aubergine) 차용은 명시적으로 제외한다.

후속 기능이 이 토큰을 소비한다: ②헤더·툴바류 → ③좌측 사이드바 → ④메시지 영역.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 레이아웃 기준표가 한곳에 있다 (Priority: P1)

화면을 만들거나 고치는 작업자가 간격·아이콘 크기·행 높이를 정할 때,
감이 아니라 단일 기준표에서 값을 고른다. 기준표의 모든 값에는 실측 근거
(Slack 데스크톱 실측 또는 Figma Slack UI Kit 실측)가 붙어 있다.

**Why this priority**: 기준표 없이는 후속 세 영역 작업이 다시 임의 수치를
만든다. 로드맵 전체의 전제다.

**Independent Test**: 후속 세 영역(헤더·툴바, 사이드바, 메시지)이 필요로
하는 레이아웃 수치 목록을 만들고, 전부 기준표에서 선택 가능한지 대조한다.

**Acceptance Scenarios**:

1. **Given** 간격 기준표, **When** 임의 UI 요소 사이 간격을 정할 때,
   **Then** 4px 그리드 단계(4/8/12/16/20/24/32) 중에서 고를 수 있고 각
   단계의 용도 설명이 있다.
2. **Given** 아이콘 크기 기준표, **When** 글자 옆에 아이콘을 둘 때,
   **Then** 글자 크기(12/13/15/18)별로 짝이 되는 아이콘 크기와 버튼 타깃
   크기가 정해져 있다.
3. **Given** 행 높이 기준표, **When** 목록형 UI(사이드바 행·메뉴 행)를
   만들 때, **Then** 표준 행 높이를 기준표에서 고를 수 있다.
4. **Given** 기준표의 아무 값, **When** 근거를 물을 때, **Then** 출처
   (Slack 실측 좌표/Figma 노드)와 실측 수치가 기록돼 있다.

---

### User Story 2 - 기존 임의 수치가 기준표 값으로 바뀐다 (Priority: P2)

기존 okrbest 커스텀 스타일에 박힌 임의 수치(모서리 6px·7px 등)가 기준표
토큰으로 치환된다. 화면은 달라지지 않는다 — 이 단계의 치환은 정리이지
리디자인이 아니다.

**Why this priority**: 기준표가 실제 코드에서 작동함을 증명하는 최소 적용이다.
치환 과정에서 시각 회귀가 없어야 후속 영역 작업도 같은 방식을 신뢰할 수 있다.

**Independent Test**: 치환 전후 해당 요소들의 실측 px 값을 비교한다 — 동일해야
한다.

**Acceptance Scenarios**:

1. **Given** okrbest 커스텀 스타일의 하드코딩 수치 목록, **When** 치환을
   마쳤을 때, **Then** 목록의 전 항목이 토큰 참조로 바뀌어 있다.
2. **Given** 치환 전 화면 실측값, **When** 치환 후 같은 지점을 실측하면,
   **Then** px 값이 동일하다 (시각 회귀 0).

---

### User Story 3 - 사용 규칙이 문서로 남는다 (Priority: P3)

후속 영역 작업자가 기준표를 올바르게 쓰도록, 적용 규칙(아이콘↔폰트 균형표,
간격 단계 선택 기준, 예외 처리)을 담은 사용 가이드가 저장소에 남는다.

**Why this priority**: 표만 있고 규칙이 없으면 해석이 갈라진다. 다만 P1·P2가
끝나야 쓸 내용이 확정된다.

**Independent Test**: 가이드만 읽고 샘플 상황(예: 13px 라벨 옆 아이콘 버튼)
의 수치를 정했을 때 기준표와 같은 답이 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용 가이드, **When** 글자 크기만 주어진 상황에서, **Then**
   아이콘 크기·버튼 타깃·간격을 가이드의 규칙만으로 결정할 수 있다.
2. **Given** 4px 그리드에 없는 기존 값(예: 2px 테두리), **When** 가이드의
   예외 절을 보면, **Then** 예외로 허용되는 경우와 등록 방법이 적혀 있다.

---

### Edge Cases

- Figma Kit 수치와 실제 Slack 실측이 다를 때: 실제 Slack 데스크톱 실측을
  우선하고, 차이를 근거 기록에 남긴다.
- 4px 그리드에 떨어지지 않는 값이 필요한 경우(1px 구분선, 2px 포커스 링 등):
  예외 목록에 용도와 함께 등록한다. 등록 없는 비그리드 값은 금지.
- upstream(Mattermost) 전역 수치는 치환 대상이 아니다 — 이 단계의 치환
  범위는 okrbest 커스텀 스타일로 한정한다 (upstream 충돌 비용 방지).
- 사용자 지정 테마: 이 기능은 색을 다루지 않으므로 테마와 무관하다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 간격 기준표를 정의한다 — 4px 그리드 단계(4/8/12/16/20/24/32)와
  단계별 용도. 각 값은 Slack 실측 근거를 가진다.
- **FR-002**: 아이콘 크기 단계를 정의한다 — 인라인/보조/툴바/주요 용도별
  크기와 버튼 타깃(24/28/32) 규칙.
- **FR-003**: 아이콘↔폰트 균형표를 정의한다 — 014 타입 스케일(12/13/15/18)의
  각 단계에 짝이 되는 아이콘 크기·버튼 타깃.
- **FR-004**: 행 높이 기준표를 정의한다 — 사이드바 행·메뉴 행·헤더류 높이의
  표준값.
- **FR-005**: 모든 기준값에 실측 근거(출처와 수치)를 기록한다 — Slack
  데스크톱 실측 또는 Figma Slack UI Kit 노드 실측.
- **FR-006**: okrbest 커스텀 스타일의 레이아웃 하드코딩을 전수 조사해 목록을
  만들고, 전 항목을 기준표 토큰으로 치환한다. 치환은 현재 렌더 값을 유지한다
  (시각 회귀 0).
- **FR-007**: 색·폰트·브랜드 요소는 변경하지 않는다. Slack 브랜드색 차용 금지.
- **FR-008**: 사용 가이드를 저장소에 남긴다 — 기준표, 균형표, 예외 규칙,
  후속 영역 작업자가 따를 선택 절차.
- **FR-009**: 4px 그리드 밖의 값은 예외 목록 등록 없이는 쓸 수 없다는 규칙을
  세우고, 기존 예외(1px 선 등)를 등록한다.

### Key Entities

- **레이아웃 토큰**: 이름, 값(px), 용도, 실측 근거(출처·원값)로 구성되는
  기준표의 한 행. 분류: 간격 / 아이콘 크기 / 버튼 타깃 / 행 높이 / 예외.
- **치환 대상 목록**: okrbest 커스텀 스타일에서 발견한 하드코딩 수치의 전수
  목록 — 위치, 현재 값, 대응 토큰, 치환 후 실측 결과.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 후속 세 영역(헤더·툴바, 사이드바, 메시지)이 필요로 하는
  레이아웃 수치 유형을 나열한 대조표에서, 100%가 기준표의 값으로 선택
  가능하다 (빠진 단계 0).
- **SC-002**: 치환 대상 목록의 전 항목이 토큰 참조로 바뀌고, 치환 전후 해당
  요소의 실측 px 값 차이가 0이다.
- **SC-003**: 기준표의 모든 값에 실측 근거가 1건 이상 붙어 있다 (근거 없는
  값 0).
- **SC-004**: okrbest 커스텀 스타일 안에서 기준표·예외 목록 밖의 레이아웃
  수치가 0건이다 (전수 검사로 확인).
- **SC-005**: 샘플 상황 3건(글자 크기만 주어진 아이콘 버튼 등)을 가이드만
  보고 풀었을 때 기준표와 같은 답이 나온다 (3/3).

## Assumptions

- 밀도 기준은 Slack 데스크톱 실측 그대로다 — 현재보다 약간 조밀해지는
  방향을 사용자가 수용했다 (브레인스토밍 확인).
- 영역별 리디자인(헤더·사이드바·메시지에 새 수치 적용)은 이 기능의 범위
  밖이다 — 이 단계는 기준표 수립과 무변화 치환까지만.
- 치환 범위는 okrbest 커스텀 스타일로 한정한다. upstream 파일의 수치는
  후속 영역 기능에서 해당 화면을 손볼 때 함께 다룬다.
- 기존 upstream 전역 변수 체계(모서리 반경 등)는 유지하고, 빠진 단계만
  okrbest 네임스페이스로 보탠다.
- 선행 분석 노트(`specs/014-slack-design-benchmark/figma-token-audit.md`,
  미커밋)는 이 기능 브랜치에 함께 커밋한다.
- Figma 파일 접근은 확인 완료 상태다 (토큰·실측 추출 가능).
