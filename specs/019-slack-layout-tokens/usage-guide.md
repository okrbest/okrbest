# 사용 가이드: 레이아웃 리듬 토큰

okrbest 화면을 만들거나 고칠 때 간격·아이콘·버튼·행 수치를 정하는 절차다.
값의 정본은 [data-model.md](data-model.md), 실측 근거는
[measurements.md](measurements.md). 색·폰트는 014 체계를 따른다 — 이 가이드는
길이만 다룬다.

## 기준표 요약

| 계열 | 토큰 | 값 |
|---|---|---|
| 간격 | `--okr-space-1..7` | 4 / 8 / 12 / 16 / 20 / 24 / 32 |
| 아이콘 | `--okr-icon-{inline,aux,toolbar,main}` | 14 / 16 / 18 / 20 |
| 버튼 타깃 | `--okr-target-{s,m,l}` | 24 / 28 / 32 |
| 행 높이 | `--okr-row-{sidebar,menu,input}` | 28 / 28 / 28 |
| 모서리 보강 | `--okr-radius-ms` | 6 (upstream `--radius-s` 4·`--radius-m` 8과 병용) |

## 수치 선택 절차

1. **간격** — 아이콘↔글자·헤더 인접 요소는 `space-1`(4), 형제 버튼·행 내부는
   `space-2`(8), 패널 패딩은 `space-3`(12), 섹션 패딩은 `space-4`(16), 본문
   좌우는 `space-5`(20), 메뉴 좌우·들여쓰기는 `space-6`(24), 큰 구획은
   `space-7`(32).
2. **아이콘과 타깃** — 글자 크기에서 균형표로 정한다:

   | 글자 | 인라인 아이콘 | 버튼 글리프 → 타깃 |
   |---|---|---|
   | 12px | 14 | 14 → 24 |
   | 13px | 16 | 16 → 28 |
   | 15px | 16 | 20 → 28~32 |
   | 18px | 20 | 20 → 32 |

   예: 13px 라벨 옆 아이콘 버튼 = 아이콘 16(`--okr-icon-aux`) + 타깃 28
   (`--okr-target-m`) + 이웃과 간격 8(`--okr-space-2`).
3. **행 높이** — 목록형 UI(사이드바 행·메뉴 행·검색창)는 28. 더 큰 행이
   필요하면 기준표에 단계를 추가(실측 근거 필수)한 뒤 쓴다.
4. **없는 값이 필요하면** — 코드에 리터럴을 먼저 쓰지 않는다. measurements.md
   에 실측 근거를 적고 data-model 기준표에 단계를 추가한 뒤 `_tokens.scss`에
   반영한다.

## 리터럴 허용과 예외

- **그리드 위 리터럴**: 4의 배수 값은 리터럴로 써도 계약 위반이 아니다
  (축약형 `padding: 8px 12px`, 음수 `-8px` 등). 단독 선언이고 토큰 단계와
  의미가 같으면 `var()` 참조를 권장한다.
- **비그리드 값**: 1·2px(선·링)와 등록 예외(5/6/7/10/14 — data-model 7절)만
  허용. 새 비그리드 값은 용도와 함께 7절에 등록해야 한다 — 용도 없는 등록
  불가. 예: 1px 구분선은 위반이 아니다(전역 예외).
- **범위 밖 속성**: font-size·line-height(014 타입 체계), box-shadow(효과),
  아바타 같은 컴포넌트 고유 치수(36 등)는 이 토큰의 대상이 아니다.

## 검사

```bash
bash scripts/okrbest/check-layout-tokens.sh
```

okrbest 커스텀 SCSS의 레이아웃 px 리터럴을 전수 검사한다 — 위반 시 파일:줄
출력과 비0 종료. 접촉 게이트와 함께 돌려 위반 0을 유지한다. 새 okrbest
커스텀 SCSS 파일을 만들면 스크립트의 `TARGETS`에 추가한다.
