# Feature Specification: 읽지 않은 항목 행 뱃지 구분 병기

**Feature Branch**: `027-unreads-split-badge`

**Created**: 2026-10-13

**Status**: Draft

**Input**: User description: "읽지 않은 항목 우측에 숫자 라벨을 멘션/DM/GM과 일반 메시지 구분별로 병기 표시 (두 가지 다 있으면 각각의 숫자 라벨 나란히 표시)"

## 현재 동작

사이드바 "읽지 않은 항목" 행의 숫자 뱃지는 멘션·DM·GM 합계만 보여준다.
일반 채널의 미읽음 메시지만 있으면 숫자 없이 행 제목만 굵게 바뀐다.
사용자는 긴급한 알림(멘션·DM·GM)과 일반 미읽음을 구분할 수 없고,
일반 미읽음의 규모는 행을 눌러 들어가야 안다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 두 수치를 병기한다 (Priority: P1)

멘션(또는 DM·GM)과 일반 채널 미읽음이 동시에 있을 때, "읽지 않은 항목" 행
우측에 뱃지 두 개가 나란히 보인다. 긴급 수와 일반 수를 클릭 없이 한눈에
구분한다.

**Why this priority**: 이 기능의 핵심 요구다. 긴급/일반 구분이 안 되는
현재 표시를 바로잡는다.

**Independent Test**: 멘션 1건 이상 + 일반 미읽음 1건 이상 상태를 만들고
행 우측에 뱃지 두 개가 각각의 수로 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 현재 팀에 멘션 3건과 일반 채널 미읽음 메시지 12건이 있다,
   **When** 사이드바를 본다,
   **Then** "읽지 않은 항목" 행 우측에 일반 뱃지 12와 멘션 뱃지 3이 나란히 보인다.
2. **Given** 뱃지 두 개가 표시된 상태다,
   **When** 멘션을 모두 읽는다,
   **Then** 멘션 뱃지만 사라지고 일반 뱃지는 남는다.

---

### User Story 2 - 일반 미읽음만 있어도 수치를 보여준다 (Priority: P2)

멘션이 없고 일반 미읽음만 있을 때, 지금은 숫자가 전혀 없다. 일반 뱃지
하나가 단독으로 표시되어 미읽음 규모를 바로 안다.

**Why this priority**: 현재 불가능했던 정보가 새로 생기는 부분이라 체감
개선이 가장 크다. 다만 US1이 성립해야 의미가 있는 파생 동작이다.

**Independent Test**: 멘션 0건 + 일반 미읽음 수건 상태에서 일반 뱃지
하나만 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 멘션이 0건이고 일반 미읽음 메시지가 5건이다,
   **When** 사이드바를 본다,
   **Then** 일반 뱃지 5 하나만 보이고 멘션 뱃지는 없다.

---

### User Story 3 - 멘션만 있으면 기존과 같다 (Priority: P3)

멘션·DM·GM만 있고 일반 미읽음이 없으면 기존 강조색 멘션 뱃지 하나만
표시된다. 기존 사용자 경험이 달라지지 않는다.

**Why this priority**: 회귀 방지 목적이다. 새 동작이 아니라 기존 동작의
보존을 검증한다.

**Independent Test**: 멘션만 있는 상태에서 기존과 동일한 멘션 뱃지 하나만
보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 멘션 2건만 있고 일반 미읽음이 없다,
   **When** 사이드바를 본다,
   **Then** 멘션 뱃지 2 하나만 기존 위치·기존 모양으로 보인다.

---

### Edge Cases

- 두 수치가 모두 0이면? 숫자 뱃지를 표시하지 않고, 행 굵게 처리도 하지
  않는다 (기존 동작 유지).
- 수치가 100 이상이면? 일반 뱃지는 99로 캡한다 (spec 025 규칙). 멘션 뱃지는 기존 표기를 유지한다.
- 뮤트한 채널은? 기존 미읽음 집계 규칙을 그대로 따라 수치에서 빠진다.
- 사이드바 폭이 좁으면? 뱃지는 줄어들지 않고 행 제목이 말줄임된다.
- 테마를 전환하면? Slate·Onyx 어느 쪽에서도 두 뱃지의 숫자가 배경과
  구분되게 보인다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: "읽지 않은 항목" 행은 멘션·DM·GM 수와 일반 채널 미읽음
  메시지 수를 별개의 숫자 뱃지로 표시한다.
- **FR-002**: 두 수치가 모두 양수면 뱃지 두 개를 나란히 표시한다. 멘션
  뱃지가 오른쪽 끝(기존 위치)을 지키고, 일반 뱃지가 그 왼쪽에 선다.
- **FR-003**: 한 수치만 양수면 해당 뱃지 하나만 표시한다.
- **FR-004**: 표기 규칙은 spec 025와 일치한다 — 멘션 뱃지는 기존 강조색
  표기, 일반 뱃지는 파랑 틴트 보조 뱃지 표기와 99 캡(100 이상이면 99 표시).
- **FR-005**: 두 수치가 모두 0이면 숫자 뱃지를 표시하지 않는다.
- **FR-006**: 수치는 현재 팀 범위로 집계하고, 뮤트 제외 등 기존 미읽음
  판정 규칙과 일치한다.
- **FR-007**: 두 테마(Slate·Onyx)에서 각 뱃지의 글자가 식별 가능한 대비를
  유지한다.

### Key Entities

- **미읽음 집계**: 현재 팀의 두 수치 — ① 멘션·DM·GM 수(긴급), ② 일반
  채널 미읽음 메시지 수. 서로 성격이 다른 수치로, 합산하지 않고 병기한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 멘션 3건 + 일반 미읽음 12건 상태에서 행 우측에 뱃지 두 개가
  각각 3과 12로 보인다 (실주행 스크린샷으로 확인).
- **SC-002**: 일반 미읽음만 있는 상태에서 행에 수치가 표시된다 — 기존에는
  행 진입 없이 알 수 없던 정보를 클릭 0회로 확인한다.
- **SC-003**: 멘션만 있는 상태의 표시가 변경 전과 동일하다 (회귀 0건).
- **SC-004**: 각 뱃지의 글자 대 배경 대비가 두 테마 모두 3:1 이상이다 (실측).
- **SC-005**: 일반 미읽음 100건 이상에서 일반 뱃지가 99로 표시된다.

## Assumptions

- "멘션·DM·GM 수"는 기존 미읽음 상태 집계가 주는 멘션 합계를 그대로 쓴다.
  DM·GM의 새 메시지는 기존 집계 규칙상 이 합계에 이미 포함된다.
- 일반 미읽음 수는 메시지 수 합계다 (채널 수가 아니다). 멘션이 달린
  메시지도 메시지이므로 두 수치는 일부 겹칠 수 있다 — 합산 표기가 아니라
  병기이므로 허용한다.
- 뱃지 순서는 일반(파랑 틴트)이 왼쪽, 멘션(강조색)이 오른쪽 끝이다. 멘션
  뱃지의 기존 위치를 유지해 시선 이동을 줄인다.
- 범위는 사이드바 "읽지 않은 항목" 행 한 곳이다. 스레드·최근 멘션·보관된
  메시지 행, 채널 행, 읽지 않은 항목 페이지 내부는 범위 밖이다 (채널 행과
  페이지 머리글은 spec 025가 이미 다뤘다).
- spec 025의 보조 뱃지 표기(색·캡 규칙)를 재사용할 수 있는 상태다.
