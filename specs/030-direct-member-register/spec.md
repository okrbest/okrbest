# Feature Specification: 팀 멤버 직접 등록

**Feature Branch**: `030-direct-member-register`

**Created**: 2026-10-23

**Status**: Draft

**Input**: User description: "팀 관리자가 초대 코드를 보내는 대신 팀 멤버를 직접 등록한다. 초대 링크가 퍼지면 원하지 않는 사용자의 팀 가입을 통제할 수 없어서, 가입의 주도권을 팀 관리자에게 두려는 요구다. 서버 개설 초기에는 CSV로 일괄 등록하고, 운영 중에는 입사자를 한 명씩 등록한다. 항목은 이메일·이름·임시 비밀번호이고 이메일을 로그인 아이디로 쓴다. 멤버는 전달받은 임시 비밀번호로 로그인한 뒤 비밀번호를 본인이 원할 때 바꾼다. 기존 초대 코드·초대 링크 경로는 그대로 두고, 기존 '구성원 초대' 모달 안에 직접 등록 방식을 추가한다. 시스템 콘솔에 기능 사용 허용 설정을 둔다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 입사자 한 명을 직접 등록한다 (Priority: P1)

팀에 입사자가 생기면 팀 관리자가 "구성원 초대" 모달을 열어 "직접 등록" 방식을
고르고, 이메일·이름·임시 비밀번호를 입력해 계정을 만든다. 등록이 끝나면 그
계정은 이미 팀에 소속되어 있다. 관리자는 이메일과 임시 비밀번호를 사내 연락
수단으로 입사자에게 전달하고, 입사자는 그 정보로 로그인해 바로 팀 채널에서
일을 시작한다.

**Why this priority**: 기능의 핵심 가치가 이 흐름 하나에 다 들어 있다. 초대
링크 없이 관리자가 가입을 통제한다는 요구를 가장 작은 단위로 충족하며, 이것만
구현해도 운영 중인 팀의 입사자 온보딩 문제가 풀린다.

**Independent Test**: 팀 관리자 계정으로 모달에서 멤버 한 명을 등록한 뒤, 그
이메일과 임시 비밀번호로 로그인해 팀 채널 목록이 보이는지 확인하면 끝까지
검증된다.

**Acceptance Scenarios**:

1. **Given** 직접 등록 설정이 켜진 서버에서 팀 관리자가 "구성원 초대" 모달을 열었을 때, **When** "직접 등록"에서 이메일·이름·임시 비밀번호를 입력하고 등록하면, **Then** 계정이 생성되고 해당 팀의 멤버로 추가되며 성공 결과가 표시된다.
2. **Given** 등록이 완료된 직후, **When** 멤버가 전달받은 이메일과 임시 비밀번호로 로그인하면, **Then** 추가 절차 없이 로그인에 성공하고 해당 팀에 소속된 상태로 시작한다.
3. **Given** 로그인한 멤버가 비밀번호를 바꾸지 않은 상태일 때, **When** 서비스를 계속 사용하면, **Then** 비밀번호 변경을 강제당하지 않으며 원할 때 계정 설정에서 직접 바꿀 수 있다.
4. **Given** 이미 서버에 계정이 있는 이메일을 입력했을 때, **When** 등록을 실행하면, **Then** 계정은 새로 만들지 않고 기존 계정을 팀에 추가하며 그 사실을 결과에 표시한다.
5. **Given** 임시 비밀번호 입력란에서, **When** "자동 생성"을 누르면, **Then** 서버의 비밀번호 정책을 충족하는 임시 비밀번호가 채워진다.

### User Story 2 - CSV로 팀 멤버를 일괄 등록한다 (Priority: P2)

서버 개설 초기에 팀 관리자가 팀원 명단을 CSV 파일(열: 이메일, 이름,
임시비밀번호)로 만들어 업로드한다. 업로드하면 행별 검증 결과를 먼저 보여 주고,
관리자가 확인한 뒤 검증을 통과한 행만 등록한다. 등록이 끝나면 행별 성공·실패와
임시 비밀번호가 담긴 결과 CSV를 내려받아 멤버들에게 계정 정보를 전달한다.

**Why this priority**: 서버 개설 초기의 일괄 온보딩 요구를 해결한다. 한 명
등록(US1)이 있으면 수동 반복으로도 가능하므로 P1보다는 낮지만, 수십 명 규모의
팀에서는 이 기능이 있어야 실용적이다.

**Independent Test**: 정상 행과 오류 행이 섞인 CSV를 업로드해, 미리보기가 행별
검증 결과를 구분해 보여 주는지, 등록 후 정상 행 멤버들이 모두 로그인 가능한지,
결과 CSV에 행별 결과와 임시 비밀번호가 담기는지 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 직접 등록의 "CSV 일괄 등록" 탭에서, **When** 템플릿 내려받기를 누르면, **Then** 열 구성(이메일, 이름, 임시비밀번호)이 담긴 CSV 템플릿 파일을 받는다.
2. **Given** 작성한 CSV를 업로드했을 때, **When** 파일 해석이 끝나면, **Then** 등록 실행 전에 행별 미리보기가 표시되고 각 행에 검증 결과(정상, 형식 오류, 중복 등)가 붙는다.
3. **Given** 정상 행과 오류 행이 섞인 미리보기에서, **When** 등록을 실행하면, **Then** 정상 행만 등록되고 오류 행은 사유와 함께 제외된다.
4. **Given** 등록이 끝난 결과 화면에서, **When** 결과 CSV를 내려받으면, **Then** 행별 성공·실패 사유와 임시 비밀번호가 담긴 파일을 받는다.
5. **Given** CSV 안에 같은 이메일이 두 번 들어 있을 때, **When** 미리보기를 확인하면, **Then** 중복 행이 오류로 표시되고 첫 행만 정상으로 처리된다.

### User Story 3 - 시스템 콘솔에서 기능을 켜고 끈다 (Priority: P3)

시스템 관리자가 시스템 콘솔에서 "팀 멤버 직접 등록 허용" 설정을 켜거나 끈다.
설정이 꺼져 있으면 모든 팀에서 직접 등록 화면이 보이지 않고, 서버도 직접 등록
요청을 거부한다. 기본값은 꺼짐이다.

**Why this priority**: 기능의 노출을 서버 운영 정책으로 통제하는 안전장치다.
US1·US2가 있어야 의미가 생기므로 우선순위는 마지막이지만, 출시 전에는 반드시
함께 있어야 한다.

**Independent Test**: 설정을 끈 상태에서 팀 관리자에게 직접 등록 화면이 보이지
않는지, 화면을 우회한 직접 요청도 거부되는지, 설정을 켜면 다시 쓸 수 있는지
확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 설정이 꺼진 서버에서, **When** 팀 관리자가 "구성원 초대" 모달을 열면, **Then** "직접 등록" 방식이 보이지 않고 기존 초대 화면만 보인다.
2. **Given** 설정이 꺼진 서버에서, **When** 화면을 거치지 않고 직접 등록 요청을 보내면, **Then** 서버가 요청을 거부한다.
3. **Given** 시스템 관리자가 설정을 켠 뒤, **When** 팀 관리자가 모달을 다시 열면, **Then** "직접 등록" 방식이 나타난다.
4. **Given** 설정이 켜진 서버에서, **When** 팀 관리자가 아닌 일반 멤버가 모달을 열면, **Then** "직접 등록" 방식이 보이지 않고, 직접 요청도 거부된다.

---

### Edge Cases

- 이미 그 팀의 멤버인 기존 계정 이메일을 등록하면 어떻게 되나? → 새로 할 일이 없음을 결과에 표시하고 실패로 집계하지 않는다.
- 임시 비밀번호가 서버의 비밀번호 정책(길이·문자 구성)에 미달하면? → 해당 행을 등록하지 않고 사유를 표시한다.
- 이메일 형식이 잘못된 행, 필수 열이 비어 있는 행은? → 미리보기에서 오류로 표시하고 등록 대상에서 제외한다.
- 자동 생성할 내부 사용자명이 기존 사용자명과 겹치면? → 뒤에 숫자를 붙여 겹치지 않는 이름을 만들며, 등록이 이 때문에 실패하지 않는다.
- 엑셀에서 저장한 CSV(BOM 포함, 다른 인코딩)를 올리면? → UTF-8(BOM 포함)을 수용하고, 해석할 수 없는 파일은 파일 단위 오류로 안내한다.
- 행 수가 허용 상한을 넘는 CSV를 올리면? → 등록을 시작하지 않고 상한과 함께 안내한다.
- 등록 도중 일부 행이 서버 오류로 실패하면? → 성공한 행은 유지하고, 실패한 행만 사유와 함께 결과에 표시한다.
- 게스트 계정으로 존재하는 이메일을 등록하면? → 일반 멤버로 승격하지 않고 오류로 표시한다(승격은 시스템 관리자의 일).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템 콘솔에 "팀 멤버 직접 등록 허용" 설정을 둔다. 기본값은 꺼짐이며, 꺼져 있으면 화면 노출과 서버 처리 양쪽을 모두 막는다.
- **FR-002**: 설정이 켜져 있고 사용자가 해당 팀의 팀 관리자 또는 시스템 관리자일 때만, 기존 "구성원 초대" 모달에 "직접 등록" 방식을 추가로 보여 준다. 그 외 사용자에게는 기존 초대 화면만 보인다.
- **FR-003**: "직접 등록 — 한 명 등록"에서 이메일·이름·임시 비밀번호를 입력받아 계정을 만들고, 같은 동작 안에서 해당 팀의 멤버로 추가한다. 계정 생성과 팀 추가 중 하나만 성공한 상태로 끝나지 않는다.
- **FR-004**: 임시 비밀번호는 관리자가 직접 입력하거나 자동 생성 버튼으로 채울 수 있다. 자동 생성 값은 서버의 비밀번호 정책을 충족한다.
- **FR-005**: 등록된 멤버는 이메일과 임시 비밀번호만으로 로그인할 수 있다. 내부 사용자명은 이메일의 `@` 앞부분으로 자동 생성하고, 겹치면 숫자를 붙여 유일하게 만든다.
- **FR-006**: 직접 등록된 멤버에게 첫 로그인 시 비밀번호 변경을 강제하지 않는다. 변경 시점은 본인이 정한다.
- **FR-007**: "직접 등록 — CSV 일괄 등록"에서 열 구성(이메일, 이름, 임시비밀번호)이 담긴 CSV 템플릿을 내려받을 수 있다.
- **FR-008**: 업로드한 CSV는 등록 실행 전에 행별 검증 미리보기를 보여 준다. 검증은 이메일 형식, 필수 값 존재, 비밀번호 정책, 파일 내 중복을 가린다. 기존 계정 여부는 미리보기가 아니라 등록 결과에서 구분해 표시한다(FR-010) — 미리보기에서 확인하려면 행마다 서버 조회가 필요하고, 이메일 노출 설정에 따라 팀 관리자의 조회가 거부될 수 있어 신뢰할 수 없다.
- **FR-009**: 등록 실행 시 검증을 통과한 행만 처리하고, 행 단위로 독립적으로 처리한다. 일부 행이 실패해도 나머지 행의 등록은 유지된다.
- **FR-010**: 이미 계정이 있는 이메일은 계정을 새로 만들지 않고 해당 팀에 추가만 하며, 결과에 "기존 계정을 팀에 추가"로 구분해 표시한다. 이미 팀 멤버라면 할 일이 없음을 표시한다.
- **FR-011**: 등록이 끝나면 행별 성공·실패와 사유를 화면에 표시하고, 임시 비밀번호가 포함된 결과 CSV를 내려받을 수 있다.
- **FR-012**: 서버는 직접 등록 요청을 전용 권한으로 통제한다. 설정이 꺼져 있거나 권한이 없는 요청은 화면 우회 여부와 관계없이 거부한다.
- **FR-013**: 직접 등록으로 생긴 계정 생성·팀 추가는 누가 언제 누구를 등록했는지 감사 기록으로 남긴다.
- **FR-014**: 기존 초대 코드·초대 링크·이메일 초대 경로는 동작과 화면 모두 바꾸지 않는다.
- **FR-015**: CSV 한 번에 처리할 수 있는 행 수에 상한을 두고, 상한을 넘는 파일은 등록을 시작하기 전에 안내한다.

### Key Entities

- **직접 등록 요청 행**: 멤버 한 명을 등록하는 데 필요한 값의 묶음. 이메일(로그인 아이디), 이름(표시 이름), 임시 비밀번호로 구성된다. 한 명 등록은 행 하나, CSV 등록은 행 여러 개다.
- **행별 등록 결과**: 각 행의 처리 결과. 상태(계정 생성+팀 추가, 기존 계정 팀 추가, 이미 팀 멤버, 실패)와 실패 사유를 가진다. 결과 CSV의 원천이 된다.
- **직접 등록 허용 설정**: 서버 전체에 적용되는 켬/끔 값. 시스템 콘솔에서 시스템 관리자가 바꾼다.
- **직접 등록 권한**: 팀 범위에서 직접 등록을 허용하는 권한. 기본으로 팀 관리자에게 부여된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 팀 관리자가 입사자 한 명을 모달에서 등록 완료하기까지 1분이 걸리지 않는다.
- **SC-002**: 100행짜리 CSV를 업로드해 미리보기 확인과 등록 실행, 결과 확인까지 5분 안에 끝난다.
- **SC-003**: 직접 등록된 멤버는 전달받은 이메일과 임시 비밀번호만으로 첫 로그인에 성공하고, 추가 승인·인증 절차 없이 곧바로 소속 팀의 채널 화면에 도달한다.
- **SC-004**: 설정이 꺼진 서버에서는 화면·우회 요청 어느 경로로도 직접 등록이 성공하지 않는다(거부율 100%).
- **SC-005**: 오류 행이 섞인 CSV에서 정상 행은 전부 등록되고, 오류 행은 전부 사유와 함께 표시된다. 결과 표시가 누락되는 행은 없다.
- **SC-006**: 기능 추가 후에도 기존 초대 경로(이메일 초대, 초대 링크)의 동작이 이전과 같다.

## Assumptions

- 임시 비밀번호는 시스템 밖 경로(사내 연락 수단)로 전달한다. 시스템은 등록 안내 메일을 보내지 않는다.
- 이메일은 조직이 파악하고 있는 실제 주소라고 가정하되, 수신 가능 여부는 검증하지 않는다. 직접 등록된 계정은 별도의 이메일 인증 절차를 요구받지 않는다.
- 직접 등록 대상은 일반 멤버 계정이다. 게스트 계정 등록은 범위 밖이다.
- 이메일/비밀번호 로그인을 쓰는 서버를 전제한다. 외부 인증 연동(LDAP, SAML 등) 계정의 직접 등록은 범위 밖이다.
- 이름은 한 칸으로 받아 입력한 그대로 표시 이름으로 보이게 한다. 내부 저장 방식은 구현 단계에서 정한다.
- CSV 행 수 상한의 구체 값은 구현 단계에서 정하되, 수백 명 규모의 일괄 온보딩(최소 200행)을 수용한다.
- 결과 CSV에 임시 비밀번호가 포함되는 것은 관리자가 멤버에게 계정 정보를 전달하기 위한 의도된 동작이다. 파일 관리 책임은 관리자에게 있다.
