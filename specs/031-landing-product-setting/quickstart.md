# Quickstart: 첫 화면(로그인 랜딩) 설정 — 종단 검증 가이드

**Date**: 2026-10-25 | **Plan**: [plan.md](plan.md)

구현 완료 판정에 쓰는 실주행 절차다. 각 시나리오의 기대 결과가 스펙의
SC-001~004와 짝을 이룬다.

## 사전 조건

- 로컬 서버 + webapp dev 환경이 떠 있다.
- 보드·플레이북 플러그인이 설치·활성화되어 있다.
- 계정 3개: 시스템 관리자, 팀 관리자(팀 A), 일반 구성원(팀 A·B 소속).

### 이 저장소의 dev 환경 함정 (기존에 확인된 사실)

- Go 테스트는 `TEST_DATABASE_POSTGRESQL_DSN`이 필요하다. 컨테이너 비밀번호는
  `docker inspect`로 확인한다.
- webapp dev 번들은 `npm run run`으로만 만든다. 일회성 `webpack --mode...`
  빌드는 번들을 깨뜨린다.
- webpack 재빌드가 `server/client/plugins`를 지워 보드·플레이북이 404가 될 수
  있다. 그 경우 플러그인을 재활성화(비활성→활성)해서 복구한다.

## 게이트 (원칙 I — 기준선 diff)

```bash
# 구현 시작 전 기준선 저장, 마감 때 같은 명령으로 diff
cd server && make check-style && make test-server
cd webapp && npm run check && npm run check-types && npm run test
```

## 시나리오 1 — 개인 설정 (US1, SC-001·SC-002)

1. 일반 구성원으로 로그인 → 설정 → 디스플레이.
2. "첫 화면" 섹션에서 "보드" 선택, 저장. (섹션 진입부터 저장까지 1분 이내 — SC-002)
3. 로그아웃 → 다시 로그인.
4. **기대**: 추가 클릭 0회로 보드 화면 도착 (SC-001). URL이 `/boards`로 시작.
5. 설정을 "채널"로 바꾸고 재로그인 → 채널 도착 (팀 기본값보다 개인 설정 우선).

## 시나리오 2 — 팀 기본값 (US2)

1. 팀 관리자로 팀 A 설정 모달 → 정보 탭 → "팀 기본 첫 화면"을 플레이북으로 저장.
2. 개인 설정이 없는 구성원으로 로그인.
3. **기대**: 플레이북 화면 도착.
4. 일반 구성원 계정으로 팀 설정 모달 확인 → **기대**: 항목 변경 불가(모달 진입
   자체가 막히거나 항목 미노출).

## 시나리오 3 — 팀별 개인 설정 (US3)

1. 구성원이 팀 A에서 "첫 화면=보드, 현재 팀에만 적용" 저장.
2. "모든 팀에 적용"으로 "채널" 저장 (팀 A 설정은 별도 유지 여부 확인).
3. 마지막 사용 팀을 A로 두고 재로그인 → **기대**: 보드.
4. 팀 B로 전환 후 로그아웃·재로그인 → **기대**: 채널 (공통 설정 적용).

## 시나리오 4 — 플러그인 비활성·재설치 (엣지, SC-003)

1. 구성원 설정: 첫 화면=보드. 시스템 콘솔에서 보드 플러그인 비활성화.
2. 재로그인 → **기대**: 채널 도착(팀 기본값 없을 때). 오류·빈 화면 없음.
3. 설정 모달 확인 → **기대**: 보드 선택지 미노출, 저장값은 변경되지 않음.
4. 보드 플러그인 재활성화 → 재로그인.
5. **기대**: 추가 설정 0회로 보드 도착 (SC-003).

## 시나리오 5 — 회귀 (SC-004)

1. 설정을 만진 적 없는 새 계정으로 로그인 → **기대**: 기존과 동일하게 마지막
   채널(없으면 town-square) 도착.
2. `?redirect_to=`가 붙은 로그인 → **기대**: 기존대로 지정 주소 이동(랜딩 판정
   미개입).
3. 소속 팀 없는 계정 → **기대**: 팀 선택 화면.
4. 팀 전환(레일·사이드바 메뉴) → **기대**: 현재 제품 유지(기존 동작).

## 완료 기준

- 시나리오 1~5 전부 기대대로 — 실주행 결과를 구현 검증 기록에 남긴다.
- 게이트 출력 + 기준선 대비 실패 목록 diff 0건.
- SC-001~004 실측값 기록 (원칙 I·III: 출력 없으면 완료 아님).
