# Feature Specification: 첫 화면(로그인 랜딩) 설정

**Feature Branch**: `031-landing-product-setting`

**Created**: 2026-10-25

**Status**: Draft

**Input**: User description: "첫 화면(로그인 랜딩) 설정 기능. 사용자가 로그인 직후 처음 도착하는 화면을 채널, 보드(focalboard), 플레이북 중에서 설정할 수 있다. 우선순위는 해당 팀의 개인 설정 > 전체 팀 공통 개인 설정 > 그 팀의 팀 기본값 > 채널. 팀 기본값은 팀 관리자가 팀 설정에서, 개인 설정은 디스플레이 설정에서 팀별로(테마와 같은 방식) 정한다. 플러그인이 비활성이면 그 순간만 다음 우선순위로 대체하고 저장값은 유지한다."

## 개요

팀마다 주로 쓰는 제품이 다르다. OKR 관리가 중심인 팀은 보드를, 운영 절차가 중심인
팀은 플레이북을 먼저 봐야 하는데, 지금은 누구나 로그인하면 채널에 도착한다. 이
기능은 로그인 직후 도착하는 화면을 팀과 개인이 정하게 해서, 자주 쓰는 기능에
바로 도달하게 한다.

적용 범위는 로그인(새 접속) 직후 처음 도착하는 화면 한 곳이다. 팀 전환 동작(현재
보고 있는 제품을 유지한 채 팀만 바꾸는 방식)은 바꾸지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 구성원이 자기 첫 화면을 정한다 (Priority: P1)

구성원이 설정 → 디스플레이에서 첫 화면을 "팀 기본값 따르기(기본) / 채널 / 보드 /
플레이북" 중에서 고른다. 다음 로그인부터 선택한 화면에 도착한다.

**Why this priority**: 개인 설정 하나만 있어도 기능의 핵심 가치(자주 쓰는 화면에
바로 도달)가 성립한다. 팀 기본값 없이도 독립적으로 동작하는 MVP다.

**Independent Test**: 구성원 계정으로 첫 화면을 보드로 저장하고 로그아웃 → 다시
로그인하면 보드 화면에 도착하는지 확인한다. 팀 기본값 기능 없이 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 보드 플러그인이 활성화된 서버에서 구성원이 첫 화면을 "보드"로 저장했다,
   **When** 로그아웃 후 다시 로그인한다, **Then** 추가 조작 없이 보드 화면에 도착한다.
2. **Given** 구성원이 첫 화면을 설정한 적이 없다, **When** 로그인한다,
   **Then** 기존과 동일하게 채널(마지막 채널 또는 기본 채널)에 도착한다.
3. **Given** 구성원이 첫 화면을 "채널"로 명시 저장했고 팀 기본값은 "보드"다,
   **When** 로그인한다, **Then** 채널에 도착한다 (개인 설정이 팀 기본값보다 우선).

---

### User Story 2 - 팀 관리자가 팀 기본 첫 화면을 정한다 (Priority: P2)

팀 관리자가 팀 설정의 정보 탭에서 팀 기본 첫 화면을 "채널(기본) / 보드 /
플레이북" 중에서 고른다. 개인 설정이 없는 구성원은 로그인 시 팀 기본값 화면에
도착한다.

**Why this priority**: 팀 단위로 사용 목적을 반영하는 요구의 본체다. 다만 개인
설정(P1)이 먼저 있어야 "개인이 팀 기본값을 덮어쓴다"는 우선순위가 성립한다.

**Independent Test**: 팀 관리자가 팀 기본값을 플레이북으로 저장한 뒤, 개인 설정이
없는 구성원 계정으로 로그인해 플레이북 화면에 도착하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 팀 기본값이 "보드"이고 구성원에게 개인 설정이 없다, **When** 그
   구성원이 로그인한다, **Then** 보드 화면에 도착한다.
2. **Given** 팀 관리 권한이 없는 구성원이다, **When** 팀 설정을 연다,
   **Then** 팀 기본 첫 화면 항목을 변경할 수 없다.
3. **Given** 팀 기본값을 설정한 적이 없는 팀이다, **When** 개인 설정 없는 구성원이
   로그인한다, **Then** 기존과 동일하게 채널에 도착한다.

---

### User Story 3 - 구성원이 팀마다 다른 첫 화면을 정한다 (Priority: P3)

여러 팀에 속한 구성원이 개인 첫 화면 설정을 "현재 팀에만 적용"할지 "모든 팀에
적용"할지 고른다(테마 설정과 같은 방식). 로그인으로 도착하는 팀에 팀별 개인
설정이 있으면 그 값을, 없으면 모든 팀 공통 개인 설정을 쓴다.

**Why this priority**: 여러 팀을 오가는 사용자를 위한 확장이다. P1·P2만으로도
단일 팀 사용자는 완결된 가치를 얻는다.

**Independent Test**: 두 팀에 속한 계정으로 A팀에는 "보드", 공통으로는 "채널"을
저장한 뒤, 마지막 사용 팀을 A팀/B팀으로 바꿔 가며 로그인해 도착 화면을 비교한다.

**Acceptance Scenarios**:

1. **Given** 구성원이 A팀에만 "보드"를 저장했고 공통 설정은 없다, **When** 마지막
   사용 팀이 A팀인 상태로 로그인한다, **Then** 보드 화면에 도착한다.
2. **Given** 같은 구성원의 마지막 사용 팀이 B팀이고 B팀 기본값도 없다, **When**
   로그인한다, **Then** 채널에 도착한다.
3. **Given** 구성원이 "모든 팀에 적용"으로 "플레이북"을 저장했다, **When** 어느
   팀으로 로그인하든, **Then** (그 팀에 팀별 개인 설정이 없는 한) 플레이북에 도착한다.

---

### Edge Cases

- **선택된 제품의 플러그인이 비활성일 때**: 그 로그인에 한해 다음 우선순위로
  대체한다. 예: 개인 설정이 플레이북인데 플레이북만 꺼져 있고 팀 기본값이 보드면
  보드로, 그것도 꺼져 있으면 채널로 간다. 저장된 설정은 지우지도 바꾸지도 않는다.
- **플러그인을 재설치(재활성화)했을 때**: 별도 조치 없이 저장된 설정이 다시
  적용된다. 서버 업데이트로 플러그인이 의도치 않게 꺼졌다 복구되는 운영 시나리오를
  지원한다.
- **설정 UI에서 비활성 제품**: 선택지로 노출하지 않는다. 저장값이 비활성 제품이면
  UI는 현재 유효한 동작(대체된 값)을 기준으로 표시하되, 사용자가 새로 저장하기
  전에는 저장값을 바꾸지 않는다.
- **제품 가용성 정보가 아직 준비되지 않았을 때**: 첫 화면 판정은 가용성 정보를
  확보한 뒤에 수행한다. 정보가 늦게 로드된다는 이유로 설정을 무시하고 채널로
  보내서는 안 된다.
- **소속 팀이 없는 사용자**: 기존 동작(팀 선택 화면)을 유지한다. 이 기능은 도착할
  팀이 정해진 뒤의 화면만 바꾼다.
- **명시적 목적지가 있는 진입**: 초대 링크, 특정 URL로 직접 진입, 로그인 후 복귀
  주소(redirect) 등 목적지가 이미 정해진 경우는 기존 동작을 유지한다. 이 기능은
  목적지 없이 로그인한 경우에만 관여한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 구성원은 개인 설정(디스플레이)에서 첫 화면을 "팀 기본값 따르기 /
  채널 / 보드 / 플레이북" 중에서 선택할 수 있다. 기본값은 "팀 기본값 따르기"다.
- **FR-002**: 구성원은 개인 첫 화면 설정을 현재 팀에만 적용할지 모든 팀에 공통
  적용할지 선택할 수 있다.
- **FR-003**: 팀 관리 권한이 있는 사용자는 팀 설정에서 팀 기본 첫 화면을
  "채널 / 보드 / 플레이북" 중에서 선택할 수 있다. 기본값은 채널이며, 팀 관리
  권한이 없는 구성원은 변경할 수 없다.
- **FR-004**: 목적지 없이 로그인(새 접속)한 사용자의 도착 화면은 다음 우선순위로
  정한다 — 도착 팀의 팀별 개인 설정 > 모든 팀 공통 개인 설정 > 도착 팀의 팀
  기본값 > 채널(기존 동작).
- **FR-005**: 우선순위로 고른 제품의 플러그인이 비활성이면 그 판정에 한해 다음
  우선순위로 대체한다. 최종 대체지는 채널이다.
- **FR-006**: 플러그인 비활성화는 저장된 설정을 삭제하거나 변경하지 않는다.
  플러그인이 다시 활성화되면 저장된 설정이 추가 조치 없이 다시 적용된다.
- **FR-007**: 개인·팀 설정 UI 모두 활성화된 제품만 선택지로 노출한다. 채널은
  항상 노출한다.
- **FR-008**: 첫 화면 판정은 제품 가용성 정보를 확보한 뒤 수행한다. 정보 로드가
  끝나기 전에 판정해서 설정을 무시하면 안 된다.
- **FR-009**: 팀 전환 동작은 바꾸지 않는다. 팀을 전환하면 지금처럼 현재 보고 있는
  제품을 유지한다.
- **FR-010**: 첫 화면 설정과 무관한 기존 로그인 동작(소속 팀 없음, 복귀 주소 지정,
  초대 진입 등)은 변경하지 않는다.

### Key Entities

- **개인 첫 화면 설정**: 사용자별 저장값. 적용 범위(특정 팀 또는 모든 팀 공통)와
  선택값(팀 기본값 따르기 / 채널 / 보드 / 플레이북)을 가진다.
- **팀 기본 첫 화면**: 팀별 저장값. 선택값(채널 / 보드 / 플레이북)을 가지며 팀
  관리 권한으로만 변경한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 첫 화면을 보드 또는 플레이북으로 설정한 사용자가 로그인하면 추가
  클릭 0회로 해당 화면에 도착한다.
- **SC-002**: 구성원이 설정 모달을 열어 첫 화면을 바꾸고 저장하기까지 1분 안에
  끝난다 (별도 안내 문서 없이 완료 가능).
- **SC-003**: 설정된 제품의 플러그인을 비활성화한 뒤 재활성화하면, 사용자 쪽
  추가 설정 0회로 다음 로그인부터 원래 설정이 다시 적용된다.
- **SC-004**: 첫 화면을 설정하지 않은 사용자·팀의 로그인 도착 화면은 기능 추가
  전과 동일하다 (기존 로그인 흐름 회귀 0건).

## Assumptions

- 적용 대상은 웹앱(브라우저·데스크톱 앱)이다. 모바일 네이티브 앱은 범위 밖이다.
- 보드·플레이북은 플러그인으로 설치되어 제품 전환 레일에 나타나는 현재 구조를
  유지한다. 이 두 제품 외의 선택지는 이번 범위에 없다.
- "로그인 직후"는 목적지 없이 접속해 서버가 도착지를 정하는 경우를 뜻한다. 세션이
  살아 있는 브라우저로 루트 주소에 접속하는 경우도 같은 판정을 따른다.
- 개인 설정의 팀별/공통 적용 방식은 기존 테마 설정과 같은 사용자 경험을 따른다.
- 사용자에게 보이는 신규 문자열은 영어·한국어를 같은 변경에서 함께 추가한다
  (constitution 원칙 V).
