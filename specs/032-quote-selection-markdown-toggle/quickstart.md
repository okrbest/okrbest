# Quickstart: 메시지 선택 영역 인용과 Markdown 미리보기·코드 전환 — 종단 검증 가이드

**Date**: 2026-11-09 | **Plan**: [plan.md](plan.md)

구현 완료 판정에 쓰는 실주행 절차다. 시나리오마다 짝이 되는 SC를 적었다. 결과(스크린샷, 전송된 메시지 원문, 명령 출력)는 `evidence/`에 남긴다.

## 사전 조건

- Node v24 (`nvm use 24`). 안 바꾸면 webapp 테스트가 로드에 실패한다.
- 로컬 서버와 webapp dev 번들(`npm run run`)이 떠 있다. 일회성 `webpack --mode` 빌드는 번들을 깨뜨린다.
- 계정 2개(A, B)가 같은 팀·채널에 있다. B는 표시 이름이 username과 다르다.
- 채널에 B가 쓴 메시지가 있다: 문단 2개(사이 빈 줄), 목록, ```` ```python ```` 코드 블록, `**굵게**`, `@A` 멘션.

## 시나리오 1 — 채널 메시지 인용 (US1, SC-001·SC-002·SC-005)

1. A로 로그인해 채널을 연다. B의 메시지에서 두 번째 문단 일부를 드래그해 선택한다.
2. **기대**: 선택이 끝난 자리 옆에 인용 버튼이 뜨고, 툴팁은 "선택 영역 인용"이다.
3. 버튼을 누른다.
4. **기대**: 채널 입력창 끝에 인용 블록이 생기고, 커서가 그 아래 빈 줄에 있다(SC-005). 선택 1번과 클릭 1번이면 된다(SC-001).
5. 답을 쓰고 전송한다. 전송된 메시지의 원문(편집 창이나 API 응답)을 확인한다.
6. **기대**: 원문이 upstream `appendQuoteToMessage`로 같은 선택에서 만든 결과와 같다(끝 공백 제외, SC-002).

## 시나리오 2 — 서식이 섞인 선택 (US1, SC-002)

1. B의 메시지 전체(문단 2개, 목록, 코드 블록, 굵게, 멘션)를 선택해 인용한다. 입력창에 쓰던 글이 있는 상태에서 한다.
2. **기대**: 입력창에는 인용 블록 하나가 보인다. 목록·펜스 기호는 인용 블록 안에 글자로 보인다.
3. 전송한다.
4. **기대**: 메시지에 인용이 하나로 렌더링된다(빈 줄에서 쪼개지지 않는다). 멘션은 `@username`이고, 코드 블록은 `python` 펜스다. 쓰던 글은 인용 위에 그대로 있다.

## 시나리오 3 — 스레드와 팝아웃 (US1, SC-005)

1. B의 메시지에 답글을 달아 RHS 스레드를 연다. RHS 안 메시지 일부를 인용한다.
2. **기대**: 스레드 답글창에 들어간다. 채널 입력창은 바뀌지 않는다.
3. 스레드를 팝아웃 창으로 열어 같은 동작을 한다.
4. **기대**: 팝아웃 창의 답글창에 들어간다.

## 시나리오 4 — 인용 버튼이 뜨지 않는 경우 (US1 Edge Cases)

- 읽기 전용 채널(글쓰기 권한 없음)에서 선택한다 → 버튼이 없다.
- 보관된 채널, 비활성 사용자와의 DM → 버튼이 없다.
- 두 메시지에 걸쳐 선택한다 → 버튼이 없다.
- 채널 입력창에서 메시지 편집 모드에 들어간 채 같은 채널의 다른 메시지를 인용한다 → 편집 중인 입력에 들어가지 않는다. 편집을 끝내면(저장 또는 취소) 대기하던 인용문이 채널 입력창에 들어간다(upstream 동작).

## 시나리오 5 — Markdown 코드 블록 전환 (US2, SC-006)

1. ```` ```markdown ```` 블록(`## 제목`, `- [ ] 할 일`, `**굵게**`)이 있는 메시지를 보낸다.
2. **기대**: 코드로 보이고, 오른쪽 위에 언어 레이블과 미리보기·코드 전환 버튼, 복사 버튼이 있다.
3. 미리보기를 누른다. **기대**: 같은 자리에 렌더링 결과가 보인다.
4. 복사 버튼을 누르고 붙여 넣는다. **기대**: 원문 Markdown이 붙는다.
5. 새로고침한다. **기대**: 미리보기로 유지된다. 다른 Markdown 블록도 미리보기로 보인다.
6. 언어 표시 없는 블록에 `## 제목`만 넣어 보낸다. **기대**: 전환 버튼이 뜬다. ```` ```python ```` 블록에는 뜨지 않는다.

## 시나리오 6 — .md 파일 미리보기 (US3, SC-006)

1. `README.md`를 첨부해 보내고 미리보기를 연다.
2. **기대**: 렌더링 결과가 보이고, 헤더에 전환 버튼이 있다. 언어 레이블은 그리지 않는다.
3. 코드로 바꾼다. **기대**: 상자 크기가 그대로이고 원문이 줄바꿈된다.
4. 다른 .md 파일을 연다. **기대**: 코드로 보인다. 코드 블록 쪽 선택과는 따로 기억한다.
5. 파일 하나뿐인 미리보기에서 화살표 키를 누른다. **기대**: 전환·복사 버튼이 사라지지 않는다.

## 시나리오 7 — 헤더 버튼과 포크 기능 회귀 (US4, SC-007)

1. 이미지 파일 미리보기를 연다. 헤더 버튼(링크 복사, 다운로드, 닫기)과 이전/다음 화살표의 크기·hover를 본다.
2. **기대**: 버튼이 36px로 정렬되고 hover 배경이 보인다. 이전 화살표 툴팁은 "이전"이다.
3. 이미지를 확대·축소, 끌기, 휠, 키보드로 조작하고 바깥을 클릭한다.
4. **기대**: 포크 기존 동작이 그대로다.
5. 라이트·다크 테마에서 반복한다.

## 시나리오 8 — 입력창 회귀 (FR-009, SC-007)

포크 인용 블록 변환 규칙(빈 줄을 `>`로 내보냄)과 새 노드가 기존 입력 동작을 바꾸지 않는지 본다.

1. 입력창에 직접 `> 첫 줄`을 치고 Shift+Enter로 빈 줄, `> 셋째 줄`을 친 뒤 전송한다. **기대**: 인용 하나로 렌더링된다. 전송 원문에서 빈 줄은 `>`다(이전에는 `> `였다. 렌더링 결과는 같다).
2. `@`로 멘션 자동완성을 열어 사용자를 고른다. **기대**: 기존처럼 멘션이 들어가고 전송 원문은 `@username`이다.
3. 다른 앱에서 Markdown(제목, 목록, 코드 블록)을 복사해 붙여 넣는다. **기대**: 기존 붙여넣기 결과와 같다.
4. 해시태그 링크가 있는 메시지를 복사해 붙여 넣는다. **기대**: 평문 해시태그로 들어간다(#201 동작).
5. 서식 바로 굵게·기울임·코드·인용을 적용해 전송한다. **기대**: 기존 결과와 같다.
6. 인용 버튼으로 넣은 인용문 끝에 글자를 덧붙여 전송한다. **기대**: 덧붙인 글자도 이스케이프 없이 그대로 나간다.
