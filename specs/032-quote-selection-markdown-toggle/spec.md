## 현재 동작

메시지 일부를 인용해 답하려면 사용자가 직접 텍스트를 복사해 입력창에 붙이고 줄마다 `> `를 붙여야 한다.
멘션은 화면에 보이는 표시 이름으로 복사되므로 인용문 안에서 멘션이 깨진다.

```` ```markdown ```` 코드 블록과 .md 파일 미리보기는 원문만 보여 준다. Markdown 문서를 공유받은 사람은 렌더링 결과를 보려면 파일을 내려받아 다른 도구로 열어야 한다.

upstream은 두 문제를 `caaec8cd`(2026-10-30)와 `36ebc1f6`(2026-11-02)에서 풀었다. 포크는 sync 분석에서 두 커밋을 바로 받지 않고 spec으로 넘겼다. 이유는 셋이다.

- 포크 입력창은 Lexical 에디터 하나뿐이다. upstream이 인용문을 넣는 Textbox·TipTap 경로가 포크에 없다.
- 36ebc1f6은 compass-ui 버튼을 쓴다. 포크는 compass-ui를 라이선스 문제로 제외했다(2026-10-18 결정).
- 36ebc1f6은 caaec8cd를 적용한 뒤의 turndown 변환 위에 만들어졌다. 그래서 둘을 함께 옮긴다.

포크는 2026-11-05 sync에서 06ab8d2c(#38680, 코드 블록 구문 강조 처리)를 먼저 받았다. 그때 36ebc1f6의 토글 코드와 테스트를 뺐다. 이 기록은 `docs/upstream-adapted-divergences.md`의 "코드 블록 구문 강조 처리 — 마크다운 토글 코드와 테스트를 뺐다" 절에 있다. 이 spec에서 그 코드를 되살린다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 메시지 일부를 골라 인용해 답한다 (Priority: P1)

사용자가 가운데 채널이나 RHS·스레드 화면에서 메시지 본문 일부를 드래그해 선택한다. 선택이 끝난 자리 옆에 인용 버튼이 뜬다.
버튼을 누르면 선택한 내용이 인용문으로 맞는 입력창 끝에 들어가고, 커서가 인용문 아래 빈 줄로 간다. 사용자는 바로 답을 이어 쓴다.

**Why this priority**: 이 spec에서 가장 자주 쓰일 기능이다. 혼자 동작하고, 다른 스토리 없이도 배포할 수 있다.

**Independent Test**: 채널에서 다른 사람의 메시지 일부를 선택해 인용 버튼을 누른다. 입력창에 인용 블록이 생기고, 전송한 메시지가 선택한 부분을 인용문으로 보여 주는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가운데 채널에 메시지가 있다, **When** 본문 일부를 선택하고 인용 버튼을 누른다, **Then** 채널 입력창 끝에 인용 블록이 들어가고 커서가 그 아래 빈 줄에 있다.
2. **Given** RHS에 스레드가 열려 있다, **When** 스레드 안 메시지 일부를 인용한다, **Then** 인용문은 그 스레드의 답글창에 들어간다. 채널 입력창은 바뀌지 않는다.
3. **Given** 입력창에 이미 쓰던 글이 있다, **When** 인용한다, **Then** 쓰던 글은 그대로 두고 빈 줄 하나를 사이에 둔 뒤 인용문이 붙는다.
4. **Given** 선택 영역에 멘션 `@표시이름`이 있다, **When** 인용한다, **Then** 인용문에는 `@username`이 들어간다.
5. **Given** 선택 영역에 목록·코드 블록·굵은 글씨가 있다, **When** 인용해 전송한다, **Then** 전송된 메시지는 upstream이 같은 선택에서 만드는 인용 Markdown과 글자 단위로 같다.
6. **Given** 여러 문단을 선택했다, **When** 인용해 전송한다, **Then** 인용문은 하나로 이어진다. 문단 사이 빈 줄 때문에 인용이 여러 개로 쪼개지지 않는다.
7. **Given** 키보드나 화면 낭독기로 텍스트를 선택했다, **When** 선택이 잠시 멈춘다, **Then** 인용 버튼이 뜨고 Tab으로 버튼에 갈 수 있다. 버튼을 벗어나면 원래 포커스로 돌아간다.

### User Story 2 - Markdown 코드 블록을 미리보기로 본다 (Priority: P2)

메시지에 ```` ```markdown ```` 코드 블록이 있으면 코드 블록 오른쪽 위에 미리보기·코드 전환 버튼이 뜬다. 처음엔 코드로 보인다. 미리보기를 누르면 같은 자리에 렌더링 결과가 보인다.
언어 표시가 없어도 Markdown처럼 보이는 블록에는 전환 버튼이 뜬다.

**Why this priority**: 문서·체크리스트를 코드 블록으로 공유하는 팀에 바로 쓸모가 있다. 인용 기능과 따로 동작한다.

**Independent Test**: ```` ```markdown ```` 블록이 있는 메시지를 보내고, 전환 버튼으로 미리보기와 코드를 오가며 복사 버튼이 항상 원문을 복사하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** ```` ```markdown ```` 코드 블록이 있는 메시지가 있다, **When** 처음 본다, **Then** 코드로 보이고 전환 버튼이 뜬다.
2. **Given** 코드 블록을 미리보기로 바꿨다, **When** 다른 Markdown 코드 블록을 보거나 새로고침한다, **Then** 코드 블록은 모두 미리보기로 보인다(사용자별로 기억한다).
3. **Given** 미리보기 상태다, **When** 복사 버튼을 누른다, **Then** 렌더링 결과가 아니라 원문 Markdown이 복사된다.
4. **Given** 언어 표시가 없는 블록에 서로 다른 Markdown 구문이 두 가지 이상 있거나 `##` 이하 제목이 있다, **When** 본다, **Then** 전환 버튼이 뜬다.
5. **Given** 다른 언어(예: `python`)로 표시된 블록이다, **When** 본다, **Then** 내용이 Markdown처럼 보여도 전환 버튼이 뜨지 않는다.
6. **Given** 미리보기로 렌더링된 내용 안에 또 Markdown 코드 블록이 있다, **When** 본다, **Then** 안쪽 블록에는 전환 버튼이 뜨지 않는다.
7. **Given** 미리보기로 바꾼 코드 블록 일부를 선택한다, **When** 인용 버튼을 누른다, **Then** 코드 블록 언어 레이블을 읽어 인용 Markdown을 만든다.

### User Story 3 - .md 파일을 미리보기 모달에서 렌더링해 본다 (Priority: P2)

사용자가 메시지에 첨부된 .md 파일을 열면 파일 미리보기 모달이 렌더링 결과를 먼저 보여 준다. 헤더의 전환 버튼으로 원문 코드를 볼 수 있다.

**Why this priority**: 공유받은 Markdown 문서를 내려받지 않고 읽게 한다. 코드 블록 전환과 같은 버튼을 쓰지만 따로 검증할 수 있다.

**Independent Test**: .md 파일을 첨부해 보내고 미리보기 모달을 열어, 렌더링 결과·원문 전환·선택 기억을 확인한다.

**Acceptance Scenarios**:

1. **Given** .md 파일이 첨부된 메시지가 있다, **When** 파일 미리보기를 연다, **Then** 렌더링 결과가 보이고 헤더에 전환 버튼이 있다.
2. **Given** 코드로 바꿨다, **When** 다른 .md 파일을 연다, **Then** 코드로 보인다. 코드 블록의 선택과는 따로 기억한다.
3. **Given** 두 보기 중 무엇을 고르든, **When** 전환한다, **Then** 모달 상자 크기가 바뀌지 않고 원문은 줄바꿈되어 보인다.
4. **Given** 파일이 하나뿐인 미리보기다, **When** 화살표 키를 누른다, **Then** 전환 버튼과 복사 버튼이 사라지지 않는다.
5. **Given** 모바일 화면이다, **When** .md 파일을 연다, **Then** 원문으로 보인다(upstream 동작).

---

### User Story 4 - 파일 미리보기 헤더와 코드 복사 버튼이 새 디자인으로 바뀐다 (Priority: P3)

파일 미리보기 모달 헤더의 다운로드·링크 복사·닫기·이전/다음 버튼과 코드 블록 복사 버튼이 upstream의 새 아이콘 버튼 모양(크기·둥근 모서리·hover 농도·어두운 헤더용 스타일)에 가깝게 바뀐다.
이전 파일 화살표의 툴팁이 "닫기"로 나오던 문제도 고친다.

**Why this priority**: 시각 정리라 기능 가치는 낮다. 전환 버튼이 헤더 버튼 옆에 놓이므로 모양을 맞춘다(사용자 결정).

**Independent Test**: 이미지·.md·기타 파일 미리보기를 열어 헤더 버튼 모양·hover·툴팁을 확인하고, 포크가 추가한 이미지 조작 기능이 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 파일 미리보기 모달이 열려 있다, **When** 헤더 버튼에 마우스를 올린다, **Then** 버튼은 같은 크기로 정렬되고 hover 배경이 보인다.
2. **Given** 이전 파일 화살표에 마우스를 올린다, **Then** 툴팁은 "이전"을 뜻하는 문구다.
3. **Given** 이미지 미리보기다, **When** 확대·축소, 끌기, 휠, 키보드 조작, 바깥 클릭을 한다, **Then** 포크의 기존 동작이 그대로다.

---

### Edge Cases

- 선택이 두 메시지에 걸치면 인용 버튼이 뜨지 않는다. 세 번 클릭으로 마지막 줄을 선택해 다음 메시지 시작점까지 선택이 넘어가면, 본문 부분만 인용한다.
- 작성자 이름 등 본문 밖까지 선택하면 본문 부분만 인용한다. 화면의 선택 자체는 그대로 둬서 전체 복사를 할 수 있다.
- 글쓰기 권한이 없는 채널, 보관된 채널, 비활성 사용자와의 DM, 루트가 삭제된 스레드에서는 인용 버튼이 뜨지 않는다.
- 읽으면 사라지는(burn-on-read) 메시지는 인용할 수 없다.
- 입력창이 메시지 편집 모드이거나 대상 채널·스레드가 다른 입력창이면 인용문을 넣지 않는다. 대기 인용은 지우지 않는다. 편집을 끝내면 대상 입력창이 대기 인용을 넣는다(upstream 동작).
- AI 재작성 등 입력창이 처리 중이면 끝날 때까지 기다렸다가 넣는다. 입력창을 쓸 수 없게 되면 인용문을 버린다.
- 로그아웃하면 대기 중인 인용문을 지운다.
- 선택 내용이 공백뿐이면 아무것도 넣지 않는다.
- 선택한 텍스트가 스크롤 등으로 움직이면 인용 버튼을 숨긴다.
- 브라우저 저장소를 막아 둔 환경에서는 미리보기·코드 선택을 기억하지 못하고 기본값을 쓴다.
- 다른 탭에서 바꾼 미리보기·코드 선택도 따라간다.
- 아주 긴 코드는 구문 강조 없이 평문으로 보인다(포크가 이미 받은 #38680 동작 유지).

## Requirements *(mandatory)*

### Functional Requirements

**인용 (caaec8cd)**

- **FR-001**: 가운데 채널·RHS·스레드 화면에서 한 메시지 본문 일부를 선택하면 선택이 끝난 자리 옆에 인용 버튼을 보여야 한다. 마우스 선택은 mouseup 뒤에, 키보드 선택은 잠시 멈춘 뒤에 보인다.
- **FR-002**: 인용 버튼을 누르면 선택 영역을 Markdown으로 바꾸고 모든 줄 앞에 `> `(빈 줄은 `>`)를 붙여, 그 메시지가 속한 입력창 끝에 넣어야 한다. 가운데 채널 메시지는 채널 입력창으로, RHS·스레드 화면 메시지는 그 스레드 답글창으로 간다. 팝아웃 창(스레드·채널 팝아웃)에서도 같은 규칙으로 그 창의 입력창에 들어간다.
- **FR-003**: 입력창에는 인용문이 인용 블록으로 보여야 한다. 커서는 인용문 아래 빈 줄에 있어야 한다.
- **FR-004**: 인용 후 전송되는 Markdown은 upstream `appendQuoteToMessage(기존 메시지, 선택 Markdown)` 결과와 글자 단위로 같아야 한다. 끝 공백과 끝 빈 줄은 비교에서 뺀다(upstream이 커서 자리로 붙이는 꼬리라서). 단문, 빈 줄이 낀 여러 문단, 목록, 코드 블록, 서식, 멘션, 기존 글이 있는 경우를 모두 포함한다. 입력창 인용 블록에 담을 수 없는 서식 줄은 기호를 그대로 둔 텍스트로 인용 블록 안에 보인다.
- **FR-005**: 멘션은 `@username`으로, 채널 링크·해시태그는 원래 Markdown으로, 코드 블록은 언어 레이블을 살린 펜스로 바꿔야 한다.
- **FR-006**: 권한·채널 상태·스레드 상태·burn-on-read 조건(Edge Cases)에 해당하면 인용 버튼을 보이지 않아야 한다.
- **FR-007**: 인용 버튼은 키보드로 접근할 수 있어야 하고, 접근 가능한 이름과 툴팁 "선택 영역 인용"이 있어야 한다.
- **FR-008**: 인용문은 대상 입력창이 준비될 때까지 대기해야 하고, 편집 모드·다른 대상·사용 불가·로그아웃 조건(Edge Cases)을 upstream과 같게 처리해야 한다.
- **FR-009**: 인용은 포크 입력창의 기존 동작(멘션 자동완성, Markdown 붙여넣기, 해시태그 붙여넣기, 서식 바, 전송, draft 저장)을 바꾸지 않아야 한다.

**Markdown 미리보기·코드 전환 (36ebc1f6)**

- **FR-010**: ```` ```markdown ```` 코드 블록과, 언어 표시가 없지만 Markdown처럼 보이는 코드 블록(서로 다른 구문 두 가지 이상 또는 `##` 이하 제목)에 미리보기·코드 전환 버튼을 보여야 한다. 다른 언어로 표시된 블록에는 보이지 않는다.
- **FR-011**: .md 파일 미리보기 모달 헤더에 같은 전환 버튼을 보여야 한다.
- **FR-012**: 기본 보기는 코드 블록이 코드, 파일 미리보기가 미리보기여야 한다. 사용자가 고른 보기는 사용자별·위치별(코드 블록, 파일 미리보기)로 브라우저에 기억해야 하고, 다른 탭의 변경도 따라가야 한다.
- **FR-013**: 미리보기는 메시지와 같은 Markdown 렌더링을 써야 하며, 렌더링 결과 안의 코드 블록에는 전환 버튼을 다시 보이지 않아야 한다. 검색 결과 화면에서는 렌더링하지 않는다(upstream 동작).
- **FR-014**: 복사 버튼은 보기와 상관없이 원문 Markdown을 복사해야 한다.
- **FR-015**: .md 파일은 두 보기 모두 같은 크기의 상자로 보이고, 원문은 줄바꿈되어야 한다. .md 파일에는 언어 레이블을 그리지 않고, 렌더링 보기면 `Markdown`으로 그린다(포크가 06ab8d2c 반영 때 뺀 upstream 동작을 되살린다).
- **FR-016**: 줄바꿈된 코드는 원래 줄 단위로 다시 합쳐 복사·인용해야 한다.
- **FR-017**: 전환 버튼 문구는 "미리보기", "코드", 접근 가능한 그룹 이름은 "Markdown 보기"여야 한다.

**버튼 디자인과 포크 보존**

## Success Criteria *(mandatory)*
